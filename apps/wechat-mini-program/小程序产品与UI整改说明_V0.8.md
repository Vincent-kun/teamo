# 小程序产品与UI整改说明 V0.8

## 一、审查依据

- 《儿童AI运动陪伴机器人 PRD V3.0》
- 《儿童AI运动陪伴机器人 MVP PRD V1.2 技术对接版》
- 《儿童AI运动陪伴机器人 MVP 功能清单 V1.0》
- 《儿童AI运动陪伴机器人 完整产品 UE Demo V7.3》
- 2026年9月24日产品讨论中的小程序UI结论

## 二、整改前主要问题

1. 展示功能多于已经冻结的能力，七种动作都能发送，容易让硬件和算法误认为全部进入MVP。
2. 任务缺少明确的设备接收回执和取消操作，未完整表达“创建—确认—执行—结果”闭环。
3. 设备页展示英文内部状态，且训练动作写死为开合跳，与家长刚发送的任务可能不一致。
4. 运动记录缺少完成状态、任务来源和执行设备，数据可信度表达不足。
5. 成长页包含皮肤兑换和身高体重占位，弱化了当前MVP最重要的真实运动记录。
6. AI计划和问答看起来像正式能力，没有充分说明当前为演示数据。
7. 页面普遍采用大圆角和较重阴影，信息层级相似，长页面容易产生“卡片堆叠感”。

## 三、本次整改

- 动作库保留七种动作的产品视野，但增加“MVP已支持、算法评审中、后续适配”状态；只有开合跳和深蹲起可发送。
- 任务列表增加设备回执、取消确认和离线拦截；历史分类同时收纳完成、取消和异常结束任务。
- 设备页根据最近任务展示动作和目标，补充中文状态、暂停/继续命令、摄像头关闭拦截及结果同步。
- 运动记录增加状态、来源和设备字段；运动详情说明AI建议来自本次记录且不用于医疗判断。
- 首页强化设备当前状态、离线提示和可立即开始的MVP动作，减少不明确入口。
- 成长页删除未真正开发的兑换与身体数据入口，改为有效动作、完成记录和周小结。
- AI页把单次运动分析放在首位，计划与问答明确标记为体验或演示能力。
- 统一按钮高度、圆角、阴影、卡片边界和按压反馈，降低装饰噪音并提升可读性。

## 四、仍需研发确认

- 正式登录、家庭空间、设备绑定与权限体系。
- 服务端命令确认、状态事件、断线重连和任务去重。
- 开合跳、深蹲起的算法验收标准；高抬腿是否进入MVP。
- 原始视频、结构化姿态事件和儿童资料的保存与删除规则。
- AI运动分析和计划生成的正式服务、审核策略与失败降级。

## 五、产品检查结论

当前版本适合作为MVP交互演示和技术对齐原型。它已经能清楚说明家长如何发送运动、设备如何接收并执行、结果如何回到家长端；但真实上线仍依赖账号、绑定、服务端状态同步、算法和隐私策略落地。

## 六、V0.9 亚克力玻璃视觉升级

- 使用“环境光背景—半透明内容卡—实色操作按钮”三层材质结构。
- 玻璃内容卡采用半透明白、细白描边、顶部高光、柔和投影与轻度背景模糊。
- 粉、紫、青、桃色降低饱和度，只作为玻璃下方的功能光晕。
- 深青色保留给设备状态、运动分析等高优先级内容，荧光绿只用于关键操作和数字焦点。
- 输入框、筛选器、列表和弹出创建面板统一材质，减少页面之间的割裂感。
- 同时保留半透明底色作为兼容降级；不支持背景模糊时仍能保证文字对比度和信息层级。
