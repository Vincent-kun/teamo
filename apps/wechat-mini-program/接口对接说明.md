# 小程序、服务端与设备接口对接说明（MVP）

## 1. 推荐通信方案

```text
微信小程序 -- HTTPS / WebSocket --> 业务服务端 -- MQTT --> 设备
```

- HTTPS：登录、设备绑定、任务创建、计划保存、运动记录查询和 AI 请求。
- WebSocket：小程序实时接收设备在线状态、运动进度和异常提醒。
- MQTT：服务端向设备下发指令，设备上报状态与运动结果。

当前小程序先使用模拟接口。真实服务端准备好后，只替换 `miniprogram/services/api.js`，页面不需要重做。

## 2. 设备状态

| 状态 | 含义 |
|---|---|
| `offline` | 设备离线 |
| `idle` | 在线待机 |
| `ready` | 已收到任务，等待孩子开始 |
| `running` | 运动中 |
| `paused` | 已暂停并保留进度 |
| `completed` | 已完成，结果待同步或已同步 |
| `error` | 设备异常 |

## 3. MQTT 主题建议

| 方向 | Topic | 用途 |
|---|---|---|
| 服务端 → 设备 | `devices/{deviceId}/commands` | 下发任务和控制指令 |
| 设备 → 服务端 | `devices/{deviceId}/status` | 在线、待机、运动中等状态 |
| 设备 → 服务端 | `devices/{deviceId}/events` | 计数、姿态提醒和异常事件 |
| 设备 → 服务端 | `devices/{deviceId}/results` | 完整运动结果 |

## 4. 指令示例

```json
{
  "messageId": "M202609280001",
  "deviceId": "TEAMO-001",
  "type": "START_TASK",
  "timestamp": 1790557200000,
  "payload": {
    "taskId": "T001",
    "actionId": "jumping_jack",
    "targetCount": 20
  }
}
```

MVP 至少需要：

- `START_TASK`：开始单项运动。
- `START_PLAN`：开始训练计划。
- `PAUSE_TASK`：暂停。
- `RESUME_TASK`：继续。
- `STOP_TASK`：结束。
- `GET_STATUS`：获取当前状态。

## 5. 结果示例

## 6. AI 接口

### 生成运动计划

`POST /ai/plans`

输入：孩子年龄、运动目标、运动基础、每次时长和可选动作。

输出：计划名称、每天的动作、目标次数、休息时间和提示语。服务端必须校验 AI 返回结构后再保存。

### 生成运动分析

`POST /ai/analysis`

输入：运动结果、有效次数、节奏、姿态事件和历史记录摘要。

输出：完成情况、动作问题、下次建议。文案只用于日常运动反馈，不提供医疗结论。

## 7. 待硬件团队确认

- 设备采用 MQTT 还是 WebSocket。
- 设备如何首次联网和绑定家长账号。
- 摄像头算法输出原始视频、人体关键点，还是只输出分析结果。
- 断网时可以保存多少条任务和运动结果。
- 设备状态上报频率、重连方式和消息去重规则。
