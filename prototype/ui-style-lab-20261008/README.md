## 2 · 三方向定义（还原来源 → 发散）

| 方向 | 名称 | 还原自 | 一句话定位 | 选型建议 |
|---|---|---|---|---|
| 一 | **清晰成长** Clear Growth | 参考图 1 | 白卡 + 荧光绿，列表与状态行为骨架 | 最接近项目现有小程序令牌（#BDF52D + 玻璃卡），**改造成本最低** |
| 二 | **温暖陪伴屋** Warm Companion | 参考图 2 | 暖白 + 浅紫插画，圆润角色解释动作 | 低龄段（6–8 岁）接受度最高；角色/插画资源成本最高 |
| 三 | **活力运动场** Arena | 参考图 3 | 高饱和撞色（青绿/蓝紫/荧光绿）+ 巨字数字 | 运动氛围最强；需防"过饱和刺眼" |

每方向发散 2 个变体（共 6 张发散）：
- **方向一 发散 A 墨底仪表** / **发散 B 静音成长**（降饱和、收圆角、放大字号）
- **方向二 发散 A 弱角色** / **发散 B 暖陶土**（去全幅插画、陶土色系，给 13–15 岁去幼稚化）
- **方向三 发散 A 荧光绿** / **发散 B 圆角收束**（保留撞色但降低锐利度）

**手机端逻辑页面 = 小程序 MVP V0.1 家长端真实页面**：四页（首页 / 运动邀请 / 设备页 / 运动分析）的结构 / 文案 / 数据直接取自 `AI运动伙伴/小程序MVP_V0.1/预览_小程序MVP.html`。与上一轮的差异：三方向不再共用一套布局，而是各按一套设计语言重排——

- **方向一 = Editorial Bento**：异尺寸便当格（CSS Grid span）+ 1px 发丝线 + 特大 `tabular-nums` 数字 + 墨色块强调；
- **方向二 = Claymorphism**：粘土卡双重阴影（外投影 + inset 左上高光 + inset 右下暗影）+ 2.5px 厚边框 + 弹性缓动 `cubic-bezier(.34,1.56,.64,1)` + 角色呼吸陪伴；
- **方向三 = Kinetic Poster**：超大字标（品牌色块 + 描边字）+ 每页一条品牌色跑马灯 + 硬偏移阴影 + 10 段计量条。

每方向 = 1 还原 + 2 发散，共 **9 套皮肤**；颜色仍随 `data-skin` 令牌，版式 / 层级 / 动效随方向语言。动效以纯 CSS 模拟 GSAP 模式（stagger 入场 / marquee 循环 / elastic 弹性 / 条形生长），在 `prefers-reduced-motion: reduce` 下全部关闭。模式来源见看板「0.5 设计语言与参考」。

## 3 · 双端统一规则（手机端 ↔ 设备端共用一套令牌）

这是本次"与手机端风格统一"的可执行定义：

1. **令牌收敛到一层 CSS 变量**：所有风格差异只在 `.phone` 上挂默认令牌，`[data-skin=...]` 覆盖；`.sc`（屏内容容器）**不重复声明**，只 `background:var(--bg-grad)` 继承。换皮肤 = 换一个 `data-skin` 属性。
2. **设备端桥接**：`[data-skin="..."] .disp-round, .disp-rect` 显式桥接 `--dev-brand / --dev-track / --dev-bg`，与手机端同令牌 → 设备屏颜色随手机皮肤自动同步。
3. **同数据四页（MVP）**：首页 / 运动邀请 / 设备页 / 运动分析，四页共享同一份数据（`S` 对象：开合跳 20 次、今日 22 分钟、连续 5 天、运动星 46、深蹲起得分 86），保证跨皮肤可比；设备端"运动中"态仍在设备屏单独呈现（MVP 手机端无独立运动中页）。
4. **等宽数字**：`font-variant-numeric: tabular-nums` 防止位数横跳。
5. **状态色语义**：完成 = 品牌色、待同步 = 琥珀、离线 = 灰，三端一致。
6. **圆屏安全区**：`.disp-round .safe` 内切圆，避免内容出血。

## 6 · 边界声明（诚实标注，未编造）

1. **图片不可读**：本会话模型无法读取位图，三张方向参考图以仓库内既有 `docs/product/design/ui-reference-trace-20261008/direction-1/2/3-*.png` 及配套文档（`三方向参考实看与设计规则.md`、`UI参考方向与审美研究_20261008.md`）作等价依据；看板内 `from:'参考图 N'` 标注了对应关系，但最终以你人眼核对三张原图为准。
2. **设备端摄像头承担全身动作识别**：渲染图中顶部滑盖槽内镜头是否承担全身识别，本看板未涉及（属硬件/算法范畴），UI 仅呈现设备屏内容。
3. **圆/方屏最终口径**：项目长期记忆中"圆/方屏待定"尚未回填闭环，本看板按现行预算规格（圆屏 360×360 / 方屏 240×280）落地，待产品结论后替换。
