# 可演示前端与复用交接

更新：2026-10-09。当前入口index.html，不需构建。请连同flow-core.js、flow-ui.js保留在同一目录。浏览器打开即可使用；全部网络、设备确认、计数与保存都是明确标注的本地演示，未连接摄像头或后台。

## 演示步骤

1. 手机点“创建运动邀请”，选择开合跳/深蹲起与1–200次目标，发送；约0.5秒显示后台受理，仍等待设备确认。
2. 在设备页点“模拟设备确认”，再“开始运动”。模拟一个动作+1，或打开自动演示计数。
3. 暂停时计数不变；恢复后继续。关闭隐私盖会暂停并关闭自动演示，重新打开后需主动恢复。
4. 模拟断网，本地模拟计数仍可继续；结束后进入结果，显示实际计数、目标完成/提前结束、设备已保存、待同步。
5. 恢复联网，在结果页模拟补传确认；同步中与已同步分别显示。刷新会恢复本地演示，未结束运动恢复成暂停；重置演示可重新开始。
6. 手机底部导航、任务历史、返回任务列表和取消待执行任务可以操作。运动中的任务使用结束操作，不伪装取消已确认。

三方向/九皮肤切换保留任务、当前页与计数。顶部设备形状只是画布适配，设备状态由同一会话驱动。手机内部滚动位置在状态刷新时保留，切换手机页面回到页首。

## 可以实际复用的部分

| 文件/层 | 责任 | 后续接入 |
|---|---|---|
| flow-core.js | 纯状态转换与store；不依赖DOM、皮肤或wx | CommonJS可require，浏览器全局TeamoFlow；可用于React/store或小程序业务层 |
| flow-ui.js | 页面视图、表单、导航、模拟事件适配 | 保留业务事件接口；框架迁移时改视图绑定，移除本地模拟计时器 |
| index.html | 原有三方向token、字体、控件风格、双端预览控制 | 拆为主题与组件样式；手机机身和实验室外壳不进入正式产品 |

事件：CREATE、ACCEPTED、DEVICE_ACK、START、COUNT、PAUSE、RESUME、PRIVACY、ONLINE、FINISH、SYNC、SYNC_ACK、CANCEL、RETRY、RESET。请求受理不等于设备收到；重试保留commandId；旧回执/取消后的回执不会开启会话；计数和网络状态独立；finish重复不会重复生成记录；0次提前结束不伪造一次。

当前sendCurrent是后台受理mock；DEVICE_ACK由设备页按钮显式模拟，SYNC_ACK由补传按钮模拟。接真实接口应由命令服务和设备事件替代这些模拟事件，不能仅把mock延迟改成HTTP后仍直接宣称设备收到。生产还需认证、权限、远端一致性、事件去重/乱序、可靠存储、设备结束回执与故障恢复；本文件不把该演示模型称为生产通信实现。

未接入：算法质量评分、AI建议、体态与循环计划；结果页只展示计数事实。页面统一使用状态模型，原静态评分展示不进入当前可点击主链。

## 验证

flow-core.test.cjs通过：开始守卫、错误回执、暂停/隐私、断网保存、同步确认、重复结束、取消后回执、零次结果、同ID重试与刷新恢复。verify-compact.cjs通过90种渲染组合，并通过UI控制器调用验证确认→开始→计数→暂停→恢复→保存→结果导航。

这些是Node业务/模板验证，未完成真实浏览器视觉、微信开发者工具、实机触控和窄屏验收。接口迁移后需要新增真实事件与端到端验证。
