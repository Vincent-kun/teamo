# 手机端 UI、按钮功能与开发交接（统一交付）

当前入口：[独立手机端](mobile.html)，最终加载 index.html?mobile=1；原实验室入口仍为 index.html。两个入口共享同一份小程序 MVP 页面模板、三套视觉风格、flow-core.js 和 flow-ui.js，不维护两份业务实现。手机端没有外部设备对比区，底部导航常驻。

## 当前布局与三套 UI

本轮 MVP 模板对齐已合并到本交付。功能与页面布局以用户指定的 `AI运动伙伴/小程序MVP_V0.1/预览_小程序MVP.html` 为准，原文件未修改。

- 底栏：首页 / 任务 / AI / 成长 / 我的，中央 AI 为独立页面。
- 二级页面：设备、动作库、记录、运动分析、姿态提醒、孩子资料。
- 首页保留原模块顺序和横向动作卡片；AI 页保留七天计划与问答区。
- 保留 Editorial Bento、Claymorphism、Kinetic Poster 三个视觉方向，在同一 MVP 布局上切换配色和样式；之前各自不同的页面布局不再作为当前基线。
- [MVP 模板对齐细节](MVP模板对齐_20261009.md)是本交付的补充记录，不是另一套手机端。

## 已接入的操作

| 原有入口/按钮 | 当前行为 |
|---|---|
| 首页设备卡、今日任务、最近运动 | 跳转设备、任务、运动记录 |
| 计划助手 | 展示明确标记的预设方案，采用后可编辑并创建任务 |
| 快速训练 | 打开动作与目标选择；支持开合跳、深蹲起 |
| 学伴成长 | 展示本机记录的次数、计数、达标次数 |
| 姿态提醒 | 说明未接入识别；提醒偏好可保存 |
| 创建运动邀请 | 校验动作、1–200整数目标；即时发送或保存未来计划 |
| 待进行/计划中/历史 | 独立列表及选中状态；无数据给出空态 |
| 计划发送/删除 | 手动发送或删除；活动任务冲突时保留计划 |
| 历史详情 | 切换指定记录，而非始终显示最近一条 |
| 设备开始、暂停、继续、结束 | 同一状态模型驱动；关闭隐私盖自动暂停 |
| 模拟动作、自动计数 | 暂停时禁用；自动演示达到目标后保存结果 |
| 模拟离线/恢复网络 | 本地计数可继续，离线禁用设备确认和同步 |
| 设备确认、发送失败、重试 | 后台受理与设备确认分开，重试保持命令ID |
| 补传 | 先同步中，获得模拟回执后已同步 |
| 隐私说明 | 打开隐私面板及清除数据确认 |
| 设置 | 修改本机孩子昵称、设备名；刷新保留 |
| 三种风格切换 | 保持业务状态；共用 MVP 页面模板 |

创建/说明弹窗支持关闭和 Escape，限制 Tab 在弹窗内。传统 div 按钮补充键盘激活及焦点轮廓。

## 复用边界

- flow-core.js：无 DOM 的业务状态与事件，可被正式前端复用；网络回执需要独立适配器接入。
- flow-ui.js：原模板数据映射、事件绑定、辅助面板和手机入口渲染。
- index.html：三方向风格令牌及评审入口；mobile.html 进入同一实现的独立手机模式。
- mvp-templates.js / mvp-templates.css：原 MVP 页面结构及作用域样式，是当前布局基线。
- 计划与设置保存在独立 localStorage key：teamo-mobile-extras-v1。运动任务/记录沿用 teamo-ui-flow-v1。
- 定时计划不会后台自动执行，需用户手动发送。首页分钟、星数及质量图表依旧是视觉示例，真实累计事实见成长面板和结果记录。
- 未连接摄像头、真实算法、设备或云端。页面不采集视频；所有设备事件及计数明确属于本地演示。

## 验证与下一轮

flow-core.test.cjs 通过状态保护、隐私暂停、断网保存、同步回执、重复结束和刷新恢复检查；verify-compact.cjs 通过90组合、主链控制器、辅助面板、计划冲突保护及12手机页面结构检查。测试采用 Node VM，不代表真实 DOM 点击、布局或浏览器视觉验收。

下一轮应在真实浏览器验证三种风格的完整点击路径、360/390/430宽度、弹窗键盘焦点及滚动，再将稳定模板抽成正式前端页面组件。现阶段手机入口是共享代码的独立展示模式，不是已经构建完毕的独立工程包。
