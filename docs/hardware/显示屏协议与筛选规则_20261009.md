# RV1106显示屏：先协议建池，再按产品条件筛选

> 2026-10-09。开发板只做验证平台，产品自研主板。涛哥已采购1106开发板，但具体板、SoC后缀和SDK版本仍未知；以下按公开Luckfox RV1106资料建立条件候选池，不能外推已买的其他厂家板有相同驱动。

## 1. 新发现与旧结论修正

此前“只有LF40找到指定RV1106平台的显示适配证据”不完整。本轮补查到Luckfox官方LVGL教程明确给出 **Pico Pro/Max＋Pico-LCD-1.3**，含ST7789V framebuffer、设备树及LVGL例程。因此把Pico-LCD-1.3增加为SPI验证基准，保留LF40两款为RGB验证基准；既有其他小屏并未因此自动变成兼容。[官方LVGL教程](https://wiki.luckfox.com/Luckfox-Pico-Plus-Mini/Luckfox-Pico-LVGL/)

教程示例`spi-max-frequency=20MHz`与`fps=30`是配置，不能解读为240×240全屏实际达到30fps。

## 2. 什么算支持：分三层，不凭接口名称盖章

1. **SoC层**：芯片有没有相关外设能力。
2. **板层**：所购板是否引出所需引脚、电压和端子；引脚是否与相机、存储、网络冲突。
3. **SDK＋屏层**：具体屏的控制器、初始化、分辨率、偏移、时序、背光及触控驱动是否在该板SDK跑通。

| 协议/架构 | 已核事实 | 候选资格与限制 |
|---|---|---|
| 普通4线SPI显示 | RV1106公开资料列2路SPI；Luckfox配置工具列Pro/Max的FBTFT；官方有ST7789示例 | ST7789/ST7789V2小屏优先建池；不同面板需初始化/偏移/颜色/触控适配。ST7735S/GC9A01不能仅凭SPI认定已有驱动 |
| 并行RGB565/666 | RV1106资料列RGB565/666；Ultra/Ultra W官方适配LF40-480480和LF40-720720 | 自研板可评估其他RGB屏，必须核RGB宽度、时序、像素时钟、同步/DE、复位/配置和引脚复用；“支持RGB”不是任意RGB屏即插即用 |
| MCU/8080、串行RGB | SoC资料列MCU LCD、Serial RGB | 不等于已买板完整引出或SDK已有驱动；进供应商确认池，不作为首轮点亮保证 |
| 屏用QSPI | 本轮未取得所购板作为四数据线LCD主机的完整证据 | QSPI屏入条件池；不能把普通SPI或Flash专用接口当作现成LCD QSPI支持 |
| UART智能屏/ESP显示协处理器 | RV1106有UART；智能屏有自带控制器 | 发送计数、动作、状态，由屏端绘图。电平/协议/UI工程/升级需开发；不是RV1106直接驱动裸屏 |
| MIPI DSI / HDMI | 已查RV1106资料没有给本方案的原生DSI/HDMI显示路径；CSI是摄像头输入 | 纯DSI/HDMI屏退出直接连接池。加桥接是新架构，成本、供电和驱动另算，不能凭MIPI字样判断兼容 |
| 单色OLED/电子纸 | 部分可经SPI/I2C实现，但本产品需要彩色角色动画 | 暂排除本轮主显示；状态辅屏可另立需求 |

来源：[RV1106 V1.3公开资料](https://files.luckfox.com/wiki/Luckfox-Pico/PDF/Rockchip%20RV1106%20Datasheet%20V1.3-20230522.pdf)、[官方配置支持矩阵](https://wiki.luckfox.com/Luckfox-Pico-RV1106/Peripherals/Luckfox-config/)、[RGB适配](https://wiki.luckfox.com/Luckfox-Pico-Ultra/RGB-Screen/)。RGB666为每通道6bit、每像素18bit；原教程英文“6bits per pixel”不照抄为正确色深。

## 3. 市场池的范围与证据等级

本轮检索Waveshare、Luckfox、Nose Display、EastRising/BuyDisplay、Tailor Pixels、Adafruit的一手型号与图纸，覆盖普通SPI、并行RGB、条件QSPI/MCU和智能屏。包含厂家目录中的真实产品，但**有型号页面不等于当前有库存**。没有统一的全球完整SKU目录，不能声称穷尽所有市场产品；后续供应商提交新型号按相同规则入池。

- A：具体板＋具体屏有官方例程/适配，仅表示官方证据；本团队未实测。
- B：协议可作为候选，有控制器/尺寸资料；该SKU在目标板仍需移植验证。
- C：接口模式、针脚或SDK缺项；等待技术负责人/供应商证据，不纳入已支持清单。
- D：智能屏/协处理器间接路线；须单独批准架构与协议。

完整候选与可调整筛选见[筛选页](display-protocol-filter-20261009/index.html)；[市场池JSON](display-protocol-filter-20261009/displays.json)可追溯每款来源。

## 4. 先设条件，再输出结果

以下是我建议带去讨论的**初筛条件，不是已批准产品需求**：

| 条件 | 建议初值 | 为什么这样筛 |
|---|---|---|
| 显示角色动画 | 彩色、优先IPS | 单色/电子纸暂不入主显示池 |
| 分辨率 | 横纵均≥240；360×360为圆屏优选方向 | 不把128×160与360×360混为同等显示体验；具体字号、观看距离要验证 |
| 尺寸 | 优先1.5–2.1″；小于1.5″保留对照 | 1.28/1.3″适合点亮验证，但角色及运动反馈可读性需产品确认 |
| 完整安装包络 | 默认两轴≤55mm，紧凑目标可改≤50mm | 屏AA不是完整模组；触控盖板、支架、FPC再计空间。可以旋转安装，仍需核朝向 |
| 板协议 | 默认普通SPI；确认Ultra/自研RGB后选RGB分支 | 开发板未知时不偷换为任意接口可用 |
| 触控 | 默认不强制，产品可切换必需 | 触控要另检查I2C/IRQ/复位、盖板外形和驱动；不能给非触控SKU加标签 |
| 软件 | 指定板/SDK能亮屏，计数/角色动画与算法并行通过 | 同IC可复用不等于无适配；只点亮不等于UE可用 |
| 供货与成本 | 国内指定型号含税报价、样品交期、开发费 | 未报价项保留未知；不把美元屏价等同整机成本 |

## 5. 推荐先做的验证分支

**若买的是Pro/Max：**用Pico-LCD-1.3官方案例验证FB/LVGL与算法并行；产品候选优先1.54″ST7789、1.69″ST7789V2（非触控/触控），分别检查真实模组尺寸和驱动偏移。参考板只用于验证，最终按自研主板设计。

**若买的是Ultra/Ultra W：**先用LF40官方屏验证RGB链路；产品小RGB屏需要另找指定RGB接口版本的FPC、时序和初始化，不把4″验证屏的84mm外形带入产品机身。

**若圆屏必须保留：**1.28″GC9A01普通SPI可作为低分辨率对照；1.46″SPD2010、1.8/1.85″ST77916 QSPI归条件路线。可以自研ESP显示协处理器，但额外器件、软件和供电纳入自研BOM，不直接把55mm现成ESP开发板当产品主板。

## 6. 数据带宽是筛选条件，不能只看屏像素

RGB565全帧理论数据量＝宽×高×16bit。以**20MHz单数据线SPI演示预算**计算纯像素上限：

| 分辨率 | 单帧字节 | 20Mbit/s纯像素上限 | 30fps纯像素需求 |
|---|---:|---:|---:|
| 240×240 | 115200 | 21.70fps | 27.65Mbit/s |
| 240×280 | 134400 | 18.60fps | 32.26Mbit/s |
| 360×360 | 259200 | 9.65fps | 62.21Mbit/s |
| 412×412 | 339488 | 7.36fps | 81.48Mbit/s |

实际还要扣指令、CPU/驱动开销与总线空闲；局部刷新可能显著降低数据量。这不是屏幕实际帧率或RV1106 SPI最高频率结论。若UE要求全屏高帧率动画，优先评估RGB或本地渲染协处理器，不凭接口存在承诺30fps。

## 7. 给涛哥的问题改成可回答的工程输入

“涛哥，我已经按SPI、RGB、QSPI和智能屏建了候选池。请确认买的1106板型号和SDK版本，屏接口实际引出了哪些引脚？我们能否先跑官方ST7789/LVGL或LF40案例？产品自研板这边，建议保留哪种显示总线、目标动画帧率和触控？我据此把屏压到3–5款，再问厂家拿FPC、初始化代码、含税价和样品交期。”

定屏前验收：指定SKU点亮→颜色/方向/偏移正确→UE与算法并行→触控/背光/休眠→供电/温升→实物含插线尺寸→供货报价。未知项不填零；本轮没有上电、报价或采购记录。
