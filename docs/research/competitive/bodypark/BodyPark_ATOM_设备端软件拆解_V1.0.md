# BodyPark ATOM 设备端软件拆解

> 作用：基于 BodyPark ATOM 实体设备圆形屏实拍，对设备端 UI/UX、运动流程、AI 能力、激励体系进行结构化拆解，为 Teamo 儿童 AI 运动陪伴机器人的设备端设计提供参考。
> 分析对象：BodyPark ATOM（球形机身 + 顶部摄像头 + 圆形触摸屏）
> 素材来源：`D:/work/sportmate/prototype/bodypark/`，112 张连续实拍帧（`_521` → `_632`）
> 分析方法：PM + UX Researcher + Competitive Analyst 三重视角；只基于截图可观察信息，未观察到的内容标记「待验证」。

# 1. 设备与界面总览

## 1.1 硬件形态

| 维度 | 观察 |
|---|---|
| 机身 | 球形/类球形，可单手持握 |
| 屏幕 | 圆形触摸屏，直径约 1.4–1.5 英寸（观感） |
| 摄像头 | 顶部独立球状模组，可上下调节角度（5°–40°） |
| 按键 | 机身右侧至少一个圆形物理按键；截图功能需「同时按下两个按键」 |
| 存储 | 支持 microSD 卡，用于保存视频和照片 |

## 1.2 设计语言

- 深色背景为主，强调色为荧光绿/草绿色（训练、CTA、进度）
- 圆形屏充分利用同心圆、环形进度条、中心大数字
- 表情/拟人化 face 作为核心情感元素（idle、加载、反馈）
- 列表项采用大圆角胶囊按钮，左右滑动或上下滚动选择

# 2. 页面拆解

## 2.1 待机 / 环境态

### 页面基础信息

| 字段 | 内容 |
|---|---|
| 页面名称 | Idle / 待机脸 |
| 所属模块 | 环境态 |
| 页面类型 | 首页 / 待机页 |
| 用户角色 | 儿童 / 家长 |
| 触发入口 | 设备开机或静置返回 |
| 核心目标 | 显示时间/电量，传达设备「在场」与情绪 |

### 视觉结构

- 顶部区域：时间 + 电量图标
- 中部区域：拟人化双眼 / 爱心眼 / 笑脸等表情
- 底部区域：无操作入口，整体为状态展示
- 主要 CTA：无；通过滑动/按键进入功能

### 功能拆解

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| 1.1 | 时间显示 | 24 小时制，可切换 | P0 |
| 1.2 | 电量显示 | 图标 + 百分比；可设置首页是否显示 | P0 |
| 1.3 | 表情状态 | 通过眼睛/爱心/笑脸传递情绪 | P1 |

### 状态模型

| 状态 | 触发条件 | 页面表现 |
|---|---|---|
| 默认状态 | 静置 | 显示时间 + 双眼表情 |
| 活跃状态 | 用户靠近/操作 | 表情变化（如爱心眼） |
| 低电状态 | 电量低 | 电量图标变红（待验证） |

### AI 能力分析

- 未发现主动 AI；表情为预设动画，非基于用户情绪的生成式反馈。

### 对 Teamo 的启发

| BodyPark 设计 | Teamo 改进方向 |
|---|---|
| 待机脸仅展示时间与简单表情 | 可加入宠物化状态（如「困了」「饿了」），与儿童运动目标绑定 |
| 电量显示可开关 | 儿童端默认隐藏电量，避免焦虑；家长端可见 |

| 4.2 | 软件更新 | Atom OS 版本检查、版本历史 | P1 |
| 4.3 | 通用 | 关于、语言、法律与合规、配对模式、恢复出厂设置 | P0 |

### 状态模型

| 状态 | 触发条件 | 页面表现 |
|---|---|---|
| 默认状态 | 进入设置 | 显示一级菜单 |
| 展开状态 | 点击某一项 | 进入二级设置页 |
| 更新状态 | 点击检查更新 | 显示「已是最新」或下载进度 |

### 产品策略

- 账户信息中身高体重用于运动消耗估算；会员入口将硬件与订阅服务绑定。
- 恢复出厂、配对模式放在「通用」深层，降低儿童误触风险。

### 对 Teamo 的启发

| BodyPark 设计 | Teamo 改进方向 |
|---|---|
| 设置层级较深，适合家长 | 儿童端隐藏设置入口；家长端通过小程序管理设备 |
| 账户信息含身高体重 | 可迁移为儿童档案，支持多孩切换 |
| 会员入口在设备端 | Teamo MVP 阶段可先不放在设备端，避免儿童误触订阅 |

### 页面基础信息

| 所属模块 | 训练 |

### 功能拆解

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| 6.1 | 5 种开始训练方式 | 展示多种入口：训练模板、快速开始、AI 模式、录制模式、记录模式 | P0 |
| 6.2 | 自定义训练模板 | 保存个人常练组合 | P1 |
| 6.3 | 快速开始 | 从动作库选一个动作直接开始 | P0 |
| 6.4 | AI 模式 | 实时指导和动作反馈 | P0 |
| 6.5 | 录制模式 | 录制训练视频供日后回看 | P2 |
| 6.6 | 记录模式 | 不录视频，手动记录动作、组数、重量 | P2 |
| 6.7 | 就一组 | 1 分钟快速完成一组 | P1 |
| 6.8 | 抬头番茄钟 | 端正坐姿、保持专注的轻量模式 | P1 |

### 用户操作流程

```
进入训练
↓
选择开始方式（推荐 / 自定义 / 快速 / AI / 录制 / 记录）
↓
选择课程或动作
↓
选择上课模式（实时教练 / 录制复盘）
↓
摄像头取景 + AI 识别
↓
开始训练
```

### 对 Teamo 的启发

| BodyPark 设计 | Teamo 改进方向 |
|---|---|
| 多种开始方式降低启动门槛 | 儿童端应极致简化：「今日任务」「快速玩一个」两个入口 |
| AI 模式作为默认高亮 | Teamo 也应将 AI 运动识别作为默认训练模式 |
| 录制/记录模式面向健身爱好者 | 儿童场景可简化为「运动回放」与家长端报告 |
| 番茄钟模式 | 可迁移为「坐姿提醒」「专注挑战」，扩展非运动使用场景 |

# 4. 产品策略分析

## 4.1 用户需求

| 需求层级 | BodyPark 满足方式 |
|---|---|
| 降低运动启动成本 | 「就一组」1 分钟快速训练、推荐课程 |
| 实时反馈 | AI 计数、语音指导、画面取景 |
| 长期坚持 | 连续打卡、训练天数/次数统计 |
| 家庭场景 | 电视投屏、多角度摆放、microSD 本地存储 |
| 健身进阶 | 组数、次数、容量、动作库 |

## 4.2 商业目标

| 目标 | 体现 |
|---|---|
| 用户增长 |  onboarding 问候、5 种开始方式降低门槛 |
| 活跃度 |  每日训练推荐、连续打卡 |
| 留存 |  训练记录、成就系统、会员解锁高级功能 |
| 付费 |  ATOM 会员入口、订单兑会员 |
| 生态扩展 |  耳机、手表、电视配件联动 |

## 4.3 产品思路

- **硬件即入口**：BodyPark 把 AI 教练做进设备，手机/电视只作为辅助显示。
- **最小阻力启动**：通过 1 分钟模式、推荐课程、快速开始降低首次使用门槛。
- **数据驱动坚持**：用连续打卡、训练统计、成就徽章构建闭环。
- **订阅增值**：会员体系将高级功能与硬件购买绑定。

| 深色控制中心过多硬件开关 | 儿童易误改网络/亮度 | 儿童端隐藏；家长端小程序管理 |

# 7. 结论与建议

1. **核心学习点**：BodyPark ATOM 把「AI 健身教练」做成了一个独立的球形硬件，训练流程完整、AI 反馈即时、数据闭环清晰。Teamo 应重点借鉴其训练启动低门槛、实时反馈、成就留存三条链路。

2. **核心差异点**：BodyPark 面向健身人群，指标和数据偏成人；Teamo 面向 6–15 岁儿童，必须把「健身数据」翻译为「游戏成长」和「陪伴反馈」。

3. **MVP 优先级建议**：
   - P0：待机宠物脸、训练启动、AI 计数、语音鼓励、结果报告、连续打卡
   - P1：手机副屏、训练前摆放引导、动作库、专注/坐姿模式
   - P2：电视投屏、智能手表联动、录制复盘、microSD 本地存储

4. **待验证事项**：
   - BodyPark 动作纠正的具体反馈形式
   - 是否支持多人体识别
   - 家长端手机 App 的完整功能（本次仅拆解设备端）
   - 云端训练计划生成逻辑
