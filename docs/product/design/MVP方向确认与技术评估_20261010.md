# MVP方向确认与技术评估

2026-10-10用户输入。以下区分用户确认、架构设想和评估建议；不改写历史PRD与硬件文档，不代表算法或硬件已验收。

## 已确认方向

- 视觉识别设想在设备本机运行；需求是稳定、流畅、准确地检测并统计动作，具体指标由算法、硬件共同评测确认。
- 需要断网本地存储：已有任务断网继续执行，已完成成绩保存在设备，联网后补传。
- MVP不保存孩子原始摄像头视频；教学素材与相机视频分开处理。
- MVP不要求断电后接着完成正在进行的运动。已保存成绩仍应在重启后保留；这不等于增加断电续练。未保存会话异常中断的处理需明确。
- 使用前提醒充电；边充边用作为电源设计候选，须确认供电能力、充电并发发热和线缆摆放。电量提醒不能保证绝不意外断电。
- 显示风格通过UI资源切换。LED点阵适合表情、大数字和简单符号；LCD适合文字与较丰富动画。LED背光LCD与LED点阵并非同一类，选型需明确实际屏型。

## 站位灯：建议小成本试验，暂不作为必做器件

用户提出在摄像头附近增加有颜色的灯，照亮大概检测范围，让孩子站进去。

| 方案 | 好处 | 限制与成本 |
|---|---|---|
| 普通发散灯 | 简单、兼顾亮度提示 | 光斑边界模糊，日光下不明显；照亮人不等于标出脚下位置 |
| 有限角度的地面光斑/图案灯 | 可以直接提示大概站位，减少口头移动指令 | 需独立光学件、驱动、功耗及安装空间；设备高度/角度改变，光斑也改变 |
| 图标+短语音，不加灯 | 不增加器件；可动态提示前后移动 | 孩子需要理解提示，仍需验证可用性 |

推荐：用低成本可见光LED地面光斑样机，先与图标+语音比较。灯是指路标记，不是“检测通过”信号。脚在光斑中，上举双手仍可能出画；真正开始仍需全身完整且稳定入镜。不要遮住镜头，不把彩光直接强照脸部；检查镜头眩光、自动曝光/白平衡变化、频闪条纹、功耗和发热。暂不引入激光方案。

颜色可表达调整/准备状态，但同时配图标或声音，不能只靠颜色。普通补光偏向均匀照亮人体，站位指示偏向投到地面，两种目标应分别评估。灯亮度、投射角和控制方式需由硬件确定，不能凭示意图直接选器件。

试验场景：不同房间亮度、深浅地板、地毯、设备摆放高度、1.5–3米距离及动作伸展。比较孩子首次站对比例、站位耗时、误引导和计数表现；结果没有改善则不加入MVP。

## 摄像头：给出评审起点，实测后冻结

建议评审起点为实际采集1280×720、持续30帧/秒；1080p/30帧作为远距离人体细节不足时的对照，不要求一开始全部启用。传感器标称500万像素不能代替实际输出规格。采集帧率与算法处理帧率分别测量，快动作还要看曝光导致的运动模糊。

建议水平视场80–100°、垂直视场60–75°作为初筛区间，均是待验证建议，不是冻结指标。最终取决于身高、摆放高度、俯仰角、距离、伸展动作及实际输出画面是否裁切。宽镜头能看得更多，但人体在画面中会更小，也可能增加畸变。

几何例子：光轴正对检测平面时，可见高度约为2×距离×tan(垂直视场/2)。2米处垂直视场60°约覆盖2.31米；1.5米处只有约1.73米。这个计算只是初筛，未包含光轴偏移、上举手臂、画面裁切和畸变，不能直接承诺1.5米适用于所有孩子。

冻结输出：水平/垂直视场、实际输出分辨率与帧率、可用站位距离、安装高度/角度、曝光表现，以及持续推理时的延迟、掉帧、温升和误计漏计。稳定/流畅/准确要分别用持续运行、反馈延迟、人工真值对照验证；具体通过数值由联合测试决定。

## 任务排队建议

一次只执行一个任务，当前会话不被新任务抢占。待执行任务按计划时间排序，同一时间按设备接收顺序排列；立即任务进入可执行队列，但不插入当前会话。未来任务不能阻挡已经到时的任务。

孩子可以选择当前可执行任务，不自动开练。过期任务跳过并回执；暂停的当前任务仍占执行位置。新任务明确回复“已收到，等待执行”；队列满时明确拒绝，不静默覆盖。容量由资源预算确定，不任意承诺无限队列。

重发同一任务只保留一份；编辑用版本号，当前执行目标不被后台突然替换；取消待执行任务可移除，取消执行中任务按约定结束并保存实际成绩。取消、迟到旧指令、断网补传不应让已取消任务重新出现。队列本地保存，但不由此推出运动中断电自动续练。

需要团队确认：有效期、队列容量、孩子能否跳选、周期任务怎样生成实例，以及执行中取消的提示方式。此方案降低插队与覆盖风险，也比复杂优先级抢占容易实现和验证。
