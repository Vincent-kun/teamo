# Teamo 家长端视觉圣经 V1.0

冻结日期：2026-10-09。状态：当前实现的稳定基线，不代表用户已选定最终品牌方向或完成视觉验收。

## 1. 唯一基准与变更规则

功能、信息架构与模块顺序以用户指定的 `AI运动伙伴/小程序MVP_V0.1/预览_小程序MVP.html` 为基准。当前视觉实现以 `prototype/ui-style-lab-20261008/` 的冻结文件为准。

`index.html` 内的手机和 `index.html?mobile=1` 必须使用同一套 MVP 模板。独立入口 `mobile.html` 只改变展示外壳，不允许另写一套导航和页面布局。

**后续补按钮、修接口、增加状态时，默认保持视觉。不得借机重新排版、换色、替换图标、改变卡片或导航。** 当前三个方向保留为候选皮肤，尚未确定最终品牌方向；不得擅自选择一套或改成三套不同信息架构。

视觉变更须先提出：修改原因、具体页面、旧/新效果、对其他页面的影响；得到用户明确指示再实施。普通逻辑修复、数据绑定、无视觉影响的重构不需要额外确认。用户直接提出的视觉修改即为授权，不重复询问。

## 2. 页面结构固定

| 层级 | 页面 | 不得擅自改变 |
|---|---|---|
| 主导航 | 首页 / 任务 / AI / 成长 / 我的 | 顺序固定；AI居中，成长第四；底栏常驻 |
| 首页 | 招呼、提示、设备、AI助手、快捷入口、今日运动、动作横条、任务、最近记录 | 模块顺序；动作卡横向滚动 |
| 任务 | 三步骤、待进行/计划中/历史、创建邀请、回执、列表 | 三种列表不能合并；请求受理与设备确认分开 |
| AI | 分析入口、七天计划、条件调整、发送、问答 | 独立主页面，不能降级为首页弹窗 |
| 成长 | 学伴、概览、周图表、分析、姿态、亮点、小结 | 完整主页面，不能只剩弹窗统计 |
| 我的 | 家长、孩子、设备、消息、隐私、帮助、重置 | 设备属于二级入口 |
| 二级 | 设备、动作库、记录、分析、姿态、孩子资料 | 保留返回和来源关系 |

本机演示统计与状态提示是辅助信息，不能替代原模块。新模块先明确归属位置，不在页面顶部无限叠加。

## 3. 视觉系统固定

当前主显示方向为 clear（清晰成长）；warm、arena 为可切换候选。三个方向必须共用页面结构，只允许使用各自已经存在的视觉令牌。皮肤切换保持任务、计数、页面与记录状态。

**取值权威是当前 CSS，而非旧报告、设计说明表或凭记忆填写的色号。** `index.html` 的 data-skin 规则定义令牌；`mvp-templates.css` 定义 MVP 页面；禁止再给单页硬编码一套新主题。

### 排版与控件

- 字体沿用当前系统中文字体栈，不引入新的装饰字体。数字可用等宽数字特性。
- 当前 MVP 主标题：28px，行高1.2，字距-0.7px；页面左右内边距18px；章节上间距24px。这些是已实现值，不要求本轮重新覆盖已有局部样式。
- 交互按钮最低44px；底栏按钮当前48px。小图标或标签的点击范围应扩展，避免缩小目标。
- 卡片继续使用当前 card/line 令牌与轻阴影；不得为新功能新增与整体无关的厚边、发光或渐变。
- AI中央入口保持现有品牌色强调；其他导航使用一致图标与选中态。图标系统尚未做最终定稿，本轮冻结现有资源，不混入新的 emoji 风格。
- 滚动发生在内容区，底栏不随长内容消失。预览机身与评审外壳不属于产品UI。
- 焦点轮廓保留，不能为美观移除；状态不能只靠颜色表达。
- 没有真实算法数据时展示“未接入/示例”；不可用随机分数填满视觉。

## 4. 交互状态也属于设计

每个控件必须有可用、不可用、处理中、成功、失败或空态中适用的状态。只调整必要状态表达，不因此换掉整个组件。

任务：发送中 → 后台受理 → 设备确认 → 待开始 → 运动中/暂停 → 已结束。
记录：设备保存 → 待同步 → 同步中 → 已同步。断网不丢本机记录；关闭隐私盖停止计数，恢复需主动操作。

AI计划、问答、星级、分钟与质量图表的模拟边界继续明确。视觉规范不替代 PM 的功能冻结、算法验收或设备协议。

## 5. 给前端的实施规则

1. 先找到现有模板和令牌，再修改事件/数据；避免创建同功能的新页面。
2. 复用 mvp-templates.js 的结构与 mvp-templates.css 的类，交互绑定留在 flow-ui.js，状态规则留在 flow-core.js。
3. 修改前后检查五个主页面及受影响的二级页，切换三个方向检查结构一致。
4. 检查360/390/430宽度、长文案、空记录、离线、暂停、弹窗与底栏；真实浏览器结果才可作为视觉验收。
5. 交接需说明“逻辑变化/视觉变化/验证结果”，禁止把重做布局写成“补齐按钮”。

## V1.1 用户授权修订：克制的系统式视觉

2026-10-09，用户明确要求移除青色底、多彩渐变、过多亮边和圆角，贴近手机系统交互习惯。本节优先于上文V1.0颜色及旧皮肤描述。

- 手机背景固定 #F2F2F7，主要卡片 #FFFFFF，正文 #1C1C1E，次要文字 #636366，分隔线 #E5E5EA。
- 单一强调色 #3F6B38；浅强调底 #EEF3EC。仅主要操作、选中项、进度和在线状态使用；不要为每个功能分配不同颜色。
- 去除手机页面渐变、玻璃模糊、内高光与卡片投影；普通卡片圆角12px、按钮10px、小标记6–8px。
- 首页AI入口改白底普通列表式层次；不再用大块青色争夺注意力。主任务提交按钮承担行动强调。
- 底栏固定，普通项不使用彩色大背景，中央AI仅保留轻量识别。
- 演示免责声明使用次级文字，不占页面第一视觉焦点。
- MVP模块顺序、导航和功能保持不变；图表、统计及AI模拟标注继续保留。
- 三套旧皮肤仍在评审工具中保留，但手机底色与控件统一服从本节，不能切回多彩背景。设备候选外观未修改。
- phone-neutral.css 是当前手机视觉覆盖层；后续应归并令牌，不能新增相互竞争的页面覆盖层。

冻结依据更新为包含 phone-neutral.css 的清单。结构与状态测试通过不等于已完成真实浏览器视觉验收。

## V1.4 提示文字纪律（2026-10-09 用户授权，优先于前文冲突条款）

页面 UI 中不欢迎与当前功能无关的提示小字。本节为硬性纪律，适用于全部页面、全部皮肤、手机端与设备端。

1. **禁止用户命令原话上屏**：任何用户对话、指令、需求描述的原话（或近似转述）严禁渲染进任何页面、弹窗、空态、状态条或看板说明。UI 文案只能由产品文案规则生成，不得回显交互过程。
2. **禁止实现说明类小字**：技术实现说明（如"计数来自本机测试""质量图表与七天计划为视觉示例""同数据 · 每方向独立版式语言"）不得出现在产品页面正文。真实/模拟数据边界记录在交接文档与 `flow-ui.js` 的演示标注中即可，不上屏。
3. **确需保留的提示**：与当前功能直接相关的状态提示（待同步、未接入、空态引导）允许存在，但每处只保留一句、功能导向，使用 `--muted` 次级文字色，不占用首屏视觉焦点。
4. **评审外壳与产品 UI 分离**：看板外壳（index.html 评审区）的说明文字属于评审工具，美化时不得将其迁入手机页面。
5. **遗留清理**：`flow-ui.js` 中 `demo-status` 免责声明与 `flow-inline-state` 内的占位说明句，在下一轮视觉改动时一并按本节处理；已授权的视觉改造不得新增任何本节禁止的文字。
