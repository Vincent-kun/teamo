# UI风格实验室：源码评审与紧凑优化

日期：2026-10-09。范围：`prototype/ui-style-lab-20261008/index.html`。本轮没有有效的浏览器截图证据，不称为完整视觉审计。结论来自本次源码检查。

## 已处理

原版把3方向×3版本×4页共36张手机预览、18个设备预览与长篇说明同时放入DOM，增加滚动与对比记忆负担。现改为一个固定展示区：方向→皮肤→页面，另保留机型和缩放。设备形状/状态独立选择，每次只生成手机1张、设备1个。切换风格保留页面与设备态，切换方向默认基础皮肤。参考和令牌默认折叠。加入控制分组、明确标签、按压状态和可见键盘焦点。业务按钮仍为静态展示，已有模板未重写。

## 后续优化建议（依优先级）

1. 统一业务交互模型。当前切换只演示视觉；运动邀请→后台受理→设备确认→运动→本地保存→云端同步应真实可点击，三方向共享同一模型，不能用视觉差异改变业务事实。
2. 示例分数、有效次数与质量建议标注模拟；图表不作为算法已有能力。不要让展示得分抢占任务状态与同步状态的层级。
3. 运动阶段角色静止、停止持续跑马灯；固定暂停位置。减少动效规则已存在，但默认装饰强度仍须实机观察。本轮关闭预览区域持续跑马灯与角色浮动，不增添新素材。
4. 方向说明中的“最易理解”“低龄接受度最高”等缺少用户测试，不作为选型证据；参考须具体到原作者作品和截图，不能只引用画廊首页或搜索页。
5. 真机校准数字、触控和圆屏安全区。既有“圆屏内切正方形左右20px”等描述不应当冻结规格。360直径的真正内接正方形边长约255，左右约53；实际采用何种区域要看元素位置与屏幕规格，不能混用圆形/矩形安全区概念。
6. 桌面并列双端，窄屏上下排列；下一验收重点是横向溢出、1:1缩放下焦点可见性、键盘操作、连续切换是否丢失对照位置。不得只凭DOM数量判断布局可用。

## 验证与限制

Node VM检查通过90种组合：36种手机页面/皮肤组合、54种设备形状/状态/皮肤组合。每次一张手机与一个设备，无undefined模板输出；通过实际注册的控制回调验证切换皮肤保留页面。没有真实浏览器渲染、点击截图、屏幕阅读器或儿童理解验证。

旧版为`index-long-board-archive-20261009.html`；新版仍从`index.html`打开。不变更PRD、MVP范围或真实硬件决定。
