# 设备端 UE 参考与视觉边界

用户明确指定参考：Teamo设备端UE展示.html（同目录）。用户提供的 localhost 展示地址未直接访问，本轮读取本地同名文件，不宣称两者内容已核验一致。仅参考交互与内容，不复制视觉。

## 交互参考

| 场景 | 可复用规则 | 需要修正/约束 |
|---|---|---|
| 待机 | 学伴表情；上滑待办、下滑计划、左滑动作、右滑排行及反向返回 | 手势需有可见入口，不依赖用户猜测 |
| 自主运动 | 选动作→设目标→入镜→准备→倒计时→计数→庆祝→结果 | 仅已支持动作可执行；模拟计数不得标成真实识别 |
| 暂停/离开 | 保留计数，继续或结束 | 重新入镜才允许恢复；不得切页重置会话 |
| 家长任务 | 到达提示→详情→开始或加入待办 | 后台受理、设备接收、孩子开始必须分开 |
| AI计划 | 接收→逐项执行→组间休息→继续/完成 | 单次会话与多项计划分开建模，不能靠跳页假定已完成 |
| 隐私盖 | 物理开关状态提示 | 参考源码只切换标志/提示；不能直接复用为安全实现，关闭必须停止识别与计数 |
| 离线/异常 | 显示离线和连接异常 | 本地记录保存、补传回执、超时和重试独立 |
| 姿态 | 提示、活动、计时结束 | 尚未接算法时明确标注示例，不作医疗结论 |
| 学校/排行 | 保留在完整场景清单中 | 待PM范围确认及学校数据授权；不自动纳入MVP或开启儿童排名 |

## 视觉边界

继续使用已有设备候选的机身、圆/方屏与学伴眼睛作为初始视觉基准，未指定新的最终方向。禁止复制参考页的配色、渐变、庆祝粒子、装饰阴影和复杂卡片。

设备与手机采用不同信息密度：设备以远距离计数、动作名、简短反馈为核心；每屏一个主要行动，暂停/结束可达。普通屏使用深中性底、单一强调色；隐私关闭/异常使用图标加文字，不只靠色彩。

圆屏与方屏需要各自排版与安全区，不能缩小手机页面套入设备。最终尺寸、触控方式与安全区等待实机确认。

## 实施顺序

1. 先画运动、任务、隐私、离线主链状态与触发事件，补齐状态保护。
2. 在已有设备视觉上实现主链，再扩展计划、休息、姿态等完整情形。
3. 学校/排行作为范围待定页，不将演示功能视作正式研发承诺。
4. 每轮交付说明参考逻辑、视觉差异、真实/模拟范围及验证结果。

本轮为参考对齐与约束记录，未修改设备UI，也未执行该参考页面的浏览器交互验收。
