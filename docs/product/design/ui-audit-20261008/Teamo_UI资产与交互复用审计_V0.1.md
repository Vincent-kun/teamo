## 5. 建议交互架构与验证脚本

页面只负责显示与发出意图。候选模块：TaskService管理任务；CommandService管理幂等命令与回执；SessionModel维护运动会话；DeviceAdapter接入可信设备快照；RecordSync负责持久化/补传；ConsentService负责授权与最小访问。状态与事件协议先评审，再实现；当前目录名称不代表这些服务已存在。

最小对象：childId、deviceId、taskId、sessionId、commandId、eventId/sequence、recordId与协议版本。会话运动状态、设备连通状态、记录保存/同步状态、隐私状态独立表达。设备计数为运动事实来源；后台确认决定远端保存状态；家长端不得自行生成完成事实。

| 场景 | 预期结果/验收 |
|---|---|
| 请求受理但设备无回执 | 显示等待确认；超时可重试，不显示送达 |
| 同一命令重复/乱序 | 不重复创建会话；旧事件不能覆盖新状态 |
| 离画再返回 | 按实际设备策略暂停/恢复，计数不重复、不补造 |
| 运动中断网 | 会话是否继续取决于本地识别能力；网络状态不替代运动状态 |
| 隐私物理关闭 | 停止采集/识别并清晰提示；视频不持久化 |
| 完成但同步失败 | 显示本地已保存、待同步；补传成功后才标已同步 |
| 保存失败/断电 | 区分完成与可靠保存；恢复不产生第二份会话或重复记录 |
| 取消与完成同时到达 | 按会话事实与协议裁决，保留可解释最终状态 |
| 未支持动作/AI失败 | 明确不可执行，保留手动任务入口；不伪装成功 |
| 撤回授权/删除 | 权限即时收紧，处理补传队列与删除墓碑，避免恢复被删数据 |

## 6. 本轮复用优先级与下一出口

先复用小程序表单与双端演示的操作路径，重写状态/回执/会话与记录逻辑；视觉用同四屏比较三方向，选定后再改页面样式。推荐默认讨论“家长清晰数据结构＋儿童适量陪伴”，不是已定稿的混合风格。循环计划、学校、AI、体态与成长扩展由PM明示本轮/后续。

下一评审需要：真实屏幕与输入方式、展示动作/计数质量依据、实际开发责任人与容量、平台交付范围。完整框架继续保留，11/15只交已确认切片。没有提交/推送或改写生产工程。
