# 1. 产品概述

## 1.1 产品定位

Teamo 是面向儿童家庭运动场景的 AI（Artificial Intelligence，人工智能）运动陪伴机器人。

设备端负责完成：

- 儿童运动交互
- AI 动作识别
- 实时运动反馈
- 运动结果生成
- 设备状态管理

设备端不承担：

- 家长管理功能
- 长期数据分析
- 商业运营能力
- 云端策略配置

## 1.2 产品目标

通过机器人陪伴形式降低儿童运动门槛，实现：

儿童：

> 想运动 → 开始运动 → 获得反馈 → 建立习惯

家长：

> 布置任务 → 查看结果 → 了解运动情况

## 1.3 产品边界

### 设备端 AI 能力边界

设备端 AI 主要用于：

- 人体检测
- 动作识别
- 动作有效性判断
- 运动次数统计

当前 MVP 不包含：

- 医疗健康判断
- 专业运动指导
- 视频上传分析
- 视频长期存储

### 设备端非职责边界

设备端不负责：

- 家长管理功能
- 长期数据分析
- 商业运营能力
- 云端策略配置

# 2. 系统边界

## 2.1 设备端职责

| 能力 | 设备端负责 |
|---|---|
| 摄像头采集 | √ |
| 人体检测 | √ |
| 动作识别 | √ |
| 动作计数 | √ |
| 实时反馈 | √ |
| 运动结果生成 | √ |
| 任务执行 | √ |
| 设备状态管理 | √ |
| 数据同步（产生并上传结构化数据） | √ |

## 2.2 平台端职责

平台负责接收、存储、管理与业务确认设备同步的数据，不与设备端争夺运动发生时的操作与判定：

- 存储运动记录、运动结果与运动星奖励等结构化数据
- 管理设备绑定关系与儿童账号关系
- 负责运动记录、成长数据的业务确认与去重
- 接收设备同步数据并返回业务接收确认（接收确认契约待确认；发送不等于送达）
- 负责家长任务的投递与回执
- 负责长期数据分析、商业运营能力与云端策略配置（不在设备端实现）

## 2.3 小程序 / APP 职责

家长通过小程序 / APP 完成管理类操作，设备端负责运动发生时的操作与判定：

- 家长创建、管理与查看运动任务
- 家长完成设备绑定与授权、确认儿童身份
- 家长查看运动记录与运动星成长记录
- 展示累计运动星与成长记录（运动星由设备端发放信息并同步平台，小程序仅展示；评定标准待设计）
- 不自行递增运动次数、不强制开启采集、不远程绕过设备本地隐私关闭

# 4. 一级功能模块

> 本章所有模块均按统一格式组织：功能描述 / 使用场景 / 功能规则 / 输入数据 / 输出数据 / 边缘情况 / 验收标准。Function ID 与优先级沿用《Teamo Device Software Functional Specification v2.2.1》既有编号与含义，本稿不重新编号、不修改其含义。

## 4.1 设备初始化与绑定

**Function ID：** 1.x（含 1.x.x 子项）
**优先级：** P0

设备首次启动至完成绑定进入主页的全过程，由「首次启动流程」「初始化状态检测」「设备绑定」三部分组成。

### 4.1.1 首次启动流程

**Function ID：** 1.x
**优先级：** P0

#### 功能描述

设备首次启动时，引导用户完成设备激活流程。

流程：

```
设备开机
  ↓
初始化检测
  ↓
网络连接
  ↓
设备绑定
  ↓
进入主页
```

#### 功能规则

- 首次启动须依次经过初始化检测、网络连接、设备绑定后进入主页。
- 未完成绑定的设备限制核心运动功能（见 4.1.3）。

#### 边缘情况

| 情况 | 处理 |
|---|---|
| 网络不可用 | 提示连接网络 |
| 绑定失败 | 支持重新绑定 |
| 流程中断 | 保存当前步骤 |

#### 验收标准

- 首次启动进入初始化流程。
- 完成初始化后不重复进入。
- 中断后可以恢复。

### 4.1.2 初始化状态检测

**Function ID：** 1.x（初始化状态检测，无独立子编号）
**优先级：** P0

#### 功能描述

设备启动时检查当前初始化状态。

#### 检测内容

- 是否完成绑定
- 是否完成网络配置
- 是否存在用户信息
- 摄像头状态
- AI 识别能力是否就绪
- 存储状态
- 电池状态

#### 状态规则

| 状态 | 行为 |
|---|---|
| 未初始化 | 进入初始化流程 |
| 已初始化 | 进入主页 |
| 初始化异常 | 进入恢复流程 |

#### 边缘情况

| 情况 | 处理 |
|---|---|
| 网络不可用 | 提示连接网络 |
| 绑定失败 | 支持重新绑定 |
| 流程中断 | 保存当前步骤 |

#### 异常处理原则

能力检测异常时：

- 提示用户当前影响；
- 限制受影响的功能（如摄像头异常不进入运动识别）；
- 引导用户恢复，能力恢复后重新确认。

#### 验收标准

- 设备可正确识别初始化 / 已初始化 / 初始化异常三种状态。
- 状态判断驱动后续入口正确。
- 摄像头、AI 识别、存储、电池异常时用户可获知影响，受影响功能被限制并可引导恢复。

### 4.1.3 设备绑定

**Function ID：** 1.x.x
**优先级：** P0

#### 功能描述

设备与儿童账号建立关联。

#### 使用场景

家长购买设备后，通过平台完成设备绑定。

#### 功能规则

1. 一个设备对应一个主要儿童档案。
2. 绑定成功后同步用户信息。
3. 未绑定设备限制核心运动功能。

#### 输入数据

| 信息 | 来源 |
|---|---|
| 设备身份信息 | 设备 |
| 儿童账号 | 平台 |
| 绑定授权 | 家长 |

#### 边缘情况

| 情况 | 处理 |
|---|---|
| 已绑定设备重新绑定 | 提示：当前设备已有绑定关系，请解除后重新绑定 |
| 网络异常 | 显示：网络连接失败，请检查网络 |

#### 验收标准

- 绑定成功后设备进入正常状态。
- 用户信息同步正确。
- 异常情况下提示明确。

## 4.2 首页与陪伴入口

**Function ID：** 2.x
**优先级：** P0

### 功能描述

首页作为儿童进入设备功能的主要入口。

展示：

- 机器人角色状态
- 当前任务
- 快速运动入口
- 设备状态

### 页面结构

```
机器人陪伴区域
  ↓
今日任务区域
  ↓
运动入口
  ↓
状态提示
```

### 功能规则

首页根据设备状态动态变化：

| 状态 | 首页展示 |
|---|---|
| 正常 | 陪伴主页 |
| 有任务 | 任务提醒 |
| 异常 | 状态提示 |
| 未绑定 | 绑定引导 |

### 边缘情况

| 情况 | 处理 |
|---|---|
| 无任务 | 展示自主运动入口 |
| 网络断开 | 提示离线状态 |
| 设备异常 | 展示恢复入口 |

### 验收标准

- 首页入口完整。
- 状态展示正确。
- 儿童可快速进入运动。

## 4.3 运动任务入口

**Function ID：** 2.x
**优先级：** P0

### 功能描述

设备端提供儿童运动任务入口，支持儿童根据设备下发任务或自主选择运动。

运动任务来源：

- 家长端创建任务
- 平台同步任务
- 设备自主运动入口

### 使用场景

**场景 A：家长布置任务**

```
家长创建运动任务
  ↓
平台同步
  ↓
设备提醒儿童执行
```

**场景 B：儿童主动运动**

```
儿童进入运动入口
  ↓
选择运动项目
  ↓
开始运动
```

### 功能规则

任务信息包含：

| 字段 | 说明 |
|---|---|
| 运动项目 | 当前执行动作 |
| 目标次数 | 需要完成数量 |
| 任务状态 | 未开始 / 进行中 / 完成 |
| 创建来源 | 平台 / 设备 |

### 边缘情况

| 情况 | 处理 |
|---|---|
| 无任务 | 展示自主运动入口 |
| 任务过期 | 提示任务失效 |
| 同步失败 | 保留本地已有任务 |

### 验收标准

- 设备可以展示有效任务。
- 儿童可以进入任务流程。
- 任务状态变化正确。

## 4.4 运动项目选择

**Function ID：** 2.x.x
**优先级：** P0

### 功能描述

儿童选择需要执行的运动项目。

MVP 支持运动类型：

- 开合跳
- 深蹲起
- 高抬腿

- 动作示范
- 目标次数
- 开始入口

### 功能规则

选择运动后进入准备阶段。

流程：

```
选择动作

动作确认

准备倒计时
  ↓

```

### 边缘情况

| 情况 | 处理 |
|---|---|
| 动作未选择 | 无法开始 |
| 摄像头异常 | 提示检查设备 |
| 识别环境不满足 | 提示调整位置 |

### 验收标准

- 支持 MVP 动作进入。
- 动作信息展示正确。
- 开始流程正常。

## 4.5 运动准备阶段

**Function ID：** 2.x.x
**优先级：** P0

### 功能描述

运动开始前，引导儿童完成准备。

### 功能流程

```
进入运动
  ↓
摄像头启动
  ↓
检测人体
  ↓
倒计时
  ↓
进入运动状态
```

### 功能规则

**运动开始前自动检查**（任一不满足时提示儿童调整，不进入运动状态）：

- 摄像头是否正常
- AI 识别是否准备完成
- 设备摆放是否满足要求

**准备阶段检测内容**（设备检测）：

- 是否检测到人体
- 人体位置是否满足识别要求
- 摄像头是否正常

### 边缘情况

| 情况 | 处理 |
|---|---|
| 未检测到人体 | 提示：请站到机器人前方 |
| 人体距离异常 | 提示：请调整距离 |
| 摄像头异常 / AI 未就绪 / 设备摆放异常 | 提示儿童调整或告知暂不能开始，恢复后重新检查 |

### 验收标准

- 摄像头正常启动。
- 准备阶段状态正确。
- 无人体无法进入运动。
- 摄像头、AI 识别或设备摆放不满足时不会开始运动，恢复后可正常进入。

## 4.6 AI 识别能力

**Function ID：** 3.x
**优先级：** P0

### 功能描述

设备通过本地 AI（Artificial Intelligence，人工智能）能力识别儿童运动动作。

### AI 处理流程

```
摄像头采集
  ↓
人体检测
  ↓
关键动作判断
  ↓
动作有效性判断
  ↓
计数结果输出
```

### 识别范围

MVP 支持：

- 单人运动识别
- 指定动作识别
- 动作次数统计

### 非目标能力

当前版本不支持：

- 多人运动识别
- 医疗健康分析
- 专业运动纠错
- 视频上传保存

### AI 识别状态确认

#### 功能描述

设备使用本地 AI 能力完成运动识别。开始运动前，设备自动确认：

- AI 能力是否可用
- 摄像头是否正常
- 当前环境是否满足识别

#### 功能规则

AI 不可用时：

- 不开始计数
- 提示用户
- 恢复后重新确认，再开始运动

运动中识别能力异常时：停止计数，保留已确认结果；恢复后先重新确认识别就绪，再继续计数，不将恢复误作新增运动。

> 注：本节只描述用户可感知的能力状态与行为，不涉及模型结构、算法细节与准确率指标。

### 验收标准

- 本地 AI 可独立完成 MVP 指定动作的识别与计数。
- 非目标能力不在本 MVP 实现范围内。
- AI 正常时可以进入运动流程。
- AI 异常时不会产生错误计数。
- 恢复后可以继续运动。

## 4.7 人体检测

**Function ID：** 3.x.x
**优先级：** P0

### 功能描述

检测运动区域内是否存在儿童。

### 输入数据

摄像头实时画面。

### 输出数据

| 结果 | 状态 |
|---|---|
| 检测到人体 | 进入动作判断 |
| 未检测到人体 | 等待用户进入 |

### 边缘情况

| 情况 | 处理 |
|---|---|
| 遮挡严重 | 暂停识别 |
| 光线不足 | 提示环境调整 |
| 多人出现 | 根据规则处理 |

### 验收标准

- 正常距离可以检测儿童。
- 无人体时不误判运动。

## 4.8 动作有效性判断

**Function ID：** 3.x.x
**优先级：** P0

### 功能描述

判断儿童动作是否满足当前运动规则。

### 功能规则

设备根据：

- 人体姿态变化
- 动作过程
- 当前运动类型

判断动作是否有效。

### 输出数据

| 结果 | 处理 |
|---|---|
| 有效动作 | 进入计数 |
| 无效动作 | 不计数 |

### 边缘情况

| 情况 | 处理 |
|---|---|
| 动作未完成 | 不增加次数 |
| 动作幅度不足 | 提示重新完成动作 |

### 验收标准

- 有效动作可以累计。
- 无效动作不会增加结果。

## 4.9 动作计数

**Function ID：** 3.x.x
**优先级：** P0

### 功能描述

统计儿童完成的有效动作数量。

### 计数规则

流程：

```
动作开始
  ↓
动作过程检测
  ↓
动作完成
  ↓
次数 +1
```

### 输出数据

实时输出：

- 当前次数
- 完成比例
- 剩余目标

### 边缘情况

## 4.21 设备状态模型

**Function ID：** 7.x
**优先级：** P0

### 功能描述

设备状态用于：

- 设备端交互控制
- 平台状态同步
- 异常定位
- 测试验证

### 设备能力状态

除运行阶段状态外，设备维护以下能力状态，用于控制功能入口、异常处理与用户提示：

| 能力 | 说明 |
|---|---|
| 摄像头状态 | 是否可正常采集 |
| AI 识别状态 | 识别能力是否就绪 |
| 网络状态 | 连接状态 |
| 存储状态 | 剩余空间与可用性 |
| 电池状态 | 电量与供电状态 |

> 边界：设备能力状态仅用于功能控制与同步，不设计设备健康中心页面，不新增用户可查看的复杂管理系统。

### 状态定义

| 状态 | 英文标识 | 说明 |
|---|---|---|
| 关机 | Power Off | 设备未运行 |
| 启动中 | Booting | 设备加载系统 |
| 初始化 | Initializing | 首次配置或恢复配置 |
| 空闲 | Idle | 设备正常等待 |
| 准备运动 | Preparing Exercise | 进入运动前准备 |
| 运动中 | Exercise Running | AI 识别运动状态 |
| 运动完成 | Exercise Completed | 生成结果 |
| 同步中 | Syncing | 上传数据 |
| 升级中 | Updating | 执行 OTA 升级 |
| 异常 | Error | 设备故障状态 |

### 状态流转（正常）

```
Power Off
  ↓
Booting
  ↓
Initializing
  ↓
Idle
  ↓
Preparing Exercise
  ↓
Exercise Running
  ↓
Exercise Completed
  ↓
Syncing
  ↓
Idle
```

异常流程：

```
任意状态
  ↓
Error
  ↓
恢复
  ↓
原状态
```

### 状态切换规则

| 切换 | 触发 | 条件 |
|---|---|---|
| Idle → Preparing Exercise | 儿童进入运动任务 / 用户主动开始运动 | 摄像头正常、用户状态有效、设备资源正常 |
| Preparing Exercise → Exercise Running | — | 检测到人体、倒计时完成 |
| Exercise Running → Exercise Completed | — | 达成目标、用户主动结束 |
| Exercise Running → Error | — | 摄像头异常、AI 识别服务异常、系统资源不足 |

### 验收标准

- 状态切换符合定义。
- 状态同步准确。
- 异常恢复后状态正确。

## 4.25 OTA 升级

**Function ID：** 9.x
**优先级：** P1

### 功能描述

支持设备软件版本远程升级。

OTA：Over-The-Air（空中升级）。

### 升级流程

```
检查升级条件
  ↓
升级文件校验
  ↓
执行升级
  ↓
确认结果
  ↓
失败恢复
```

### 升级规则

检查升级条件（升级前）：

- 电量 / 供电状态
- 网络状态
- 存储空间
- 当前设备状态（如用户正在运动，延迟升级）

升级文件校验：

- 校验不通过的升级文件不安装。

升级保护：

- 保护用户数据；
- 保护运动记录（含已保存未同步结果）；
- 保护系统与识别资源。

失败恢复：

- 升级失败时恢复到可用版本，保护已保存运动记录。

### 边缘情况

| 情况 | 处理 |
|---|---|
| 下载失败 | 重新下载 |
| 升级失败 | 恢复旧版本 |
| 用户正在运动 | 延迟升级 |

### 验收标准

- 升级包正常下载。
- 校验失败不会安装。
- 升级失败可以恢复。
- 升级失败设备可恢复到可用版本；数据不会丢失。

- 网络异常
- 升级异常

### 日志原则

**记录**：时间、状态、事件、错误码。

**限制**：

- 不记录家庭音视频；
- 不保存用户隐私数据；
- 不保存视频、截图或原始语音。

### 边缘情况

| 情况 | 处理 |
|---|---|
| 存储不足 | 自动清理历史低优先级日志 |

### 验收标准

- 关键事件可被记录。
- 日志不包含原始视频或家庭影像。

## 4.27 异常处理

**Function ID：** 11.x
**优先级：** P0

### 功能描述

统一设备端异常的分类、处理原则与恢复流程，保障核心运动流程与数据一致性。

### 4.27.1 异常分类

| 类型 | 示例 |
|---|---|
| 网络异常 | 无法连接服务器 |
| 识别异常 | 动作无法判断 |
| 硬件异常 | 摄像头故障 |
| 系统异常 | 服务停止 |
| 同步异常 | 上传失败 |

**异常分类处理对照**

| 异常 | 处理 |
|---|---|
| AI 异常 | 停止计数 |
| 摄像头异常 | 停止识别 |
| 网络异常 | 自动恢复（多次失败后引导重新配置，见 4.23） |
| 存储不足 | 保护核心数据（优先保护未同步运动结果） |
| 温度异常 | 限制运行（可运行范围内降低运行强度、保持计数可信；达到安全边界时安全停止并保护已保存结果） |

### 4.27.2 异常处理原则

**原则一：不影响用户核心流程**

例如网络异常时，允许本地运动、本地结果保存。

**原则二：保持数据一致**

异常情况下：不丢失运动结果、不重复上传。

**原则三：提供用户反馈**

反馈包括：当前问题、建议操作、是否自动恢复。

### 4.27.3 错误恢复流程

```
异常发生
  ↓
记录错误日志
  ↓
判断是否自动恢复
  ↓
恢复成功 → 返回原状态
  ↓
失败 → 提示用户处理
```

### 4.27.4 AI 识别异常

**场景**

- 人体无法检测
- 动作无法判断
- 环境不满足
- 识别能力运行中异常（如识别资源不可用）

**处理**

1. 停止计数，保留已确认结果
2. 提示用户调整或告知暂不能识别
3. 恢复后先重新确认识别就绪，再继续计数，不将恢复误作新增运动

### 验收标准

- 异常不会导致错误运动结果。
- 用户可以继续完成任务。
- 异常恢复后状态与数据正确。
- AI 异常时不会产生错误计数；恢复后可以继续运动。
