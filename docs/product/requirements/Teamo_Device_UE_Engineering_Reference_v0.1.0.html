A 详细状态与PAGE线框

英文标签仅是设计/研发沟通用语，均为Pending Review，不定义客户端枚举、接口字段、存储结构或算法实现。绑定、运动执行、保存和同步是不同状态维度；PAGE负责呈现与操作确认，不创造事实。

5.1 Exercise Session State 运动会话状态

INIT、READY、COUNTDOWN、RUNNING、PAUSED、FINISHED描述会话执行；SAVED描述结果保存；SYNCING、SYNCED描述同一记录的同步。后面三个状态不替代会话状态，也不要求用户停留在结果页。

状态 进入条件 可执行行为 退出条件 / 去向 关联PAGE
INIT 已进入自主选择或任务确认上下文；不等于设备开机 确认儿童、来源、支持动作与目标；返回 上下文有效进入准备；取消退出，记录创建时机TBD PAGE-02/03，儿童确认PAGE-00/08
READY 有效动作、目标和归属进入准备阶段 看说明、隐私检查、必要时调整站位、明确开始或取消 条件满足且明确开始→COUNTDOWN；不足停留；恢复路线TBD PAGE-04
COUNTDOWN 开始意愿明确且准备满足 等待、取消；禁止计数 完成后复核通过→RUNNING；取消/离画→READY；隐私失效阻断 PAGE-05
RUNNING 初次开始或恢复获准，隐私及准备有效 可信计数与反馈、暂停、提前结束 暂停/判定异常→PAUSED；达标或明确结束→FINISHED PAGE-06
PAUSED 主动暂停或离画/识别异常已判定需暂停 保留次数，说明原因，继续或结束；不累计 继续→READY重新检查；结束→FINISHED；超时TBD PAGE-06→04
FINISHED 达标、主动结束或已确认中断规则生效 停止采集/计数，生成真实结果并交给保存 执行事实保持结束；保存成功增加SAVED事实，失败走异常分支 PAGE-06→07保存衔接
SAVED 6.2.1确认本地结果保存成功 看真实结果、返回首页；允许时后台上传 已保存事实保持；同步进SYNCING，或离线待同步 PAGE-07；PAGE-01提示承载
SYNCING 已保存且正在上传/补传，尚未获平台业务接收确认 查看状态；按契约重试，沿用原记录标识 业务确认→SYNCED；失败→待补传；重试参数TBD PAGE-07/01；后台状态
SYNCED 平台确认接收同一结果记录 查看已同步状态，不重复生成结果或奖励 终态事实保持；冲突处理契约TBD PAGE-07/01；后台状态

READY包含准备阶段，并不单凭该标签允许开始；必须另有“准备满足、隐私允许、儿童明确开始”条件。INIT的标签不承诺记录已创建，创建时机仍按6.1.1待确认。

[INIT] -> [READY：检查隐私与准备] -> [COUNTDOWN] -> [RUNNING]
             ^                         |            |     |
             | 取消/离画                |            |     +-> [FINISHED]
             +-------------------------+            v
             +-- 选择继续并重新准入 ------------ [PAUSED]
                                                     +-------> [FINISHED]
恢复是否再次经过COUNTDOWN：TBD。

隐私关闭、撤权或状态未知时立即阻断采集；不强行归入可继续计数状态，具体异常状态承载与撤权响应时限TBD。未确认事件不计，低置信度不作确定纠错。

5.2 Binding State Model 绑定状态

未绑定 → 等待绑定 → 绑定处理中 → 绑定成功 → 当前儿童确认 → 正常使用（PAGE-01）。正常使用可因有效解绑事实或绑定异常进入相应分支，不把解绑/异常当必经结束步骤。

状态 业务含义 / 允许去向 约束与TBD
未绑定 无有效家庭绑定上下文，进入PAGE-00 不创建账号，不虚构关系
等待绑定 等待家长发起有权限操作 联网依赖、绑定方式TBD
绑定处理中 请求已发起但尚未收到有效关系确认 不把扫码/请求发送称绑定成功；超时、取消契约TBD
绑定成功 设备收到平台认可的有效绑定状态 当前儿童仍须明确；成功确认契约TBD
当前儿童确认 绑定有效，确认当前使用儿童；未明确不分配成绩 确认方式与PAGE-00/08承载TBD，不默认人脸识别
正常使用 有效绑定、当前儿童明确，按各能力条件使用 断网不自动解绑；隐私准入独立检查
解绑状态 收到经授权确认的解绑事实，按规则回未绑定 家长端发起/平台管理；设备处置与离线规则TBD，不承诺本机解绑入口
异常状态 绑定失败、状态失效或上下文不可确认 说明原因并按契约恢复；不擅自解除已有有效关系

具体状态枚举、超时、恢复和跨端一致性TBD。二维码及过期重取路径为候选能力 / Pending Review / 优先级TBD，需与整体绑定方案联合评审，不默认二维码技术方案。设备只执行有效上下文，平台维护云端关系。

5.3 Recording State Model 记录状态

完成运动 ≠ 已保存；已保存 ≠ 已同步。三个维度可同时存在，例如“提前结束 / 已保存 / 待同步”，不能用单一“完成”覆盖。

维度 业务状态 事实依据 页面表达与约束
执行 准备、倒计时、运动、暂停、结束 第3章执行规则与第4章有效事件 PAGE-04–07；结束区分达标/提前结束，其他中断口径TBD
保存 待保存/保存处理中、保存失败、已保存SAVED 第6.2章本地保存结果 PAGE-07保存衔接；失败如实说明，恢复保证TBD
同步 待同步、SYNCING、失败待补传、SYNCED 第6.3章平台业务确认 PAGE-07/01必要提示；网络发送成功不等于业务接收 
[FINISHED：真实结束]
          |
          v
[生成结果 -> 本地保存] --失败--> [未保存 / 恢复重试，保证TBD]
          |成功                        | 按确认规则重试
          v                            +----> 本地保存
[SAVED：已保存] -> [待同步] -> [SYNCING] -> [SYNCED]
                    ^             |
                    +-- 失败待补传+
页面可返回首页；后台处理沿用同一记录标识。

未保存结果不按已保存记录同步；补传不重建结果。退出页面不改变成绩、来源或同步事实。重启只恢复已可恢复事实，不自动续计，恢复频率与断电保证TBD。任务接收状态与本次运动记录状态也需分别表达。

B 异常业务依据

以下整理已有异常职责，均继承Pending Review，不新增诊断能力。提示必须表达已判定原因、当前影响和可行去向；不能确定原因时如实说明不可确认状态，不虚构具体故障。文案示意不作为冻结交互稿。

E 完整评审问题

点击问题可展开背景、待确认内容、影响与所需输入。建议参与方不等于已指派Owner；全部结论仍待评审，描述不批准新能力。

UE-OQ-01 · 绑定方案、联网依赖、成功确认及失败恢复；是否采用二维码 关联范围：PAGE-00、绑定模型。状态：TBD。 **问题背景**：首次使用需要获得有效家庭绑定与儿童上下文，但现稿没有选定绑定技术方案；扫码、联网成功与绑定成功是不同事实。 **具体待确认内容**：明确联网与绑定的先后依赖、配网责任端、绑定凭据来源、有效关系确认条件；若采用二维码，确认有效期、失效恢复与替代路径；定义失败、取消、超时和绑定失效后设备回到哪个状态。二维码仍是候选，不能先当默认方案。 **影响与边界**：影响PAGE-00状态转移及首次启动准入。契约未明确时，UI可以探索引导，但FR不能将某一种绑定方式或超时值写成已批准要求。 **评审所需输入 / 建议参与方**：建议产品、设备端、家长端与平台共同提供绑定链路及失败案例；具体Owner待指定。需要正常、断网、凭据失效与已有绑定关系的业务确认依据。 **应形成的结论**：记录绑定方案、跨端职责、成功依据、异常去向和是否采用二维码；未决项分别登记TBD，不以一次“绑定方案通过”覆盖所有分支。
UE-OQ-02 · 列表/详情及设置分组是否拆分；操作输入和屏幕承载 关联范围：PAGE-00–08。状态：TBD；不决定硬件。 **问题背景**：PAGE号定义逻辑职责，并没有确定显示硬件、输入方式或实际页面数量。任务列表/详情和设置分组可能合并，也可能分步承载。 **具体待确认内容**：确认哪些信息需要同时理解、哪些需要逐步确认；任务列表与详情是否拆分，设置分组如何进入/返回；在已选硬件条件下，选择、开始、暂停、继续和结束操作能否完成。触控、按键或其他方式仍TBD。 **影响与边界**：影响PAGE-00–08承载与导航。不能由逻辑页面数量推导实体屏幕数量，也不能以信息架构倒推已经选定触控硬件。 **评审所需输入 / 建议参与方**：建议产品、UX、硬件与设备研发提供实际显示/输入约束和儿童操作场景，评审远距可理解性与关键操作可达性；验证方法及标准TBD。 **应形成的结论**：形成逻辑PAGE到实体承载的对应关系，记录输入方式、返回路径及硬件约束；PAGE编号保持稳定。
UE-OQ-03 · 自主目标范围与三/七动作关系 关联范围：PAGE-02/06、v0.4 OQ-01。状态：TBD。 **问题背景**：v0.4将开合跳、深蹲起、高抬腿列为当前提议，整体PRD存在七动作口径；自主次数目标的允许范围也尚未确认。 **具体待确认内容**：MVP演示三动作已确认；保留整体七动作追踪，不在本次删除其他动作；逐动作确认允许目标范围、默认值是否需要及无效目标处理。高抬腿单侧/双侧计数口径需与目标和结果一致，不在本稿填入数值。 **影响与边界**：影响PAGE-02可选动作和目标、PAGE-06计数理解及后续FR验收；范围未确认不能把七动作直接加入，也不能宣称其他动作已删除。 **评审所需输入 / 建议参与方**：建议产品负责人结合算法与体育专业的有效规则证据确认，引用v0.4 OQ-01及OQ-03；若改变PRD范围，需另行旧口径—新证据—建议修改变更单。 **应形成的结论**：分别记录动作清单、产品/演示适用范围、每动作目标与计数单位及批准依据；保留未决动作的追踪去向。
UE-OQ-04 · 任务撤销/过期/重复、多儿童及归属确认 关联范围：PAGE-00/03/08。状态：TBD。 **问题背景**：任务接收、执行、撤销与同步各自有事实来源；多儿童时还需保证任务及成绩归属于正确儿童。当前尚未定义全部有效性规则。 **具体待确认内容**：确认撤销/过期在未开始、准备和运动中分别如何处理；重复投递如何识别并维持同一接收结果；当前儿童如何确认、多儿童切换何时允许，已有任务和记录如何保持归属。不得默认人脸识别或让儿童修改家长目标。 **影响与边界**：影响PAGE-00/03/08状态与任务执行入口，并影响记录归属。规则缺失可能使已失效任务仍可开始或成绩被分配给错误儿童。 **评审所需输入 / 建议参与方**：建议设备端与平台提供任务标识、有效条件、撤销事实及当前儿童上下文契约，由产品确认业务规则；Owner与具体契约TBD。 **应形成的结论**：按任务阶段列出有效/无效处理和身份切换条件，注明跨端事实来源；执行状态与同步状态分别记录。
UE-OQ-05 · 准备条件、说明跳过、暂停超时及恢复倒计时 关联范围：PAGE-04/05/06。状态：TBD。 **问题背景**：准备、开始与恢复共用准入检查，但准备满足标准、说明跳过规则及暂停恢复细节未冻结。 **具体待确认内容**：确认身体完整、画面可用与多人情况怎样形成可开始状态；动作与安全说明是否允许跳过及适用条件；主动暂停、离画和识别异常的恢复条件；暂停超时是否结束，继续前是否再次倒计时。各阈值与时长TBD。 **影响与边界**：影响PAGE-04/05/06转移和取消/恢复分支。恢复始终重新检查隐私与准备，保留成绩，不在未满足条件时继续计数。 **评审所需输入 / 建议参与方**：建议产品、算法、设备研发与体育专业提供准备条件及异常证据；硬件提供隐私状态可用性。需覆盖首次开始和暂停后恢复两种情形。 **应形成的结论**：输出准备准入、可跳过规则、暂停原因—恢复条件、超时及倒计时适用关系；未确认参数不进入验收值。
UE-OQ-06 · 保存失败承载、断电恢复、用时及同步确认契约 关联范围：PAGE-07、记录模型。状态：TBD。 **问题背景**：运动结束、本地保存和平台接收是三个独立事实。现稿已要求真实成绩，但保存失败、断电恢复和用时口径仍待确认。 **具体待确认内容**：确认保存中/失败信息由哪个逻辑状态承载、如何重试及可恢复保证；断电后可恢复哪些已确认事实；用时是否包含暂停；平台业务确认与发送完成如何区分，补传与冲突怎样沿用原记录标识。 **影响与边界**：影响PAGE-07结果可信度、恢复路由与家长端一致性；保存失败不得称已记录，发送完成不得称家长已收到，同步失败不得改写达标事实。 **评审所需输入 / 建议参与方**：建议设备端和平台提供记录、保存、恢复与接收确认契约，由产品确认时间定义；存储保留范围、失败保证和冲突策略TBD。 **应形成的结论**：分别记录结束、保存、同步状态及责任端，明确恢复范围和用时定义；保存失败的实体承载可保留TBD但不能丢失分支。
UE-OQ-07 · 角色表情与基础完成鼓励深度 关联范围：PAGE-01/07。状态：Pending Review；不改P0。 **问题背景**：角色状态表情与完成鼓励已有功能依据及P0口径，但最小资源、触发事件和运动星/PB深度尚未明确。 **具体待确认内容**：确认待机、准备、暂停、达标及提前结束需要哪些固定回应；表情与短提示的触发、频率及一致性；基础运动星/PB是否属于本轮最小范围。不能由此增加成长体系、开放聊天或新AI陪伴能力。 **影响与边界**：影响PAGE-01/07及运动状态回应；当前P0保持，不因视觉表达丰富程度自行升降级。未达标结果不能通过鼓励表达成达标。 **评审所需输入 / 建议参与方**：建议产品与UX结合v0.4 OQ-05提供最小事件—回应清单和必要性依据；涉及运动内容由相关专业审核，具体OwnerTBD。 **应形成的结论**：记录最小回应范围、适用状态和后置资源，运动星/PB另列结论；保持事实反馈与表现深度的区分。
UE-OQ-08 · 独立动作辅助检测是否纳入及其授权/退出边界 关联范围：PAGE-09。状态：候选能力 / Pending Review / 优先级TBD。 **问题背景**：运动准备中的人体/画面检测与入镜引导已经映射，但没有证据说明脱离运动任务的独立检测属于MVP。PAGE-09仅为候选。 **具体待确认内容**：先确认独立用户任务及必要性，再决定是否纳入；若纳入，明确主动进入、采集授权、允许输出、异常、退出停止采集与是否需要动作选择。骨架显示和辅助提示分别评审，不默认姿态评分、体态分析或医疗判断。 **影响与边界**：影响PAGE-09及首页候选入口。未批准前不能列为默认入口、承诺独立功能号或用已有4.1.1/3.2.2证明纳入。 **评审所需输入 / 建议参与方**：建议产品、UX、算法和设备研发提供用途、复用边界及隐私检查；OwnerTBD。独立场景需自己的范围依据，不以技术可复用代替产品批准。 **应形成的结论**：记录纳入/延期/不纳入的评审结论、理由和条件；若纳入需同步功能大纲与FR。当前保持候选能力 / Pending Review / 优先级TBD。
UE-OQ-09 · 首页摘要、绑定帮助、预览/骨架、关于信息、声音、出厂恢复、更新等是否需要 关联范围：相关候选分支。状态：候选能力 / Pending Review / 优先级TBD。 **问题背景**：首页摘要、专门绑定帮助、预览/骨架、关于信息、声音、恢复出厂和更新入口均为未批准的呈现或能力提议，不能整组视为必需。 **具体待确认内容**：逐项确认用户问题、必要性和已有功能依据：首页摘要的聚合口径，绑定帮助的内容责任，预览/骨架的隐私及可理解性，设备名称/SN的用途，声音与必要提醒的关系，恢复出厂的本地清理/云端解绑区别，以及OTA是否纳入。 **影响与边界**：影响相关候选分支、资源及跨端契约；不以设置分组或页面示意把候选加入MVP，关于设备也不自动新增诊断工具。 **评审所需输入 / 建议参与方**：建议各候选由产品牵头分别收集UX、硬件、设备端和平台证据，必要时引用v0.4第9章；责任人与优先级均TBD。 **应形成的结论**：每项单独登记纳入/延期/不纳入、功能依据、影响与责任人，不能一条“设置通过”批量批准。全部保持候选能力 / Pending Review / 优先级TBD直至有效评审。
UE-OQ-10 · 配网、授权、删除、提醒设置及家长确认的责任端与入口 关联范围：PAGE-00/08。状态：TBD；保持v0.4跨端责任。 **问题背景**：设备执行隐私与身份上下文，家长端负责有权限的管理，平台维护云端关系；已有责任不等于所有设置都应由设备发起。 **具体待确认内容**：确认配网、授权、数据删除与提醒设置由哪端发起，设备负责哪些状态与回执；家长确认如何生效，离线或权限不明时如何处理；本地停止采集不能被远程任务绕过，设备删除不等于账号注销或云端全量删除。 **影响与边界**：影响PAGE-00/08的可执行操作与跨端提示。范围未确认时仅保留必要状态及TBD入口，不能让儿童无授权完成受限管理。 **评审所需输入 / 建议参与方**：建议产品、设备端、家长端与平台共同提供发起—校验—执行—回执职责链及离线处理依据，沿用v0.4第12章；具体人员TBD。 **应形成的结论**：逐操作记录责任端、权限依据、设备入口是否需要、失败回执与数据处置边界；不由本稿更改账号或平台职责。
