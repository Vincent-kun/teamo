## 0 定位与使用规则

本文定义逻辑页面、入口、页面职责、状态与功能映射，不定义视觉样式、按钮位置或输入硬件。逻辑页面可在屏幕能力评审后合并或分步呈现，不据此确定实体屏幕数量、比例或触控。设备面向6–15岁儿童，家长负责绑定、授权及管理；首页体现角色陪伴，同时保持任务与快速运动易进入。

本附录对应[v0.4功能大纲](Teamo_MVP_设备端软件功能大纲_v0.4_冻结候选_20261012.html)。原功能编号、P0/P1与三/七动作范围不变。新增提议只写“Pending Review / 优先级TBD”，不能根据页面清单认定已加入MVP。已映射的页面继承功能优先级，表达形式仍需评审。

## 1 首次启动与日常启动

### 1.1 首次启动

适用于未绑定设备。恢复出厂后的再次绑定仅在恢复出厂功能获准后适用，不据此承诺已支持。

开机初始化 → 判断绑定/网络状态 → 未绑定时进入绑定引导 → 按已批准方案完成联网与家庭绑定 → 确认当前儿童 → 设备获得有效绑定状态 → 进入首页。

联网、扫码和绑定的顺序TBD：若绑定二维码需平台签发，设备必须先具备可用连接；若采用离线设备标识加家长端配网，步骤可以不同。本文不强制“先绑定后配网”，也不选择二维码或直连协议。

### 1.2 日常启动

开机初始化 → 恢复本地任务、记录和隐私状态 → 绑定有效进入首页；缺少儿童归属时进入身份确认；绑定失效进入绑定引导。断网不要求重新绑定，允许的缓存任务与本地运动仍可执行；后台待同步记录独立补传。

## 3 页面0：绑定与首次使用引导

目标：让家长知道设备是否联网、是否已绑定家庭、当前儿童是否明确。设备执行已确认绑定上下文，不创建账号或擅自改变云端关系。

| 内容 / 操作 | 页面输出 | 依据与状态 |
|---|---|---|
| 绑定状态提示 | 未绑定、等待家长操作、处理中、已绑定或失败原因 | 7.2.3，具体状态契约TBD |
| 联网状态与引导 | 当前连接状态，连接失败处理入口 | 7.1.1–7.1.2，配网入口与责任端TBD |
| 当前儿童确认 | 平台有效儿童身份；未明确不将成绩分配给错误儿童 | 7.2.3，不默认人脸识别 |
| 二维码展示 | 仅在二维码方案通过后显示平台认可的绑定凭据 | 新用户提议；Pending Review / 优先级TBD，不预定由设备生成 |
| 二维码失效后的重试 | 失效提示及重新取得有效凭据的路径 | 若二维码为唯一绑定路径，过期恢复应随核心绑定纳入评审，不能未经评估独立放P1 |
| 绑定帮助 | 最小操作说明或替代操作路径 | 新提议；内容与优先级TBD |

等待操作 → 绑定处理中 → 平台确认成功 → 儿童确认 → 首页；失败返回可重试状态。扫码不等于绑定成功，家长端成功也须由设备收到有效绑定状态。已有家庭绑定时说明真实关系，解绑/切换须经授权，不自动解除。网络失败不伪称完成，扫码失败/凭据过期提供恢复路径；失败保留已有有效关系。

## 5 快速运动与家长任务

### 5.1 快速运动

首页 → 选择支持动作 → 确认自主次数目标 → 共用准备/倒计时/运动/结果流程。当前动作提议为开合跳、深蹲起、高抬腿；选择不支持动作不得伪装可开始。允许目标范围及操作输入TBD。自主结果标记自主来源，不显示为家长布置任务。

### 5.2 我的任务

列表至少让儿童看懂动作、目标和状态；详情提供来源和执行条件。任务名称、创建时间是否必须在设备显示，TBD；不能为了展示字段增加复杂页面。收到任务只更新任务状态/入口，不自动开启摄像头或跳过儿童开始确认。

未开始 → 进行中 → 达标完成或提前结束。同步状态与任务执行状态分别显示：已保存待同步不等于任务未完成，提前结束不等于达标。撤销/过期/重复任务按3.1有效规则处理，细节TBD。

## 6 共用运动流程

| 页面 / 状态 | 必须表达什么 | 允许操作 / 去向 | 条件与异常 |
|---|---|---|---|
| 运动准备 | 动作、目标、简明动作说明和一个主要站位原因 | 调整站位、确认开始、返回 | 未授权/关闭/未知不采集；骨架或视频预览不默认支持 |
| 倒计时 | 开始时机及取消状态 | 等待、取消 | 结束再次满足守卫才运动；离画回准备 |
| 运动中 | 已确认次数/目标、识别状态、适度鼓励 | 运动、暂停、提前结束 | 不确定事件不计，低置信度不确定纠错 |
| 暂停 | 已确认成绩与一个主要原因 | 继续→重新准备；结束→结果保存 | 不清零、不累加；恢复是否再倒计时TBD |
| 结束保存 | 停止采集，生成与保存真实结果 | 等待；失败时按规则重试 | 保存失败不称已记录，恢复保证TBD |
| 运动结果 | 动作、目标、实际、用时、达标/提前结束、保存与同步状态 | 返回首页 | 后台补传不阻断已允许的本地运动，不重复结果或奖励 |

目标、实际与状态来自同一设备运动事实；页面只呈现与触发操作。返回页面不自行重建记录、改目标或递增次数。

## 7 独立姿态检测：候选边界

用户本轮提议将其作为独立检测工具，需区别于已存在的“运动准备中人体检测/站位引导”和非运动体态陪伴。现有4.1.1与3.2.2只支持明确运动流程中的准备能力，不能直接证明独立检测已进入MVP。

| 提议 | 可复用依据 | 未决内容 |
|---|---|---|
| 人体在场检测、站位提示、退出 | 4.1.1、3.2.2、2.2.2 | 独立采集场景、授权、退出关闭规则是否纳入 |
| 骨骼关键点显示 | 无已冻结显示形式 | 显示必要性、屏幕可理解性、儿童隐私与资源；Pending Review |
| 动作辅助提示 | 4.2与5.1仅对已验证动作有效 | 如何选择动作和判断提示；不扩展未验证纠正能力 |

不做医疗体态分析、身材评价或健康评分。若获准，必须明确采集开始/停止意图及隐私守卫；退出关闭采集、不持久化原始帧。PAGE-09目前不计入已映射MVP页面承诺。

## 9 信息架构与评审问题

日常首页 → 快速运动 / 我的任务 / 设置。

快速运动与任务 → 共用运动准备 → 倒计时 → 运动中 ↔ 暂停/重新准备 → 结束保存 → 结果 → 首页；同步独立进行。

首次未绑定 → 绑定与联网引导 → 当前儿童确认 → 首页。

独立姿态检测、声音控制、恢复出厂、检查更新为待评审分支，未加入当前默认入口。

| 问题 | 冻结前需要结论 |
|---|---|
| 绑定方案及联网先后依赖 | QR是否采用、由谁提供凭据、过期/失败恢复及配网端 |
| 页面承载与操作方式 | 屏幕与远距可读性、触控/按键等输入、逻辑页面合并范围 |
| 独立姿态工具是否纳入 | 与运动准备/体态陪伴的区别、骨架显示是否需要 |
| 首页今日摘要是否需要 | 任务/完成的聚合口径与端间一致性 |
| 设置新增提议的范围 | 声音、名称/SN、出厂恢复、更新入口及家长授权 |
| 页面对既有角色/三动作边界 | 继承v0.4待决结论，不通过UE另行冻结 |
