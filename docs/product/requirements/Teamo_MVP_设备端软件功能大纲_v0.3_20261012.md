# Teamo 儿童运动陪伴机器人
# MVP 设备端软件功能大纲 v0.3

> 日期：2026-10-12 · 状态：评审稿 · 负责人：设备端软件产品负责人（待确认）
> 用途：先确认设备有哪些功能、每项功能做什么，以及MVP范围。

设备帮助6–15岁儿童完成家庭运动，家长通过APP/小程序布置任务、查看结果。设备端负责运动当下的交互、识别、反馈、记录及同步。

本稿以开合跳、深蹲起、高抬腿为当前MVP动作提议。现行整体PRD包含七动作，三动作是演示切片还是产品范围调整，仍需确认。P0为本稿MVP必需项；P1为后续候选；P2暂不列具体功能。本文未冻结。

## 功能总览

| 一级功能 | 二级功能 | 主要输出 |
|---|---|---|
| 1 设备启动与运行管理 | 启动与运行；状态与异常 | 设备可用状态、恢复结果及故障提示 |
| 2 运动入口与操作 | 运动入口与角色回应；状态提示与操作确认 | 清晰入口、可操作信息与角色回应 |
| 3 运动任务与执行 | 任务接收与查看；运动准备与开始；暂停、继续与结束 | 可执行目标及开始、暂停、恢复、结束状态 |
| 4 动作识别与计数 | 识别状态与有效计数；三种动作识别 | 三种动作的有效次数及识别状态 |
| 5 运动反馈与结果展示 | 即时反馈；结果查看与保存提示 | 当前进度、调整提示及真实运动结果 |
| 6 运动记录与同步 | 运动记录；本地保存与记录恢复；结果同步 | 可追溯记录、保存结果及同步状态 |
| 7 联网与使用者管理 | 网络连接与状态提示；平台状态同步与使用者确认 | 连接状态、通信确认及当前儿童 |
| 8 隐私控制与数据管理 | 摄像头使用控制；数据权限与提醒控制 | 可见、可停止的采集和受控数据使用 |

一次运动：查看任务或选择运动 → 确认目标 → 准备 → 倒计时 → 识别计数与反馈 → 完成或提前结束 → 保存结果 → 同步家长端。

本版检查结论：功能名称表达设备行为；目标和约束单独说明；同一业务行为只有一个主要归属，其他模块提供输入或呈现结果。

下面按“一级功能 → 二级功能 → 功能点”展开，使用1.1.1这样的数字编号。具体页面、协议、算法和测试指标留到详细需求阶段。

### 8.3 贯穿全部功能的约束

以下为准入条件，不作为独立功能点计数：儿童原始摄像帧不持久化，不写入记录、日志或缓存，不上传持久化；隐私关闭或状态未知不得采集；低置信度不作确定纠错；提前结束不伪称达标；无广告、儿童充值、陌生人社交或公开身体数据。记录、识别和反馈功能均须满足这些约束。

| 更多运动项目 | 从已有动作池增加经验证的动作 | 与整体PRD七动作范围一起确认 |
| 运动训练建议 | 根据真实记录及审核规则提供受限建议 | 不自由生成儿童运动处方 |
| 个性化成长 | 展示个人进步、长期成长与徽章 | 基础运动星、个人最好成绩是否属于P0，单独确认 |
| 内容与语音陪练 | 用运动相关内容帮助开始和坚持 | 不发展为开放聊天或独立游戏循环 |

P2暂不分配。学校授权任务、独立体态观察、软件升级（OTA）和远程诊断继续保留原需求追踪，本轮范围及优先级待确认。

### 9.2 本轮需要确认的功能问题

| 问题 | 对功能范围的影响 |
|---|---|
| 三动作是本轮演示范围还是产品MVP范围？ | 决定其余四动作放在哪里，不能静默删减原PRD |
| 儿童怎样开始、暂停、恢复和结束？ | 决定基本操作输入；触控、按键或其他方式未定 |
| 高抬腿是一侧一次还是两侧一轮？ | 决定目标及结果计次口径 |
| 多儿童切换、多人入镜怎样处理？ | 决定任务与成绩归属 |
| 基础运动星、个人最好成绩是否纳入P0？ | 决定完成反馈与成长边界 |
| 是否必须支持OTA？ | 决定设备维护是否属于当前交付必需能力 |
| 动作说明能否跳过；中断多久结束？ | 决定开始安全前置与暂停后结束行为 |
| 记录保存多久，撤权和删除如何响应？ | 决定恢复与数据管理边界；儿童原始视频不保存 |

原始儿童摄像帧不持久化；隐私关闭或状态未知不能采集。家长端负责任务创建、权限和查看，设备负责真实运动结果，平台负责传递与统一记录。
