1 User Journey 用户旅程

旅程是基于既有功能的设计输入，不代表已完成用户研究或实机验证。设计机会仅用于提升已有信息的理解，不新增产品能力。

1.1 儿童首次使用旅程

用户目标：在家长协助下了解设备可用状态、完成有效家庭与儿童上下文确认，开始一次运动并理解结果。触发条件：未绑定设备首次启动；恢复出厂后重走此旅程仅在该候选获准后适用。

阶段 / PAGE用户行为与目标用户疑问系统响应 / 关键状态风险设计机会
开机 / PAGE-00或01儿童开机，家长协助；知道是否可用能开始了吗？初始化、检查网络及绑定，路由到首次使用或首页不知道等待原因区分正在初始化与需家长处理
连接与绑定 / PAGE-00家长按确认方案操作，儿童等待连网了吗？绑定成功了吗？未绑定→等待→处理中→有效绑定；失败说明原因把连网或扫码当绑定成功区分连接、处理中、关系已确认；方案TBD
当前儿童确认 / PAGE-00，承载TBD家长确认使用儿童这次运动记给谁？读取有效儿童上下文，不明确则待确认成绩错归属明确当前归属及未确认原因，不引入账号创建
选择运动 / PAGE-01→02或03儿童选择自主目标或家长任务做什么？做多少？展示有效动作、目标、来源；无任务如实说明两入口被误认为两套运动相同动作/目标语言和共用准备入口
准备与开始 / PAGE-04→05理解动作，站好并明确开始为什么不能开始？何时开始？隐私准入、入镜引导、条件满足后倒计时并复核未授权采集、准备不足开练给一个主要可处理原因，说明恢复路径
执行 / PAGE-06运动，必要时暂停或结束算了几次？为什么暂停？可信计数与提示，暂停保留成绩不确定计数、结束压力区分识别状态与已确认进度，保留真实努力
结束 / PAGE-07→01看结果并结束本次体验达标了吗？保存了吗？家长收到了吗？真实结果、保存状态、独立同步状态把提前结束、保存、同步混淆分开表达三种事实，不伪称达标或送达

联网与绑定先后、输入、说明媒体及儿童确认方式TBD；二维码不是默认技术方案。

1.2 日常运动旅程

触发条件：日常开机、查看任务或选择自主运动。目标：以正确儿童归属完成真实运动闭环，理解异常及记录状态。

用户任务页面职责 / 路径关键状态与系统响应设计边界
恢复可用环境初始化→PAGE-01；绑定失效转PAGE-00，儿童待确认承载PAGE-00/08，TBD恢复已保存任务、记录、隐私，不自动续计断网不等于解绑，恢复范围TBD
自主开练PAGE-01→02选支持动作→确认允许目标；标记自主来源不修改家长目标，不独立计数
执行家长任务PAGE-01→03无任务/列表/详情→确认有效任务任务到达不自动采集或开始
完成准备两入口汇合PAGE-04→05目标/归属有效，隐私允许，准备满足，儿童明确开始无效条件阻断，倒计时不计数
运动及恢复PAGE-06；暂停继续回PAGE-04RUNNING/PAUSED，次数可信且保留恢复是否再倒计时TBD，不绕过准入
理解结果PAGE-07→01FINISHED与保存/同步事实分别表达已保存不等于已同步；补传不阻断允许本地运动

1.3 启动规则追溯

首次启动：初始化→检查绑定与网络→未绑定PAGE-00→按评审方案连接/绑定→当前儿童确认→PAGE-01。

日常启动：初始化→恢复已保存任务、记录与隐私状态→按绑定及儿童上下文路由。缺少当前儿童不得错误归属，绑定失效进入引导，断网保持有效关系；恢复范围与具体契约TBD。
