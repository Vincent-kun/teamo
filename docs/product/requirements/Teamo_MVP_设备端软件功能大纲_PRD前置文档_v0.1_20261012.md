## 1. 需求背景

### 1.1 市场背景

本项目切入家庭固定空间中的儿童短时重复运动，核心机会是降低“产生运动意图到实际完成”的阻力，而非增加儿童屏幕停留。当前项目资料把开始难、坚持难、完成结果不可信及家长监督成本高列为主要问题。它们是产品定位依据，尚无本轮独立用户研究支持发生率、规模或提升幅度；相关量化判断均为 TBD。

家长现场监督能提供支持，但也可能要求家长反复提醒、人工计数与确认；是否造成显著负担须访谈验证。视频跟练能提供示范，但仅播放内容无法自动确认儿童是否完成有效动作。通用运动App提供任务和记录，但家庭摆放、启动和跨端确认的摩擦仍需实测。专用常驻设备拟将任务、识别、反馈和保存接成短流程，价值通过开始率、有效完成、结果可信及家长负担验证，不承诺已提升坚持率。

参考材料用途：网关功能大纲v4.0用于学习分层编号、P0/P1/P2及Change Log；网关PRDv3.0用于学习概述、权限、边缘情况和验收表达。两者版本不一致，不能合成同一产品基线。深信服竞品分析仅借鉴定位→能力对比→差异化→风险的方法，不采用未核实的价格、参数和市场结论。附件儿童功能大纲用于比对用户故事、运动流程与安全边界，现行仍以仓库资料为准。

### 1.2 用户群体

| 角色 | 使用环境与行为 | 核心需求 / 管理需求 | 关注指标 |
|---|---|---|---|
| 6–9岁儿童 | 家庭固定空间；理解和启动可能需要成人协助，按提示运动 | 简单入口、可理解提示、温和反馈与随时退出 | 理解度、成人介入、开始与完成情况 |
| 10–12岁儿童 | 执行家庭任务，也可能自主选择目标 | 自主开始、明确进度、可信计数、看见个人努力 | 有效成绩、挫败退出、再次运动 |
| 13–15岁青少年 | 更重视自主和隐私；年龄差异需分别验证 | 克制的角色表达、边界可控、结果专业且可理解 | 自主使用、隐私理解、反馈接受度 |
| 家长管理者 | 通过APP/小程序安排任务和查看结果，非持续现场计数者 | 设置可理解目标、管理授权、查看真实完成及异常 | 目标/实际/状态、未完成原因、保存/同步状态、监督负担 |
| 后台/运营人员（TBD） | 平台诊断与版本支持；具体角色权限未冻结 | 必要设备状态、版本及错误摘要，不获取家庭原始视频 | 可用状态、同步失败、故障恢复；运营看板不属本设备稿承诺 |

年龄段行为为分层验证方向，不是本轮已获得的实测结论。学校是后续授权任务来源，教师端不纳入本稿设备P0实现承诺。

### 1.3 用户痛点

| 当前状态 | 存在问题 / 待验证假设 | 产品机会 |
|---|---|---|
| 家长发出运动要求，儿童需要另找入口和目标 | 开始步骤与反复催促可能阻碍开练 | 接收清晰任务，儿童明确确认后进入准备 |
| 儿童自行数动作或只看跟练内容 | 注意力分散，无法自动确认有效完成 | 依据已验证规则计数，呈现目标和实际 |
| 动作不完整、站位不适合或识别不确定 | 无明确提示可能导致漏计、挫败或误解 | 先提示一个可处理原因，不以低置信度给确定纠错 |
| 中途离开、主动暂停或网络断开 | 已完成努力可能被清零或丢失 | 保留已确认成绩，本地继续与可靠保存 |
| 家长只能问“做完没有” | 难以区分实际完成、提前结束和未同步 | 同一结构化结果连接设备和家长端 |

不以“儿童需要反馈”替代因果分析；上述机会需通过家庭观察、人工真值对照与端到端验证确认。

### 1.4 产品定义

Teamo是一款家庭常驻的儿童运动陪伴机器人，通过视觉动作识别、可信计数、角色化即时反馈与结果同步能力，为6–15岁儿童及其家长解决运动难开始、努力难确认和监督负担较高的问题。

本稿MVP做什么：接收家长任务或进入已有依据的自主运动，明确儿童归属与目标，完成入镜准备、倒计时、开合跳/深蹲起/高抬腿识别计数、基础反馈、暂停恢复、提前结束、结果保存及平台同步；提供必要启动、状态、网络和隐私管理。三动作是本轮指定的拟定范围，规则和实机能力尚待验证。

本稿MVP边界：不承诺额外动作、专业姿态评分、个性化训练处方或独立体态观察。儿童端不提供开放聊天、独立游戏大厅、陌生人社交、公开身体数据或全站排行、广告及儿童充值。原始儿童摄像帧不持久化；家庭视频远程监控不属于产品能力。学校任务、长期成长及OTA等未冻结项目继续追踪，未列P0不等于批准删除旧需求。

## 3. 核心业务流程

### 3.1 运动任务流程

家长端创建任务 → 平台传递 → 设备校验任务与儿童归属 → 本地保存并回执 → 任务展示 → 儿童开始确认 → 隐私检查 → 入镜与站位准备 → 倒计时 → 再次确认可开始 → 运动识别与有效计数 ↔ 实时反馈 → 达标或主动结束 → 停止本轮采集 → 生成并保存结果 → 展示结果与保存状态 → 上传并确认 → 家长端查看。

### 3.2 异常与替代流程

- 自主运动：儿童选择支持动作与目标 → 创建自主来源运动记录 → 共用准备及后续流程，不能伪装为家长任务。
- 无人/不完整入镜/隐私关闭或未知：不进入运动，给出明确处理方式；收到远程任务不自动开摄像头。
- 主动暂停/离画/识别异常：停止新增成绩、保留已确认成绩 → 重新检查准备 → 明确恢复或结束。恢复不延续未完成半周期。
- 提前结束：保存实际成绩与未达标状态；不生成虚假完成或奖励。
- 断网：已缓存且允许执行的任务继续本地运动与保存；新任务未送达不称已接收；结果进入待同步，网络恢复后补传。
- 保存失败：不称已保存；保留可恢复结果并提示重试。重启恢复策略和写入保证 TBD。

### 3.3 数据对象与跨端责任

| 对象 | 必要业务信息 | 规则 |
|---|---|---|
| 任务 | 唯一标识、版本、来源、儿童、动作、目标/单位、有效条件、状态 | 接收、开始、完成、撤销与待同步须区分；启动时目标不得静默变化 |
| 一次运动记录 | 唯一标识、儿童、关联任务或自主来源、动作、目标、实际次数、用时、结束状态、保存/同步状态 | 真实生成，重复补传不重复记录；三动作成绩单位为次数，计次定义 TBD |
| 设备状态 | 可运行状态、隐私/采集状态、网络、最近同步、软件版本 | 未知不伪装正常；只同步必要信息 |

以上为业务对象，不冻结字段名、数据库、API或协议。家长端管理任务/权限/查看，设备维护实际运动事实，平台承接统一结果；跨端责任人与契约版本 TBD。

## 8. 验收标准框架

本节定义未来FR需要的验收维度，不替代详细测试，也不宣称实机通过。每条FR绑定功能编号、前置条件、正常/异常输入、可观察输出、通过条件、指标口径、依赖、Owner及证据。性能数字和测试集须评审后冻结，不编造准确率。

| 核心模块 | 功能验收 | 性能验收（阈值TBD） | 异常验收 |
|---|---|---|---|
| DS-01 基础 | 启动后状态真实、恢复可操作 | 启动/恢复耗时、连续运行稳定性 | 启动失败、重启、中断恢复不造完成 |
| DS-02 交互 | 任务、目标、状态与操作可理解 | 三年龄段理解度、显示可读性、响应耗时 | 无任务、输入失败、提示冲突可返回 |
| DS-03 任务 | 接收→准备→倒计时→执行→结束连贯 | 接收确认与准备成功耗时 | 无效/撤销/重复任务、离画、主动结束 |
| DS-04 识别 | 三动作按规则累计完整有效周期 | 人工真值对照的误计/漏计、反馈延迟；样本分层TBD | 半动作、遮挡、低置信度、多人不误分配成绩 |
| DS-05 反馈 | 次数与记录一致，正向提示及真实结果 | 可读/可听、提示频率与打扰率 | 不确定时不作确定纠错；未达标不称完成 |
| DS-06 数据 | 唯一记录、可靠保存与确认补传 | 保存/同步耗时、容量、恢复成功率 | 断网、写失败、重复上传与冲突不重复结果/奖励 |
| DS-07 通信 | 真正接收与平台回执一致，归属明确 | 联网、业务确认、重连耗时 | 断网不阻断允许的本地任务；未送达不称接收 |
| DS-08 安全 | 隐私守卫、状态透明、不持久化原始帧 | 停止采集与撤权响应耗时 | 关闭/未知不采集；删除请求和离线授权边界可验证 |

证据仅保存必要结构化记录；算法评测素材如另行获取，须独立授权、隔离治理与另定留存，不得借测试放宽产品视频不持久化边界。指标同时看开始、完成、恢复、可信结果与家长理解，不能仅用屏幕停留或活跃奖励评价。

FR展开入口：沿用10/10设备需求基线FR-DEVICE-001、FR-TASK-001、FR-SPORT-001–007、FR-DEVICE-002等；本文DS编号是功能范围号，不能取代FR。新增安全或跨端项先映射既有需求，再决定是否新增FR。详细功能需求写行为和输出；技术需求另列运行环境、协议、资源、性能约束与实现验证，互相引用。
