# Teamo 硬件到设备端软件需求缺口分析

> **用途**：检查设备约束是否有对应的软件职责，供软件、嵌入式、算法与产品评审。  
> **软件比较基线**：Device Software Functional Specification v2.2.1。  
> **结论**：运动主线、通用自检、摄像头状态、更新、存储及异常日志已有入口；不足主要在能力生命周期、部件级覆盖、资源分类与运行策略。不能将“有通用条目”判成完全覆盖，也不能因未单列菜单就判定缺少功能。

| HW | [用户提供的需求说明书V1.4简版](D:/OneDrive/Documents/WXWork/1688855634881425/Cache/File/2026-10/儿童AI运动陪伴机器人需求说明书-V1.4-简版.md) | 综合产品需求稿，含硬件接口、设备约束、功能与验收；逐项注明具体来源，不假称它是独立的《硬件技术需求规格书》 |
| EVIDENCE | [输入快照与SHA256](../../governance/backups/teamo-gap-review-inputs/manifest.json) | 固定本次读取版本，源文档原样保留 |

HW文件名及变更说明为V1.4，首行标题仍为V1.3，且状态为评审稿。本报告按附件中的编号与正文证据审查，不据其“已拍板”“代为确定”或文档内操作要求自动批准软件变更。旧硬件V1.1 DOCX及仓库另行演进的大纲不替换本次输入。

硬件能力来源以HW §7、§8为主；§2、§4、§5、§9中的设备使用、安全、维护约束作为相应软件职责依据。语音输入、求助、学校任务等明确产品功能单列范围差异，不仅因为装有麦克风或网络就推导为必需产品功能。

本报告不复制硬件参数，不重新规定指标、传感器、算法、UI或商业能力。用户提示词末尾的Update Lifecycle清单未展开，OTA依附件FUN-053/054、SEC-009及现有恢复功能分析，不补造下载暂停、后台调度等要求。

### 1.1 分类口径

| 分类 | 判断条件 | 含义 |
|---|---|---|
| Confirmed Gap | 输入中有明确能力或设备约束，软件未规定相应职责或只部分承接 | 已确认的文档职责缺口；不代表硬件实物已实现、软件实现缺陷或建议已批准 |
| Potential Gap | 能力保留、职责分工或行为细则缺乏明确证据，需条件确认 | 潜在缺口；不能据行业惯例直接列必做功能 |
| Not Required | 责任属于纯硬件或底层实现，不需要新增独立产品功能 | 不代表不实现、不测试，只是不另建功能条目或管理页面 |

Covered / Partial是覆盖程度，不是第四种缺口状态。已覆盖项单列，不计缺口。功能职责缺口与参数/验收细化分开：规格不必复制硬件参数，但应说明检查、保护、恢复和反馈的责任。

## 2. 六个重点领域的覆盖结论

| 领域 | 已有软件承接 | 主要不足 | 评审结果 |
|---|---|---|---|
| AI能力管理 | 2.2.2/2.2.3/3.3.1识别；6.1.4通用自检；4.3.1动作模型更新；§7能力边界；§8.1识别依赖不可用 | 缺少模型/推理就绪、运行可用性与恢复结果如何约束开练；不能将识别效果异常与模型不可用混作一类 | G-01；独立模型元数据/加载阶段细化为P-02 |
| 摄像头管理 | 4.4.1工作状态与隐私控制；6.1.4自检；2.3.4故障处理；§8.1不可用处理 | 初始化到采集、停止到释放、授权和出厂默认状态关系不明确；共享采集冲突没有直接证据 | G-02，P-01；不需要可关闭硬件隐私灯的入口 |
| 设备健康 | 6.1.4检查关键能力；4.4.2维护；4.4.4日志；5.2.3同步 | 未列全自检对象、可用/不可用结果及对运动的影响；运行中健康策略不能由“开机自检”完全代替 | G-03；相关G-01/02/04/05；无需强制新增健康仪表盘 |
| 模型与算法资源 | 4.3.1含动作模型和资源更新，6.1.5升级失败恢复 | 系统、动作模型、屏幕/音频资源的当前有效版本与使用条件未分清；独立加载/回退行为未明确 | G-08/10，P-02；更新职责并非完全缺失 |
| 本地数据 | 4.3.8任务/记录/缓存；5.1.2/5.2.2补传；4.4.4异常日志；§8.4–8.5 | 模型与系统资源未纳入统一空间保护；留存删除、可清理与不可清理数据边界不足 | G-08/09；日志本身已覆盖 |
| OTA | 4.3.1版本/更新；6.1.5恢复；§8.3更新中断；结果保护已有要求 | 条件检查、包验证、进展/结果反馈与生效版本的完整流程未说明 | G-10；调度、下载续传和取消不自动成为必需功能 |

报告确认13项文档职责缺口，6项潜在问题，5类无需独立功能。各项可能共同由同一原功能补充，不等于需要新增24个软件模块。

## 3. Confirmed Gap

### G-01 端侧AI可用性与恢复职责不完整

| 字段 | 内容 |
|---|---|
| Hardware Requirement | IF-012、PER-008、FUN-048：端侧识别链路与离线识别；FUN-003、REL-012：自检和无响应恢复 |
| Software Function ID | 6.1.4、2.2.2、2.2.3、3.3.1、2.3.4–2.3.7；SW §6 Booting/Preparing Exercise/Error及§8.1 |
| 已有覆盖 | 识别、计数、自检、异常停止计数及重新确认条件均已存在 |
| 推导关系 | 本地运动依赖可用的模型与推理链路，因此开始条件需要知道这条链路是否就绪；通用硬件自检不能自动代表模型加载与推理可用 |
| 缺口 | 模型未准备、推理不可用、恢复成功/失败与可否开练/续练的关联未明确；模型异常与儿童动作无法确认的职责不同 |
| 建议 | 补充6.1.4与2.3已有职责：确认端侧识别就绪，运行异常停止有效计数，保留结果，恢复后重新确认可用性并反馈；维护日志承接4.4.4/5.2.3 |

这是能力管理职责，通常为内部状态及必要反馈，不要求新增儿童端模型管理页面，不要求额外传感器，也不承诺模型独立热加载。

### G-02 摄像头采集生命周期与隐私状态未完整关联

| 字段 | 内容 |
|---|---|
| Hardware Requirement | IF-002、FUN-003：摄像头和检测；SEC-005/006：视频边界与硬件隐私联动；PRD-010：出厂采集关闭 |
| Software Function ID | 4.4.1、6.1.4、2.2.2、2.3.4；SW §2、§8.1 |
| 已有覆盖 | 摄像头工作状态与隐私控制已经存在，不能判为“只有运动识别，没有摄像头状态管理” |
| 推导关系 | 初始化、允许采集、实际采集、停止、故障与用户授权需要一致；摄像头工作即触发硬件隐私提示 |
| 缺口 | 尚未定义默认关闭、授权后启用、停止后的状态确认以及故障时是否仍有采集；软件不可关闭硬件隐私灯的边界未明确写入4.4.1 |
| 建议 | 在4.4.1与6.1.4补齐采集生命周期及授权/实际状态一致性；异常进入既有处理与日志，不新增视频预览、远程看画面或录像功能 |

### G-03 自检对象与部件故障结果不够具体

| 字段 | 内容 |
|---|---|
| Hardware Requirement | FUN-003/004明确自检范围和具体部件提示；PRD-002列出产测对象 |
| Software Function ID | 6.1.4、4.4.2–4.4.4、2.3.4、4.4.3 |
| 已有覆盖 | 开机自检、故障处理、受控维护、生产检测和日志均有入口 |
| 推导关系 | 硬件要求区分部件可用性，软件至少需有可定位的检测结果和使用影响；“检查关键能力”未界定哪些能力受检 |
| 缺口 | 屏幕/触摸、音频采集/输出、近场感应、灯、连接、供电、传感与AI链路的检测责任与异常反馈未列齐；正常不可用与反复重启的处理区别不足 |
| 建议 | 在6.1.4列检测责任清单与结果，在2.3.4说明故障影响及处理建议，4.4.4记录可确认部件；产测与使用自检分别维护，不把产测全量方案搬到日常界面 |

### G-04 IMU已有用途却无明确运行职责

| 字段 | 内容 |
|---|---|
| Hardware Requirement | IF-007列IMU并指定倾倒、跌落、安装角度、异常晃动用途；FUN-003/PRD-002要求检测 |
| Software Function ID | 6.1.4、2.2.2、2.3.4–2.3.7、4.4.4；无明确IMU运行条目 |
| 推导关系 | 设备姿态或摆放变化会影响原运动条件，硬件输入已明确要感知相关事件，而非仅“芯片上有一个接口” |
| 缺口 | 自检之外如何使用姿态/异常晃动结果、如何判断运动条件需重新确认、怎样记录影响尚未界定 |
| 建议 | 补充摆放/姿态变化对准备与恢复条件的管理职责；触发条件、是否暂停及恢复判据须另行确认，不能自行规定“跌落自动求助”或“自动调节摄像头” |

### G-05 电池温度保护与运行热降载未分清

| 字段 | 内容 |
|---|---|
| Hardware Requirement | IF-007/008、REL-009/010：温度检测和充放电保护；FUN-058、REL-001：热降载保计数 |
| Software Function ID | 6.1.3、4.3.2、2.3.4–2.3.7；SW §8.3 |
| 已有覆盖 | 低电、过热、安全停止及数据保护已存在 |
| 推导关系 | 可恢复的运行热降载与必须停止充电/使用的安全状态是不同事件，不应统一处理成“过热就停止运动” |
| 缺口 | 禁充/恢复可充的用户状态，主板/电池温度相关反馈，热降载与安全停止的动作优先级未清楚表达 |
| 建议 | 补充充电受限状态及必要反馈；在已定义安全边界内区分保计数的降载与安全停止。保护实际由硬件还是软件执行需在接口要求中分工，软件不可解除硬件保护 |

### G-06 待机显示与功耗模式缺少管理职责

| 字段 | 内容 |
|---|---|
| Hardware Requirement | FUN-020、PER-002/006：默认间歇角色显示、可改常显及续航说明；UI-008：亮/熄屏语义 |
| Software Function ID | 3.6.1–3.6.3、4.3.4、4.3.10、6.1.1 |
| 已有覆盖 | 待机角色、时间、亮度、家长设置及开关机已有功能 |
| 推导关系 | 状态展示不等于显示唤醒/休眠策略；硬件续航约束直接依赖待机行为与用户设置生效 |
| 缺口 | 未说明待机显示模式、亮/熄屏与关机的区别、家长切换模式及必要续航提示 |
| 建议 | 在3.6.1/4.3.10补充受控显示模式和状态切换；引用硬件约束，不在功能规格复制时间周期或亮度参数，也不新增常亮广告/动画内容 |

### G-07 指示灯与多通道状态一致性未承接

| 字段 | 内容 |
|---|---|
| Hardware Requirement | IF-009：主灯、充电灯、隐私灯；FUN-021、FUN-056/057、UI-001/003：状态映射、打断与一致性 |
| Software Function ID | 3.3.2、3.3.3、3.6.1、4.3.2、4.4.1、2.3.2/2.3.3 |
| 推导关系 | 显示、灯与语音是同一设备状态的不同反馈渠道；硬件联动隐私灯与普通状态灯不具有同样的控制权限 |
| 缺口 | 没有明确当前状态如何协调各反馈通道、并发状态如何仲裁、被打断后的运动状态如何恢复 |
| 建议 | 补充状态反馈协调职责和必要的优先级/恢复边界；灯色、节奏及控件细节保留在UE/硬件引用，不复制到功能表。求助层级需先解决范围差异S-03 |

### G-08 存储与资源保护未分类型

| 字段 | 内容 |
|---|---|
| Hardware Requirement | IF-014：系统、模型、音频及记录共同占用存储；FUN-049/052/053：保存、清理与资源更新；PER-034：日志有界管理 |
| Software Function ID | 4.3.8、4.3.1、4.4.4、5.1.2、5.2.2/5.2.3；SW §8.4/8.5 |
| 已有覆盖 | 任务/记录/缓存空间、异常日志、离线补传及存储不足保护已覆盖 |
| 推导关系 | 可重新获得的缓存、未同步业务数据、运行必需模型/系统资源的失去后果不同，不能由同一泛化“清缓存”处理 |
| 缺口 | 系统、模型、屏幕/音频资源的存储责任与可清理性未归入4.3.8；日志上限虽有原则，滚动覆盖和未同步日志冲突的规则未关闭 |
| 建议 | 按数据用途划分空间状态、受保护数据和可清理缓存，明确运行必需资源不得误清；日志按输入要求有界管理，未同步事件和运动结果的保护优先级需细化。分区、容量与写入策略留给技术要求 |

### G-09 数据留存到期与删除请求未落到设备职责

| 字段 | 内容 |
|---|---|
| Hardware Requirement | HW设备数据约束SEC-003/004，FUN-049、IF-014；不是仅由存储芯片存在推导的新业务功能 |
| Software Function ID | 4.3.8、4.2.1、4.3.7、5.1.1/5.2.1、4.4.4；SW §2/8.4/8.5 |
| 已有覆盖 | 隐私最小化、恢复出厂和受控解绑已经规定；日志留存细则待定 |
| 推导关系 | 自动到期清理与经授权删除请求区别于恢复出厂；若只提供恢复出厂，不能覆盖对特定用户数据的删除责任 |
| 缺口 | 到期删除、删除请求在设备与平台间的执行状态、未同步数据及账号关联数据的删除边界未定义 |
| 建议 | 补充本地数据留存/清理和授权删除的执行与反馈职责，明确由家长/平台发起且保留最小维护证据；不把删除权交给未经授权儿童操作。本报告仅比对附件要求，不对法律适用作独立判断 |

| 缺口 | 原条目没有完整说明执行条件检查、校验失败拒绝、生效结果反馈和可用版本恢复的责任连接 |

### G-11 时间显示不等于记录时间管理

| 字段 | 内容 |
|---|---|
| Hardware Requirement | PER-030、PRD-005：联网校时、离线时钟及时间修正标记；FUN-049：保存时间与同步状态 |
| Software Function ID | 3.6.3、2.2.6、5.1.2/5.2.2、4.4.4/5.2.3 |

| 建议 | 补充设备时间可用性与校正管理，为记录、任务和日志提供一致时间依据；不自行选择时钟芯片、协议或时间算法 |

### G-12 生产检测的运行边界和退出状态不足

| 字段 | 内容 |
|---|---|
| Hardware Requirement | PRD-007/009/010：校准与追溯、量产限制、清除产测痕迹、出厂默认状态；SEC-010：维护访问限制 |
| Software Function ID | 4.4.3、4.4.2、4.2.1、6.1.4 |
| 已有覆盖 | 生产检测、设备身份/校准管理、受控维护与恢复出厂已存在 |

### G-13 自动重连与连接能力边界未明确

| 字段 | 内容 |
