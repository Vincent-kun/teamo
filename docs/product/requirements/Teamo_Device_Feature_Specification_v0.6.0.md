## 产品定位

面向6–15岁儿童家庭运动。设备负责运动当下的交互、视觉识别、可信计数、角色反馈、本地记录与同步；家长管理任务、授权和结果；平台维护有效身份关系与统一服务。陪伴服务运动，不转为开放聊天或家庭视频监控。

## 功能范围

MVP演示已确定仅开合跳、深蹲起、高抬腿。七动作整体产品追踪保留，不删除其余动作。本文保持47项原P0 / Pending Review、20项已有细化功能优先级TBD、2项历史停用追溯；原P1后续候选也保持。范围状态与实现方案分开，功能列入正文不等于全部批准。

绑定、二维码、儿童切换、解绑等统一放在对应功能模块，不再单独藏在“补充提议”区。未获确认的功能在业务规则中明确范围/优先级待评审；二维码、输入方式、授权、目标范围和有效规则等待确认内容不擅自确定。

编号用于定位功能和评审讨论，沿用原号。完整追踪见附录A；原问题清单与变更记录分别见独立治理日志。本文不定义数据库字段、工程状态枚举、测试索引或具体性能阈值。

## 功能详细说明


## 1 设备启动与运行管理

### 1.1 启动与运行

#### 1.1.1 开机与初始化

**功能目标**

让家庭知道设备能否开始使用。

**使用场景**

家庭在开机与初始化环节，需要获得明确、真实且可理解的操作结果。

**功能描述**

启动软件并验证必要运行条件，进入可用或明确异常状态。

**用户流程**

```text
设备上电或重启；隐私状态未明不得采集 → 开机与初始化 → 可用状态或已确认启动异常
```

**业务规则**

- 优先级：P0；状态：待评审（Pending Review）。
- 行为归属：设备启动与运行；具体人员待指定。
- 前置：设备上电或重启；隐私状态未明不得采集。
- 待确认：启动时长待确认。

**异常处理**

启动/必要服务不可用，按设备故障处理处理；范围与时限TBD。

**验收标准**

验证必要运行条件后进入可用或明确异常状态；启动时长TBD。 正式量化方法和实际测试用例仍待建立。

#### 1.1.2 恢复启动状态

**功能目标**

重启后回到正确状态，不自动续计或伪称完成。

**使用场景**

家庭在恢复启动状态环节，需要获得明确、真实且可理解的操作结果。

**功能描述**

根据已保存记录恢复恢复的任务、结果和隐私状态，输出待机、恢复提示或异常；不重复负责读取记录。

**用户流程**

```text
启动后已取得恢复结果；恢复状态TBD → 恢复启动状态 → 待机、恢复提示或异常去向
```

**业务规则**

- 优先级：P0；状态：待评审（Pending Review）。
- 行为归属：设备启动与运行；具体人员待指定。
- 前置：启动后已取得恢复结果；恢复状态TBD。
- 待确认：恢复进入哪个状态待确认。

**异常处理**

无法确认的进度不补造，具体不可恢复处理TBD。

**验收标准**

只恢复可确认事实，不自动续计、不将未完成会话表示为完成。 正式量化方法和实际测试用例仍待建立。

### 1.2 状态与异常

#### 1.2.1 设备运行状态管理

**功能目标**

状态一致，避免同一操作在不同入口产生冲突。

**使用场景**

家庭在设备运行状态管理环节，需要获得明确、真实且可理解的操作结果。

**功能描述**

统一维护当前运行状态和允许的操作；运动过程的暂停、恢复与结束由运动任务与执行模块定义。

**用户流程**

```text
相应状态事实可用；各守卫由所属功能维护 → 设备运行状态管理 → 当前可执行操作和一致的业务状态
```

**业务规则**

- 优先级：P0；状态：待评审（Pending Review）。
- 行为归属：设备启动与运行；具体人员待指定。
- 前置：相应状态事实可用；各守卫由所属功能维护。
- 待确认：—。

**异常处理**

故障、权限或识别异常按所属分支，恢复契约TBD。

**验收标准**

同一业务操作在不同入口遵循相同状态约束；执行、保存、同步分别表达。 正式量化方法和实际测试用例仍待建立。

**验收标准**

显示真实采集状态；运动退出或授权撤销后停止采集，不能通过远程任务绕过本地关闭状态。

**用户流程**

```text
状态可确认；提示方式与撤权响应TBD → 摄像头状态提示与关闭 → 摄像头状态提示及停止采集事实
```

**业务规则**

- 优先级：P0；状态：待评审（Pending Review）。
- 行为归属：设备隐私与权限；具体人员待指定。
- 前置：状态可确认；提示方式与撤权响应TBD。
- 待确认：状态提示方式与撤权响应待确认。

**异常处理**

撤权/关闭或状态未知先阻断；响应时限TBD。

**验收标准**

退出/结束或撤权停止采集；显示真实状态，不由远程请求强制开启。 正式量化方法和实际测试用例仍待建立。

#### 8.1.3 设置本地摄像头使用状态

## 业务状态模型

一次运动：目标与归属确认→准备→倒计时→运动→真实结束→保存→结果展示。暂停保留已确认努力，继续前重新检查隐私和准备；是否再次倒计时待确认。准备、倒计时与暂停不累计成绩。

执行、保存和同步是三个维度：运动结束不等于已保存，已保存不等于平台收到；可同时表达“提前结束 / 已保存 / 待同步”。上传/补传可在后台进行，不阻断允许的本地运动。首次绑定、儿童身份、网络及隐私各有独立事实，不能强行套成单一运动状态。

原始摄像帧不持久化，不进入记录、日志或缓存，不上传持久化。未授权、关闭、撤权或本地状态未知禁止采集；退出/结束停止采集。低置信度不作确定纠错，提前结束不伪称达标。不支持广告、儿童充值、陌生人社交、公开身体数据、医疗或视频监控。

## 跨端职责

| 能力 | 设备端 | APP / 小程序 | 平台 |
|---|---|---|---|
| 创建任务 | 不创建家长任务，自主目标来源另记 | 家长填写并提交目标 | 校验权限、保存并投递 |
| 任务接收 | 3.1检查，6.2保存后回执 | 显示真实接收状态 | 投递及记录回执，不等同发送成功 |
| 任务执行 | 运动任务与执行模块维护运动过程 | 家长查看必要状态 | 传递状态，不代设备递增次数 |
| 动作识别 | 动作识别与计数模块输出有效事件及次数 | 不独立生成成绩 | 不生成虚假成绩；部署位置待确认，不放宽离线/隐私 |
| 结果生成 | 6.1生成真实结果及唯一标识 | 不修改实际成绩 | 接收校验及统一存储 |
| 结果查看 | 5.2呈现设备简要结果 | 呈现家长授权记录 | 提供统一结果服务，不承诺新查看界面 |
| 账号绑定 | 绑定状态与当前儿童确认读取执行绑定和当前儿童上下文 | 家长发起绑定/切换 | 校验身份、维护关系 |
| 本地保存恢复 | 6.2保存并恢复必要记录 | 展示平台确认结果 | 保存已收到记录，不伪造未送达内容 |
| 同步管理 | 6.3补传并按业务确认更新状态 | 展示已确认结果 | 业务接收确认、按记录标识去重 |
| 设备状态同步 | 设备状态同步提供必要状态及版本 | 查看允许状态 | 传递/保存必要状态 |
| 授权与采集控制 | 8.1执行有效授权及本地阻断 | 家长管理授权，不远程强制采集 | 维护授权关系、传递变化 |
| 删除/解除绑定 | 处理设备数据权限与删除请求决定本地权限清理行为，6.2执行本地数据处置 | 家长发起、查看处理状态 | 校验权限、协调云端处置与设备确认 |
| 版本与故障信息 | 提供版本及必要摘要 | 展示位置与操作入口待确认 | 仅接收必要信息，契约待确认 |

算法提供审核规则与有效事件，硬件提供可用输入输出及真实隐私状态；具体方案、部署位置和人员待确认。设备不创建家长任务或管理云端账号关系，不擅自改变家长目标。
