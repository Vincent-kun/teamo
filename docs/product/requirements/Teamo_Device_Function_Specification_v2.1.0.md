## 1. Product Definition

### 1.1 产品定位

面向6–15岁儿童家庭的常驻AI运动陪伴机器人，以明确任务、视觉动作识别、可信结果与适度角色陪伴帮助儿童更容易开始、独立完成并持续运动。

### 1.2 用户对象

| 对象 | 核心场景 | 使用边界 |
|---|---|---|
| 6–15岁儿童 | 执行任务、自主运动、理解反馈和个人进步 | 6–9、10–12、13–15岁理解与自主性分别验证 |
| 家长管理者 | 授权、安排、设置边界与理解真实结果 | 不要求持续承担人工计数或远程监控 |
| 学校影响者 | 经家长授权下发任务、接收必要结果 | 学校任务范围Pending Review，不默认拥有家庭数据 |

### 1.3 核心价值

| 价值 | 功能承诺 |
|---|---|
| 容易开始 | 获授权任务和快速运动提供明确启动目标 |
| 可信完成 | 有效计数、异常恢复与结果保护尊重已完成努力 |
| 愿意再运动 | 适度鼓励、个人进步与真实运动激励服务运动主线 |
| 家长少监督 | 同步真实结构化结果与必要异常，不发展远程监控 |

### 1.4 产品闭环

设备陪伴 → 运动任务 → AI识别 → 实时反馈 → 运动结果 → 成长激励 → 家长同步。

成长增强未获批准时，必要鼓励、结果与家长同步仍应完整提供。

## 2. Product Boundary

| 责任主体 | 负责 | 不负责 / 限制 |
|---|---|---|
| 设备端 | 执行获授权安排与自主运动；准备判断、识别、计数、反馈；结果保护、同步；设置应用、状态与维护 | 家庭权限管理、支付、开放聊天、自由生成运动处方、公开社交、医疗判断、视频监控及回放 |
| 家长端 | 授权与绑定管理、确认安排、设置提醒和免打扰、查看与理解结果 | 不替代设备实时计数；不默认远程开启家庭摄像头 |
| 云端 | 获授权任务、状态、结构化结果与资源协作 | 不绕过授权，不默认接收原始家庭视频，不据竞品推定新增LLM能力 |

| 边界 | 规格要求 |
|---|---|
| 隐私 | 数据最小化；原始视频不上传、不持久化；提醒不保存视频或截图 |
| 成长与商业 | 不以充值、登录或在线时长替代运动，不在儿童端承接成交或公开竞技排名 |
| 硬件 | 竞品屏幕、摄像头、触控、配件及LLM规格均不构成Teamo硬件承诺 |
| 成人健身指标 | 不迁移负重、KG容量、组数作为儿童成长指标 |
| 日常陪伴 | 受家长授权和免打扰约束，陪伴不形成脱离运动的开放聊天主线 |

## 3. Software Capability Architecture

目的：定义软件能力责任域。Capability Model ≠ Information Architecture ≠ Menu Structure。功能分组与ID在第4章维护，IA与页面结构由后续UE设计确定。

```text
Teamo Device Software Capability
├── Companion State（陪伴状态）
├── Exercise（运动执行）
├── AI Recognition（AI识别）
├── Growth Feedback（成长反馈）
├── Daily Companion（日常陪伴）
├── Device Management（设备管理）
└── Cloud Sync（云端同步）
```

| 架构模块 | 软件责任 | 对应原功能ID/分组 |
|---|---|---|
| Companion State | 表达可使用、运动中、暂停、异常及陪伴状态 | 3.3.3、3.6；引用4.3.2/4.3.3/4.3.6/4.4.1/6.1状态，不重复创建功能 |
| Exercise | 任务、自主运动、目标、开始、中断恢复及结果 | 2.1–2.5；2.2.2/2.2.9/2.2.3/2.3.1调用AI识别责任 |
| AI Recognition | 判断入镜、识别就绪、支持动作有效性、计数及识别中断 | 2.2.2/2.2.9/2.2.3/2.3.1/3.3.1；3.3.2承接状态提示语音，不包含动作教学/纠正或生成式AI |
| Growth Feedback | 真实运动对应星星、个人进步、成就与候选宠物成长 | 3.1–3.2、3.3.3；3.1.3排行为P2，具体范围Pending Review |
| Daily Companion | 授权提醒、免打扰、后续装扮互动与专注计时 | 3.4–3.5；体态检测能力仍需验证 |
| Device Management | 绑定、网络、供电、状态、隐私、维护与更新 | 1.1、4.1–4.4、6.1 |
| Cloud Sync | 获授权安排、结构化结果及异常日志同步、离线保存和补传 | 5.1–5.2、2.2.7/2.5.2/3.4.2/3.5.3/4.3.10 |

跨域引用表示协作，不重复创建功能。Companion State是能力域，不是新增一级菜单。

## 5. MVP Scope

目的：以核心运动、陪伴状态和必要运行支撑确定首发职责。用户本次确认的优先级已执行；学校和装扮明确非P0，按P1增强归类，具体后续排期未冻结。整份文档仍为Review。

### 5.1 MVP Core Loop

```text
设备启动 → 确认设备与儿童绑定 → 陪伴状态 / 选择运动或家庭任务
→ 运动准备 → 识别就绪确认 → AI识别 → 动作计数 → 状态提示语音与实时反馈
→ 运动结果 → 同步家长（离线先保存，联网后补传）
```

儿童绑定为归属前置条件，不要求每次重绑。识别就绪与准备条件未满足不得开始有效计数；暂停可恢复，主动结束保护真实结果。异常日志贯穿运行与运动过程，联网同步平台，不作为运动结果或成长奖励。

## 6. State Model

目的：统一设备运行状态与转换条件。模型统一既有运行职责与本次P0陪伴状态，不规定页面流程或实现架构。

```text
Power Off → Booting → Idle → Preparing Exercise → Exercise Running
                            ↑          ↑               ↕
                            │          └──────────── Paused
                            └────── Completed ←────────┘

Booting / Preparing Exercise / Exercise Running / Paused
    → Error → 重新判断条件后返回Idle或Preparing Exercise
任一供电状态 → 受控关闭或断电 → Power Off
```

| State | Description | Trigger | Exit Condition |
|---|---|---|---|
| Power Off | 设备未运行，不进行识别或同步 | 关闭或断电 | 启动条件具备且发起启动，进入Booting |
| Booting | 初始化并检查关键能力，确认记录与设备状态 | 开机或重启 | 自检通过进入Idle；影响使用的故障进入Error；关机进入Power Off |
| Idle | 可接收安排或发起运动；未绑定时仅进行获授权的准备与绑定 | 启动完成、结果确认或正常退出 | 归属与目标明确后进入Preparing Exercise；必要故障进入Error |
| Preparing Exercise | 确认当前儿童、目标、识别就绪（2.2.9）与有效运动条件，提供准备提示 | 选择运动或任务 | 识别就绪且条件满足后开始并进入Exercise Running；取消回Idle；故障进入Error |
| Exercise Running | 判断有效动作、计数并提供实时反馈 | 准备条件满足且开始 | 主动暂停或可恢复识别中断进入Paused；目标达成或主动结束进入Completed；阻断故障进入Error |
| Paused | 停止新增运动计数，保留已确认进度 | 主动暂停、离场或可恢复条件不足 | 续练先回Preparing Exercise重新确认条件；主动结束进入Completed；阻断故障进入Error |
| Completed | 本次运动已经结束，区分完成、未完成与中断结果，保存并安排同步 | 目标完成或用户结束 | 结束确认后回Idle；执行下一项目回Preparing Exercise；同步失败保留结果而非强制进入Error |
| Error | 关键条件不满足或故障阻断使用，保护可确认结果并提示恢复 | 自检、识别依赖、供电或存储等阻断故障 | 原因解除且条件确认后回Idle或Preparing Exercise；无法恢复则受控关闭或结束记录 |

### 6.1 能力状态（部件条件输入）

设备整机状态以下列能力状态为判断条件。能力状态是状态机的条件输入，不是新增菜单或管理页面；“整机处于Idle”不代表所有能力可用。

| 能力状态 | 就绪口径（承接功能） | 对设备状态的影响 |
|---|---|---|
| Camera | 摄像头可正常采集（4.4.1） | 未就绪时不进入有效识别；运行中异常按2.3处理 |
| AI | 识别资源加载完成、识别环境可用（2.2.9、6.1.4） | 未就绪不开始计数，运行中异常暂停新增计数；恢复后重新确认 |
| Storage | 存在可写空间且系统与识别资源完整（4.3.8） | 不足时保护结果并提示；无法保护新结果时不继续积累无法记录的运动 |

Completed是本次运动结束态，不等于达标。Error是异常分支，不是正常完成后的必经状态。网络与同步状态可与运动状态并存，单纯断网不必停止可离线执行的运动。能力状态的就绪阈值、检测时机与重试条件，及既有状态与时间阈值、自动暂停条件的细则仍待PRD和验证确定。

## 8. Exception Handling

目的：为运动可信性与恢复建立统一响应。以下为既有异常功能的职责展开；具体阈值、可自动区分的原因、恢复时限及验收方法待后续确定。不得在不能确认原因时编造故障诊断。

异常发生与恢复时由4.4.4记录必要事件，由5.2.3联网同步平台；未确认的原因记录为“原因未确认”，不把推测写成诊断结论。断电前无法写入的片段不能事后补造。

### 8.1 Recognition Failure

| Scenario | Device Response | User Guidance |
|---|---|---|
| 儿童不在有效区域 | 关联2.2.2、2.3.1–2.3.3；准备时不开始计数，运动中暂停新增计数并保留进度 | 回到可运动区域，条件重新确认后续练 |
| 距离异常 / 入镜不完整 | 不把不可确认动作计入结果；无法确认具体原因时给出通用条件提示 | 调整站位并重新确认；不输出未验证距离数值 |
| 光线不足或可见性受影响 | 当识别结果不可靠时停止新增有效计数；光线原因自动诊断属于AI-C-001候选 | 检查环境可见性，改善后重试或结束 |
| 身体被遮挡 | 保留已确认结果并提供识别条件提示；不保证能自动准确区分遮挡原因 | 清理运动区域，重新确认后续练 |
| 动作无法确认 / 不支持动作 | 不计为有效完成，不宣称专业纠错；关联2.1.3、3.3.1 | 按已支持动作重试，可暂停或结束 |
| 多人入镜且归属无法可靠确认 | 不推断儿童身份，不产生无法确认归属的新记录；由2.3处理中断 | 确认当前儿童和运动环境后重试 |
| 识别依赖不可用 | 关联2.2.9、2.3.4–2.3.7、6.1.4；开始前未就绪不开始计数，运行中阻断有效计数，保护可确认进度，必要时进入Error | 查看必要故障提示，恢复后重新确认就绪，再重新准备或结束 |

### 8.2 Network Failure

| Scenario | Device Response | User Guidance |
|---|---|---|
| 网络断开 | 关联4.1.3–4.1.4、5.1.2、5.2.2；设备先自动尝试恢复连接，多次失败后引导重新配网；条件满足时继续可离线运动，保存必要结构化结果 | 可继续可用运动；联网后补传，在线专属任务暂不可用 |
| 同步超时 / 失败 | 保留本地结果及未同步状态，不伪称成功、不重复新建结果 | 检查连接；明确结果已保存与待同步状态 |
| 新任务或设置未收到 | 反馈接收和生效状态，不将未确认安排视为已执行 | 检查家长端安排与设备状态 |
| 联网补传重复 | 依据5.1.2/5.2.2保持结果唯一性，不重复打卡或奖励 | 说明同步结果，无需重复运动或手动造记录 |

### 8.3 Power Failure

| Scenario | Device Response | User Guidance |
|---|---|---|
| 低电量 | 关联4.3.2、6.1.3；告知使用风险，保护结果 | 按设备提示补充供电或结束运动 |
| 电量不足 / 过热 | 在可执行范围保存进度；温度在可运行范围内时降低运行强度、保持计数可信（热降载）；达到安全边界时停止不安全使用；充电受限时告知用户并提示恢复；不保证所有突然断电均零丢失 | 暂停使用，恢复安全条件后重新确认 |
| 突然断电 | 重启后只恢复已可靠保存的数据，未保存片段不推算为有效动作 | 告知可确认结果及不能恢复部分，选择恢复或重新开始 |
| 供电切换 | 6.1.2原P0提案保留，按已确认硬件条件保护状态；异常时由2.3恢复 | 确认供电状态；不承诺未确认双供电能力 |
| 更新中断 / 重启失败 | 关联6.1.5，执行恢复并保护已保存运动记录 | 恢复可用后再开始运动，必要时联系受控维护 |

### 8.4 Storage Failure

| Scenario | Device Response | User Guidance |
|---|---|---|
| 存储不足 | 关联4.3.8；保护有效结果、系统与识别资源，提示不足，不擅自删除未同步记录 | 按授权管理存储，恢复足够空间后继续 |
| 结果保存失败 | 明确未可靠保存状态，不伪称已同步或已结算奖励；不能保护新结果时阻止继续积累无法记录的运动 | 处理存储问题，了解已保存与不可确认部分 |
| 保存数据无法确认 | 不补造次数与目标完成，受控维护仅使用必要运行信息 | 告知记录不可确认，提供恢复或重练选择 |
| 同步后清理 | 在结果保护与授权边界内管理缓存，不将成功同步误作删除儿童历史的授权；到期清理与授权删除承接4.3.8 | 说明必要存储状态；清理规则后续评审 |

### 8.5 Exception Logging & Platform Sync

| 场景 / 要求 | 设备职责 | 平台同步结果 |
|---|---|---|
| 异常发生或状态变化 | 记录必要的异常类型、发生时间/时间不可用状态、设备运行阶段、影响及处理状态；仅保留能确认的信息 | 事件在授权范围可追溯，不包含家庭影像或原始语音 |
| 异常恢复 / 未恢复结束 | 记录恢复结果及本次运动是否继续或结束，关联必要事件上下文 | 可理解异常经过，不把故障事件当成有效运动或重复奖励 |
| 离线 | 保存待同步异常事件，明确未同步状态 | 不伪称上传成功，联网后补传 |
| 联网补传 | 同步必要日志，处理重复并反馈成功/失败状态；平台确认接收后才视为已同步 | 不丢待同步事件、不重复形成同一次异常 |
| 日志保存或同步失败 | 在可执行范围保留失败状态，保护运动记录优先，不产生自我循环的无限日志 | 恢复后继续同步；无法可靠保存部分不补造 |
| 存储管理与维护访问 | 限制日志容量与保留范围，仅有权平台维护人员访问；未同步日志清理规则待评审 | 不上传视频、截图、原始语音、口令或无关儿童/家庭数据 |

日志容量、保留时长、重复事件归并、重试与清理规则在后续PRD中确定；MVP记录与同步职责已明确，不因规则待细化改回候选。

## 9. Growth System Principle

目的：成长反馈只奖励真实运动，保持儿童心理安全、隐私及运动公平。

| 类别 | 原则 | 功能承接 |
|---|---|---|
| 奖励有效动作 | 依据可确认的有效完成形成运动星或成长反馈 | 2.2.3、3.3.1、3.1.1 |
| 奖励持续运动 | 依据真实运动日与持续积累，而非打开设备或虚假签到 | 2.4.1、3.2.2、3.2.4 |
| 奖励个人进步 | 比较同一儿童、动作、单位的有效记录 | 3.2.3 |
| 不奖励登录与在线时间 | 陪伴、浏览、待机不替代运动贡献 | 3.1–3.2 |
| 不奖励虚假签到或充值 | 安排不等于完成，消费不带来识别或计数优势 | 2.4.1–2.4.5 |
| 不重复奖励 | 补传或恢复不重复计算同一次运动的成长收益 | 5.1.2、5.2.2 |
| 保护真实努力 | 提前结束不抹去有效完成；达标奖励与部分努力反馈的规则待评审 | 2.2.5–2.2.6、2.3.5 |
| 温和持续激励 | 连续运动不引入缺勤惩罚、羞辱、公开竞技排名或强迫签到 | 3.2.2–3.2.4；3.1.3为P2，具体形态待评审 |
| 宠物服务运动 | 宠物成长仅为候选，不建立脱离运动的独立养成或付费循环 | 3.1.4 P2 / Candidate |

成长星/运动星名称、结算口径、连续运动规则与设备承载范围待评审，不在本稿编造公式或奖励数值。
