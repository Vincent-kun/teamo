## 2. 状态真源与 UI 规则

| 信息 | 真源 | 设备显示 | 家长显示 |
|---|---|---|---|
| 任务配置与版本 | 获授权发布方；部署位置 M1 定 | 本地已确认任务 | 发送中/已送达/拒绝；发布成功不等于已开练 |
| 当前会话与次数 | 设备运动会话模块 | 已确认次数与目标 | 最近设备快照；离线标上次更新时间，不自行预测计数 |
| 物理隐私状态 | 硬件实际状态 | 关闭或未知即停止采集 | 上次确认状态与时间；离线不能断言当前开关状态 |
| 单次结果 | 设备先原子保存；同步模块确认接收 | 完成/提前结束＋待同步或已同步 | 已接收的真实结果；未收到时显示等待结果 |
| 奖励 | 由真实结果派生、按 sessionId 去重 | 一次反馈 | 同一奖励记录，不重复追加 |
| 分析结论 | 授权记录摘要＋分析版本 | 不参与实时计数 | 依据、范围、数据不足或失败；无依据不展示精确能力评分 |

“完成”表示运动业务结果；“已同步”表示结果传输状态，两者不合并。“暂停”保留进度；“中断”是保存后的终态之一，不伪装成达标。

## 3. 主链页面状态矩阵（待联合冻结）

| 状态 | 进入条件 | 设备主信息与操作 | 家长端信息 | 转移与保护 |
|---|---|---|---|---|
| Idle | 无活动会话 | 今日任务/自主运动、伙伴表情 | 今日结果、待办、设备最近状态 | 摄像头按流程与授权开启，不为待机默认持续采集 |
| Task | 任务已接收且版本有效 | 动作、目标、开始/稍后 | 已收到、等待孩子开始 | 重复命令不创建第二条；过期或不支持动作明确拒绝 |
| Entry | 已选任务或自主目标 | 站位图＋一次具体提示、返回 | 正在准备 | 无人/太近/太远/身体不完整不开始 |
| Ready | 满足冻结的稳定入镜条件 | 站好了、准备开始 | 准备完成 | 稳定时间由算法评审定，非页面动画时间 |
| Countdown | 准备满足且儿童已确认 | 3/2/1、取消 | 即将开始 | 离画/摄像头关闭取消倒计时，重新入镜 |
| Running | 倒计时结束、采集有效 | 大计数/目标、暂停/结束、短提示 | 运动中、最近确认进度 | 无完整动作事件不加次数；网络断开不清零、不停止本地闭环 |
| LowConfidence | 算法无法确认当前动作 | 调整站位或再做一次 | 如需显示则使用可理解原因 | 不责备、不补造次数；持续异常按冻结策略暂停 |
| Paused | 主动暂停、离画或采集故障 | 已完成进度、原因、继续/结束 | 已暂停＋最近进度 | 恢复须重新入镜；清除未完成动作周期，保留已确认次数 |
| Result | 达标或主动结束 | 实际/目标、完成或已结束、返回 | 等待结果或已收到结果 | 先可靠保存再庆祝；写入失败提示重试，不能假装结果已保存 |
| PendingSync | 结果已保存但未获上传确认 | 结果已保存，等待同步 | 仍显示上次确认信息 | 重试同一幂等键；确认前不删待上传记录 |
| Interrupted | 重启后发现未结束会话 | 已保存进度，继续或结束 | 会话中断、等待最新状态 | 不自行判达标；恢复从最后持久化确认值开始 |

建议默认儿童在设备确认继续；App 不直接跳过入镜和安全条件。远程暂停/结束能否支持、何时确认，由 W2 交互与协议评审决定，不能把演示按钮视为最终授权规则。

## 4. 首批有意义的验收脚本

| 编号 | 操作与输入 | 预期结果 | 验收层 |
|---|---|---|---|
| C01 | 同 commandId 发送同一任务三次 | 一条任务，返回同一接收事实；无多次邀请和奖励 | 协议＋双端 UI |
| C02 | 创建目标20，已确认12，暂停后继续 | 暂停期间拒绝计数；重新入镜下一次有效周期为13 | 会话＋真实算法 |
| C03 | 第12次确认后离画；送入迟到动作事件 | 保留12，迟到事件不计；恢复清除半周期 | 会话＋算法适配器 |
| C04 | 断网完成任务，再重连重复上传 | 本地结果保留；最终仅一条结果与一份奖励 | 存储＋同步＋UI |
| C05 | 运动中物理关闭摄像头或隐私状态未知 | 停止采集和计数，保留进度；设备提示与最近确认家长状态有来源 | 硬件＋设备＋UI |
| C06 | 事件顺序 10、12、11，随后重连 | 不回退次数；发现缺口按策略取权威快照 | 通信＋App |
| C07 | 会话写入与结果入队时断电 | 无虚假完成、无孤立丢失结果；可定位最后持久化事实 | 真实存储/断电测试 |
| C08 | 已执行任务收到较新版本取消/修改 | 按冻结策略确认拒绝或后续生效；目标不无声变化 | 任务协议＋UI |
| C09 | 无记录、未授权、分析超时或输出被拦截 | 分别显示数据不足/需授权/降级结果，基础运动可继续 | 分析＋家长 UI |
| C10 | 切换儿童档案、撤销绑定或删除记录后旧设备补传 | 不串儿童、不越权、不复活删除记录及其分析 | 权限＋同步＋删除 |
| C11 | 模拟输入通过后换真实目标板完成10次开合跳闭环 | 每次任务、计数、暂停、结果一致，达到原 M4 验收 | 真实系统集成 |
| C12 | 儿童只看设备完成开始/暂停/恢复，家长查看未达标结果 | 记录理解、成人介入与困惑；未达标不被理解为系统漏记录 | 三年龄段用户观察 |

C01–C10 先在模拟器验证协议与状态，硬件相关条目最终必须用真实设备重验。算法计数效果另用冻结的评测集与人工真值比较；模拟器接口测试不能替代识别准确度。

## 5. UI 文件与工程交接结构建议

设计文件应按“基础规则、家长端、设备端、异常与恢复、实机验收”组织。每页带状态 ID、数据来源、文案和对应验收编号；图标标明静态/动画、格式、尺寸与授权来源。演示姓名/成绩、模拟操作与生产素材分别标记，避免带进正式包。

M1 后新工程建议逻辑分为：共享契约、运动会话核心、模拟器、设备适配器、设备 UI、家长平台实现、数据与同步实现。物理目录结构随冻结技术栈确定，当前不创建空工程充当开发进度。已有演示、冻结快照与发布目录保持原位。

首个开发提交应包含：可运行的会话模块、模拟事件输入与输出、C02/C03/C04 等接口验收证据，以及能显示真实模块输出的最小双端界面。先验证业务事实，再扩展展示页。
