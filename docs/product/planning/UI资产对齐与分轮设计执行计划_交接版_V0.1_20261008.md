# UI资产对齐与分轮设计执行计划 · 交接版 V0.1

更新：2026-10-08。状态：执行计划，尚未完成资产审计或设计定稿。项目：儿童 AI 运动伙伴（6–15岁）。

## 1. 本轮目标与授权范围

用户要求先核对本地与 `git@github.com:Vincent-kun/teamo.git` 已有 UI 成果，整理归类，明确能复用与需重写部分；重点是交互逻辑。随后调查专业可视化方法与三种高审美视觉方向，讨论后收束，分轮搭建原型。先建立完整软件框架，再由 PM 决定 2026-11-15 MVP 展示范围，UI 设计者不能独自承诺全部功能。

本文件把上述工作变成可接续任务；不修改既有 PRD、甘特图或产品边界，不移动历史资料，不提交、推送或发布。完整设计覆盖与 MVP 实现范围分别记录。

## 4. 工作包与交付顺序

### P0：本地与远端成果核对

1. 记录本地分支、HEAD、未提交文件；只读核验GitHub实际分支、提交SHA及更新时间。网络阻塞时记录原因，不把本地缓存冒充远端。
2. 扫描 `apps/wechat-mini-program/`、`prototype/`、`AI运动伙伴/小程序MVP_V0.1/` 与冻结快照；排除依赖、构建缓存、受保护发布目录。
3. 以文件哈希识别副本；标明规范入口、历史副本、远端有而本地无、本地未提交。禁止为归类大规模搬文件。
4. 逐项登记页面、组件、交互、图标/角色素材、设计token、接口mock、测试与文档；标明版权或来源不明资源。

交付：UI资产索引CSV/JSON、仓库版本对照、源码证据与差异清单。出口：每项可追溯到文件/提交，不存在两个无解释的主入口。

### P1：交互复用与重写评估

以“绑定/选择儿童→创建任务→设备确认→入镜→倒计时→运动→暂停/恢复→保存→同步→家长结果”为评估主链，另列设备自主开练候选。所有已有页面分别标记：直接复用、改造复用、重写、仅参考、延后/待PM决定。

复用判断必须区分视觉资产、页面结构与业务逻辑。重点检查命令ID与重试幂等、任务与会话职责、真实回执、重复/乱序事件、离画恢复、物理隐私关闭、离线补传、保存失败、重启恢复、删除与授权撤回。模拟计数、共享内存状态、硬编码计划与分数不能直接当生产实现。

交付：复用矩阵、关键流程状态表、交互缺陷与改造优先级、最小协议候选。出口：主链状态、触发、守卫、提示、恢复动作与责任真源清楚；未实现能力明确标记。

### P2：专业图册与三方向参考

图册分层：能力树表达包含关系；责任/数据流表达模块分工；泳道表达跨端协作；局部状态图表达转移。先呈现主链，再按需展开异常，避免一张巨图混用语义。保留图例、箭头含义与可读字号。

视觉调查使用同一组四屏：家长首页、任务设置、设备实时计数、运动结果。候选方向：A活力运动场（Nex Playground）；B温暖陪伴屋（Yoto，邻近品类）；C清晰成长仪表（Fitbit Ace LTE）。产品官网用于功能证据；官方品牌/设计系统用于规则；Behance原作者与Awwwards案例用于审美参考。奖项和作品集不能证明儿童可用性，参考素材不得直接复制进产品。

每方向输出：实际可见参考图与来源、字体/色彩/布局/动效规则、三年龄段适配、适合与不适合借鉴的点、同内容四屏对比。出口：看过实际视觉而非仅搜索摘要；团队能够比较清晰度、年龄适配与实现成本。

### P3：讨论、收束与分轮原型

- 第1轮：全量逻辑与异常框架；PM标记本轮/后续/排除/待决，算法与硬件确认约束。
- 第2轮：同四屏的三种视觉方向；讨论后确定方向与必要混合规则，留评审理由。
- 第3轮：按选定方向搭建可点击双端原型，分批覆盖主链与异常；形成组件、状态文案和素材交付。
- 第4轮：真实设备与服务联调，观察儿童理解、家长结果判断，修复主链问题并彩排。

各轮允许重叠：范围内主链与协议可先行，完整远期视觉不阻塞开发。不能把完整框架理解为11/15必须全部实现。

## 7. 验收与交接要求

- 资产审计有版本与文件证据；重复副本有解释；模拟/真实能力分开登记。
- 状态图文字清晰、分层明确；主链与异常可分别查看；不可只通过静态截图认定交互可用。
- 原型主链及关键恢复可操作；远端回执与本地成功分开；儿童原始视频不持久化。
- 三方向使用相同内容比较；明确图像实看状态、来源、借鉴理由与版权边界。
- 交付包含运行方法、状态模型、组件/素材、协议候选、未决项、已知限制与验证证据。
- MVP最终裁剪有PM记录；工程落实有真实设备/服务证据。
