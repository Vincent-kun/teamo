## 1. 三者关系（版本血缘）

```
完整产品 UE Demo V7.3  ──(微调措辞)──▶  V7.4（当前设计源，已在 docs/）
        │
        │ 小程序 MVP README 明确「根据 V7.3 整理」，并按 2026-09-24 会议收紧为 3 条主线
        ▼
微信小程序 MVP V0.1（家长端可运行代码，Mock 数据）
```

- **V7.3 / V7.4** 是**完整产品级交互原型**（单 HTML 文件，可在浏览器跑），覆盖家长 App + 孩子端设备屏 + 调试检查器。
- **小程序 MVP V0.1** 是从 V7.3「整理」出来的**家长端可运行工程**（真实 wxml/wxss/js，可导入微信开发者工具），只落地家长侧闭环。
- 两者动作库一致（7 类），但 MVP 仅开放 2 个为「MVP已支持」。

## 2. V7.3 完整 UE Demo 解析

### 2.1 三大界面
| 界面 | 说明 | 是否进入 MVP |
|---|---|---|
| `appScreen`（家长 App） | 首页/任务邀请/AI计划/成长/我的/设备/记录/资料/设置/家庭空间 等模块 | ✅ 大部分落地（见 §3） |
| `deviceScreen`（孩子端设备屏） | 机器人的「表情眼」(5–6 态：normal/focus/happy/curious/sleepy/alert) + 运动会话流程：站姿检测→开始→计数→休息→完成 | ❌ MVP 未实现 |
| `调试检查器` | 开发用面板：设备状态、运动控制(+1有效动作/离开画面/暂停/完成/离线/上线/开心/提醒/规则生成状态)，明确标注「开发信息仅在这里显示，不进入家长端和儿童设备界面」 | ❌ 内部工具，不进 MVP |

### 2.2 动作库（与 MVP 一致）
双脚跳绳、开合跳、高抬腿、深蹲起、俯卧撑、仰卧起坐、平板支撑（7 类）。

### 2.3 家长 App 模块（appScreen）
首页、运动邀请(任务)、AI 计划、成长、我的、设备、记录、资料、设置、家庭空间。含绑定、隐私、医疗边界（医疗 5 处、健康 3 处提示）。

## 3. 小程序 MVP 相对 V7.3 的「收敛」与「新增」

### 3.1 已落地（从 V7.3 家长 App 派生，11 页面）
首页 / 任务(邀请) / AI(计划) / 成长 / 我的 / 设备(家长视角) / 动作库 / 记录 / 分析 / 姿态 / 资料。
→ 与 V7.3 家长 App 模块基本对应；`设置/隐私/重置演示` 收进「我的」页；`家庭空间` 简化为「我的」里的单孩子模式。

### 3.2 明确砍掉 / 后置（MVP 边界）
- **孩子端设备屏（deviceScreen）**：MVP 的「设备页」是**家长视角的监控**（状态/控制/能力开关/动态），并非孩子面对机器人时的会话 UI（站姿检测、表情眼、休息/完成反馈）。这是两者最大结构差异。
- **调试检查器**：内部开发工具，不进 MVP。
- **动作库**：V7.3 七种动作均可在原型里走通；MVP 仅开合跳/深蹲起标「MVP已支持」，其余标「算法评审中/后续适配」，避免误导硬件与算法。
- **未做**：学校端、皮肤兑换、身高体重占位、多人家庭权限、正式支付、医疗判断、饮食拍照分析（与 MVP 边界一致）。

### 3.3 MVP 相对 V7.3 的「新增价值」
- **可运行工程**：真实微信小程序代码（非原型），可导入开发者工具、可接真实后端（`USE_MOCK` 一键切换）。
- **接口层文档化**：新增《接口对接说明》——HTTPS/WebSocket + MQTT 链路、设备状态机 7 态、`devices/{id}/commands|status|events|results` 主题、指令/结果 JSON 示例。V7.3 无此落地约定。
- **视觉系统化**：MVP 采用 V0.9 亚克力玻璃（环境光→半透明卡→实色按钮），并在整改说明里固化了整改前问题与收敛逻辑；V7.3 偏探索性视觉。
- **主线收紧**：按 2026-09-24 会议把家长侧收为三条主线（创建邀请 → 设备执行 → 学伴积分养成）。

## 4. V7.3 vs V7.4 差异（同目录两份设计源）

| 维度 | V7.3（本日归档） | V7.4（既有最新） |
|---|---|---|
| 动作库 | 7 类 | 7 类（一致） |
| 界面结构 | appScreen + deviceScreen + 调试检查器 | 同 |
| 家庭空间/绑定/隐私 | 有 | 有（一致） |
| 医疗边界提示 | 5 处 | 6 处（+1，措辞更严谨） |
| 健康提示 | 3 处 | 2 处（−1） |
| 结论 | 设计源母本 | 在 V7.3 基础上的措辞/边界微调，无新增界面 |

→ 两份设计源**结构等价**，V7.4 是 V7.3 的边界措辞精炼版。小程序 MVP 如要追平设计，应以 **V7.4** 为准，并补足 §3.2 缺失的孩子端设备屏与调试检查器参考。

---

## 5. 结论与建议

1. **版本定位**：V7.3 = 母本（已归档）；V7.4 = 当前设计真源；小程序 MVP = 家长端实现基线。三者并存，不要互相覆盖。
2. **最大实现缺口**：孩子端设备屏（deviceScreen）与调试检查器在 MVP 中完全没有对应物。若下一步要演示「设备如何引导孩子运动」，需从 V7.3/7.4 抽取 deviceScreen 流程单独做 MVP 子原型。
3. **动作库对齐**：MVP 把 5 个动作标为非 MVP，但 V7.3/7.4 原型里动作均可演示；待算法验收后逐步放开，与 V7.4 保持一致。
4. **接真实后端**：MVP 已预留 `services/api.js` 与接口文档，是 V7.3/7.4 不具备的落地资产，演进时优先复用。
5. **归档位置**：V7.3 已存 `docs/product/design/` 与 V7.4 同目录，便于版本对照；小程序 MVP 在 `AI运动伙伴/小程序MVP_V0.1/`，两者通过本说明关联。
