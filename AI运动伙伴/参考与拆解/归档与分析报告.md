## 1. MVP 周甘特图分析

### 1.1 规模与结构

**关键发现**
- **设备端软件是绝对重心**：占 35% 总工时（1178h），且 48 个高风险中的 12 个、126 个阻塞中的 43 个集中在这里——通信协议、状态机、断网补传是最大雷区。
- **硬件（278h）与算法（396h）工时偏低但风险极高**：硬件 7 个高风险 + 15 阻塞、算法 6 高风险，二者决定"能否做出真实样机"，是计划的隐性瓶颈。
- **结构/工业设计（308h）零关键任务但有 4 高风险**：视场、稳定性、装配被明确标注不得阻塞真实设备联调（与 BodyPark 结论一致）。

### 1.3 时间轴与里程碑
任务起始周分布：**W1:29 / W2:31 / W3:28 / W4:21 / W5:21 / W6:8 / W7:8 / W8:2** —— 计划**前重后轻**，W1–W5 集中启动，W6–W8 主要是测试、集成与用户测试。
里程碑：M0 范围冻结 → M2 硬件 Bring-up → M3 单模块验收 → M4 开合跳黄金链路 → M5 三动作集成 → M6 Alpha → M7 用户测试 → M8 发布。

### 1.4 关键路径（27 个关键任务，节选）
冻结 M0 范围基线 → 冻结 MVP 硬件方案 → M2 硬件 Bring-up → 设备端业务状态机 → 开合跳识别与计数 → 冻结通信底层/业务协议 → 双端通信模块 → 冻结后端边界/任务会话服务 → AI 分析聚合与降级/对话卡片/联调 → M4 黄金链路 → M5 三动作集成 → M6 Alpha / 最终回归 → M7 用户测试 / 关键修复。

### 1.5 四大风险主题（贯穿 48 个高风险）
1. **器件选型未冻结**（硬件 3.1.2/3.1.3/3.1.4）：第 2 周必须冻结主选与备选，关键料逾期即切换开发板/替代料。
2. **接口先用模拟数据并行开发**（设备软件/App/通信/姿态）：黄金链路逐段验收，接口变更当天同步。
3. **算法先冻结评测集与量化阈值，未达标降级到开合跳**（视觉算法 6.2.x）。
4. **隐私最小化 + 规则降级兜底**（AI 分析/后端 9.x、10.x）：仅用已授权结构化摘要，异常回退规则总结。

## 2. BodyPark ATOM 拆解分析

### 2.1 这是什么
**BodyPark ATOM（型号 BPK A1）**——一款"AI 健身陪伴终端"，被第三方做了**逆向工程 + 可复刻性评估**。拆解方最终结论是：**不要逐器件复制，而应定义为"自主兼容设计"**，拿它当产品需求参考重做电子架构。

### 2.2 硬件架构（已确认实机信息）
| 子系统 | 规格 | 状态 |
|---|---|---|
| 主控 SoC | Rockchip **RV1106B**（Cortex-A7+MCU，0.5 TOPS INT8 NPU，嵌入式 DDR 512Mbit–2Gbit） | 确认 |
| 摄像头 | 5MP / 1/2.8" / **160° 超广角** / MIPI CSI-2 | Sensor 型号/Lane 未确认 |
| 显示屏 | 1.43" **466×466 圆形 AMOLED** | 面板/驱动/接口未确认 |
| 存储 | 4Gbit SPI NAND（FORESEE F35SQB004G ≈512MB）+ microSD | 确认 |
| 无线 | NL-H853-SSA1 2.4GHz 模组（WiFi/BT） | Host 接口未确认 |
| 电池 | 1S **2000mAh** LiPo，USB-C 5V/2A | 确认 |
| 电源 | UP1(marking E1831，非 ETA6963) / UP4(≈TPS62A02A-Q1) | 完整型号未确认 |

**数据流**：Camera → ISP → NPU(Pose/动作) → 运动状态机 → 圆屏/扬声器/手机端。这与本项目的"采集→识别→反馈"闭环同构。

### 2.3 成本模型（人民币，含制造与损耗）
| 口径 | 直接物料 | 含 SMT/装配/测试/包装 |
|---|---:|---:|
| 单台样机 | 491–1350 元 | **571–1570 元** |
| 小批量(100–1000) | 225–477 元 | **260–567 元** |
| 量产(1 万台) | 156–316 元 | **176–371 元** |

> 注意：含大量 **C/D 级占位值**（未获 RFQ），是情景模型而非采购报价。四档最需优先收敛：RV1106B、无线模组、摄像头、结构件。

**NRE 经验预算**：PCB/硬件 15–60 万；结构/模具 15–80 万；BSP/驱动 20–100 万；**视觉算法/数据 50–300 万+**；App/云 30–200 万+；测试认证 20–100 万+。
**团队预算**：实验室样机 3–15 万(2–4 人/2–4 月) → 可演示工程样机 50–200 万(5–8 人/6–10 月) → 接近商业 200–800 万+(8–15 人+/9–18 月+)。

### 2.4 可复刻性分层（L1–L5）
- **L1 原理验证**（高）：开发板 + 5MP MIPI Camera + 圆屏 + WiFi/BT 即可跑通主链路。
- **L2 自研硬件样机**（中高）：自研主板、完整电源/音频/存储/结构。
- **L3 接近原机尺寸续航**（中）：定制 FPC/天线、低功耗、EMC、热、装配公差。
- **L4 接近原机 AI 体验**（中低）：动作数据集、Pose/识别模型、业务规则、语音反馈——**算法才是真壁垒**。
- **L5 完整商业产品**（低）：App/云/OTA/账号/内容/认证/供应链。

**核心判断**：硬件可复刻性高，决定性投入从 BOM 转向**算法数据、软件系统、产品调优与持续运营**。

### 2.5 推荐实施路径（与本项目高度可映射）
阶段 0 证据补齐(2–4 周) → 阶段 1 开发板 PoC(4–8 周) → 阶段 2 自研主板 EVT(8–14 周) → 阶段 3 DVT 算法收敛(12–24 周) → 阶段 4 PVT/认证(8–16 周)。
**Go/No-Go**：自研 PCB 前必须确认 Camera Sensor Driver、显示接口、无线 Host 接口；开模前冻结视场/屏角/散热/按键/电池尺寸。

## 3. 跨文件综合：对本项目 MVP 的启示

### 3.1 同构性（关键结论）
BodyPark ATOM 与本项目的**硬件形态几乎 1:1 重合**：RV1106B 视觉终端 + 圆屏反馈 + 超广角摄像头 + 本地姿态/动作识别 + 手机端分析。区别仅在**使用场景**（成人健身 vs 儿童运动陪伴）与**合规要求**（儿童数据最小化）。因此 BodyPark 是一份**现成的、可借鉴的 MVP 硬件参考架构**，而非无关竞品。

### 3.2 把 BodyPark 三阶段直接映射进甘特图
| BodyPark 阶段 | 对应本项目任务 | 当前计划状态 |
|---|---|---|
| 阶段 0 证据补齐（UART/USB/电源树/接口确认） | 硬件 3.1.2–3.1.6 调研 + 3.2.1 架构评审 | 高 risk，第 2 周冻结器件 |
| 阶段 1 开发板 PoC（Camera→ISP/NPU→显示闭环） | 硬件 3.3.x Bring-up + 算法 6.2.1 开合跳 | 关键路径，M2/M4 |
| 阶段 2 自研主板 EVT | 硬件 3.2.2–3.3.5 冻结方案/Bring-up | 3 关键 + 7 高 risk |

**建议**：在甘特图"硬件方案与样机"模块补充一条显式任务——"对标 BodyPark 冻结接口规范（24-pin Camera FPC / QSPI 圆屏 / 电源域划分）"，把 BodyPark 的 Go/No-Go 节点固化进 M2 前检查单。

### 3.3 风险对齐（两边一致的高危项）
| 风险 | 甘特图表现 | BodyPark 对应 |
|---|---|---|
| 器件选型未冻结 | 硬件 7 个高风险 | 阶段 0 证据补齐 + "关键料号未确认"高 risk |
| 算法数据/泛化不足 | 视觉算法 6 个高风险 | L4 难复刻，先冻结评测集 |
| 软件/云范围膨胀 | 后端 9.x 高 risk | "先明确离线 MVP，再增账号与云" |
| 儿童隐私 | 10.1.2/9.1.3 高 risk | 数据最小化、视频不持久化 |

### 3.4 成本锚点（用于本项目预算）
- 小批量 BOM 可参考 **260–567 元/台**；若走"开发板 PoC 起步"，样机阶段可控制在 **571–1570 元/台** 且避免自研主板沉没成本——与甘特图"评估开发板与自研板路径(3.1.2)"的高 risk 决策直接呼应。
- NRE 中**视觉算法/数据 50–300 万+** 是最大单项，应在 MVP 预算里优先保障，并复用 BodyPark"先开合跳黄金链路、未达标降级"的节流策略。

### 3.5 可直接复用的设计规范（`路线.md`）
- **24-pin Camera FPC**（留 4 Lane 余量，2-Lane 起步）、**QSPI 圆屏**（非 MIPI DSI，更简单）、**6 层 PCB + 功能分区**、**电源按 Domain 拆分（3V3_SYS/WIFI/CAM/LCD）** 以降低待机电流、**MIPI 100Ω / USB 90Ω / RF 50Ω 阻抗表**。
- 数据流与"动作状态机 + 关节角/阶段/对称性"评价逻辑，可直接作为本项目动作计数与质量评分的参考实现。

### 3.6 建议的下一步（可执行）
1. **硬件立项前先发 RFQ**：RV1106B、无线模组、5MP 摄像头、圆屏四类优先收敛（对应 3.1.2）。
2. **把 BodyPark 接口规范写入 M2 前冻结清单**（Camera/Display/无线 Host 接口 + 视场/屏角/电池尺寸）。
3. **甘特图回填 Named Owner**（夏炜城/魏子奇/李沁佟），并把 BodyPark 三阶段作为硬件子里程碑显式登记。
4. **算法评测集现在就冻结**：定义三动作允许误差、离线能力、儿童分群验证集，避免 L4 陷阱。
5. **预算按"离线 MVP 优先"排**：先保证设备端闭环，账号/云能力后置，控制 NRE 在可演示工程样机档（50–200 万）。
