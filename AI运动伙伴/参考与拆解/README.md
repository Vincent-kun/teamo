## 关键结论速读（详见 `归档与分析报告.md`）

- **规模**：148 基线任务（后补 1 = 149），3376 计划工时，M0–M8 共 8 周。
- **重心**：设备端软件占 35% 工时（1178h），且高风险/阻塞高度集中——通信协议、状态机、断网补传是最大雷区。
- **隐性瓶颈**：硬件（278h）与算法（396h）工时偏低但风险极高，决定"能否做出真实样机"。
- **里程碑**：M0 范围冻结 → M2 硬件 Bring-up → M3 单模块验收 → M4 开合跳黄金链路 → M5 三动作集成 → M6 Alpha → M7 用户测试 → M8 发布。
- **状态**：所有任务"未开始"，尚无 `actual` 回填；周视图进度环需每周回填才能驱动。

## 使用提示

- 改计划：编辑 `gantt_tasks.json` 后用对应 HTML 重新加载；或直接在 HTML 内操作。
- 看硬件对标：BodyPark 拆解去 `docs/research/bodypark-teardown/`（`路线.md` 是复刻设计准绳）。
- 不要基于未回填的"计划工时"对外承诺交付日期。
