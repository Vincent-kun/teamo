# AI 运动伙伴：4G 物联网与端云模型架构研究

> 日期：2026-09-23  
> 范围：家庭消费端（家长手机 App + 儿童使用的硬件本体），不含学校端。  
> 本文是工程决策建议，不把既有 PRD 当成需求真值；所有体验目标都应通过真机、真卡、真实家庭网络验证。

## 1. 先给结论

内置 4G 值得做，但它解决的是“首次使用和换环境时不必先配 Wi-Fi”，不是“网络永远即时可用”。正确产品形态应是：

1. **4G 默认可用，Wi-Fi 是可选的低成本/大流量通道**。用户开箱不应被 SSID、密码或手机热点阻塞。
2. **本地先启动，网络并行驻网**。开机动画、角色问候、儿童身份选择、基础运动和隐私指示都不依赖云；云连接就绪后再无感增强对话。
3. **视觉闭环必须本地完成**。摄像头帧只在设备内用于人体/动作识别，默认不上传、不形成可回看的监控资产。云端只接收最小化的结构化运动事件及儿童主动发起的短语音片段。
4. **不能把“模型用网络”理解成“所有功能都押在网络上”**。云端适合自然语言理解、内容编排和高质量 TTS；计数、暂停、危险提示、断网提示、固定指令和当次结果必须离线可用。
5. **首轮 EVT 优先采用成熟 Cat.1 bis 模组 + 焊接式物联网卡（MFF2）或卡座**，同时向运营商/模组商询证 eUICC 远程配置能力。不要把“焊接 SIM”误称为真正可远程换运营商 profile 的 eSIM。

因此，UI 的状态机至少要真实覆盖：`本地可用/4G 驻网中/云服务连接中/在线/弱网/离线/套餐异常/实名未完成/服务维护`，而不能只有一个装饰性的“联网图标”。

## 2. 为什么是 Cat.1 / Cat.1 bis，而不是 NB-IoT 或默认上 5G

工信系统公开的移动物联网分层建议把 NB-IoT 放在低速率、时延不敏感场景，把 4G Cat.1 放在中等速率且要求稳定传输的场景，5G RedCap 则面向更高吞吐的应用。对本产品的短语音上行、TTS 下行、模型请求、OTA 和遥测，Cat.1 的 10 Mbps 下行 / 5 Mbps 上行等级已经充足；它又比 5G 方案更利于控制模组、射频和套餐成本。[广东省通信管理局：《“粤联”行动计划（2025—2027 年）》](https://gdca.miit.gov.cn/zwgk/tzgg/art/2025/art_f4118536b1b348728d6fe17ea6b19e8a.html)

**边界条件**：如果后续决定把持续视频上传作为核心功能，Cat.1 的带宽、流量和隐私模型都会改变；但那也会使产品变成家长监控器，与当前定位冲突。因此不应以“未来可能传视频”为由提前上更重的蜂窝方案。

### 3.1 不能忽略的电源与射频代价

4G 模组的小尺寸不等于系统代价小。合宙的硬件指南明确要求持续供电能力大于 1 A、瞬态大于 2 A，并指出射频发射瞬间可能出现 1.5–2 A 的百微秒级脉冲；供电不足可能导致驻网时反复重启。[Air780E 官方开机与供电指南](https://docs.openluat.com/air780e/at/hardware/design/poweron/)

主板应因此预留：

- 独立且有余量的 3.8 V 蜂窝电源轨、靠近 VBAT 的低 ESR 储能电容及电压监测；
- 主天线的完整净空、匹配网络、射频测试座和整机 OTA 验证；
- 模组与摄像头/屏线/扬声器功放的 EMI 隔离；
- USB 2.0 或 ECM/RNDIS 数据通路，UART 作为控制与恢复通道；
- 看门狗、掉线重拨、FOTA 回滚和卡状态诊断。

模组 BOM 比较不能只看单价，必须同时比较运营商入库、CCC/SRRC/NAL 状态、Linux/Android 驱动、固件维护期、FOTA、天线认证复用和供货周期。

## 4. 物联网卡、焊接 SIM 与 eSIM

### 4.1 法规和运营约束

面向消费者销售带物联网卡的设备时，企业不仅是“买一张流量卡”。《反电信网络诈骗法》第十二条要求物联网卡销售进行用户风险评估、实名登记，并限制开通功能、使用场景和适用设备；单位用户购卡后再销售设备给个人，还需核验登记最终用户身份并把相关信息传给运营商。[工信系统转载的《反电信网络诈骗法》](https://sdca.miit.gov.cn/zwgk/fgbz/art/2023/art_fbcef7bd763e4993be6151201798cd8c.html)

这意味着 C 端流程必须包含：家长实名/激活、设备 IMEI/ICCID 绑定、套餐状态、停复机处理、换机解绑和注销，而不是出厂插卡就结束。行业卡还通常按“功能最小化”限制语音和短信，产品通信应基于数据通道，不把短信/电话作为核心能力。[工信部物联网行业卡安全要求](https://www.miit.gov.cn/jgsj/waj/gzdt/art/2020/art_8239fdb667f343a686accf3401501036.html)

### 4.2 推荐路径

- **EVT/PVT**：卡座便于多运营商和故障替换；也可并行做 MFF2 焊接式物联网 SIM 样机验证可靠性。
- **量产**：倾向 MFF2/eUICC 形态，避免儿童可触及卡槽，也提升防尘、防松动和防拆能力。
- **不要混淆概念**：MFF2 只是封装；是否能远程下载/切换运营商 profile，要看 eUICC、运营商平台和远程 SIM 配置协议是否形成完整商业闭环。
- GSMA 的 SGP.32 专门面向网络或 UI 受限的 IoT 设备，定义 eUICC profile 的远程配置和管理；它证明技术路线存在，但不等于中国三家运营商已自动为本项目提供可商用服务。必须在 RFQ 中逐项确认 EID、profile 下发平台、灾备 bootstrap profile、资费、认证和切换 SLA。[GSMA SGP.32 v1.2/规格清单](https://www.gsma.com/solutions-and-impact/technologies/esim/esim-specification/)、[GSMA IoT RSP 说明](https://www.gsma.com/solutions-and-impact/technologies/internet-of-things/technologies/iot-rsp-enabling-the-growth-of-massive-iot/)

建议采购不是零售渠道的“无限流量物联卡”，而是直接与基础运营商或能明确承担实名、连接管理与 SLA 的合规服务商合作。

## 5. 开机与网络注册：怎样真正改善体验

蜂窝网络要经过模组上电、SIM 初始化、搜网、注册、PDP 激活、DNS/TLS 和业务鉴权。具体时间受信号、运营商、卡状态、网络回落、基站负载和固件影响，供应商规格书没有给出一个可对所有家庭承诺的固定秒数。因此本文**不虚构“4G 三秒联网”指标**。

应建立如下并行启动状态机：

```text
按下电源
 ├─ 0~目标 1 s：屏幕/灯光给出本地即时反馈
 ├─ 本地角色与运动引擎启动 → 可进入基础活动
 └─ 4G 模组启动 → 驻网 → 数据链路 → 云鉴权
                         ├─ 成功：无打断切到在线增强
                         ├─ 较慢：显示“我在连接，先做热身吧”
                         └─ 失败：离线模式 + 家长 App 中提供诊断
```

建议把以下数字作为 **EVT 验收目标而非市场承诺**：

| 指标 | 建议目标 | 测试方法 |
|---|---:|---|
| 按键到首个视觉/声音反馈 | P95 ≤ 1 s | 100 次冷启动录像/示波 |
| 按键到本地菜单可操作 | P95 ≤ 5 s | 不等驻网 |
| 正常信号下冷启动到云服务可用 | 先测基线，再以 P50/P95 分运营商发布 | 三运营商、强/中/弱信号，各 ≥100 次 |
| 已开机断网后的自动恢复 | 不阻塞运动；恢复后自动续传事件 | 飞行箱/拔天线/欠费卡/小区切换 |
| 云故障 | 基础计数、暂停、结束、结果均可完成 | DNS、TLS、API 超时分别注入 |

优化手段包括：软关机时让主控待机、保持模组注册（若功耗预算允许）；服务连接预热；短超时后立即切离线；DNS 和鉴权缓存；OTA 分片/断点续传。但“永不真正关机”会带来待机功耗、发热和隐私感知问题，必须通过实体隐私指示与功耗测试取舍。

## 6. 云模型流量：语音可控，视频不可接受

### 6.1 可复算的流量估算

腾讯云实时音频接口支持 16-bit 单声道 PCM，推荐 16 kHz，也支持 Opus；据此可直接计算未经压缩的语音流量：`16,000 × 16 bit × 1 声道 = 256 kbit/s = 32 kB/s`。[腾讯云音频接口格式说明](https://cloud.tencent.com/document/product/862/137503)

以下仅为容量规划估算，不含 TLS/协议开销、重传和运营商计费进位：

| 业务 | 假设 | 单次/单日数据量 | 30 天量级 |
|---|---|---:|---:|
| ASR 上行（PCM） | 每天 10 分钟真正说话片段 | 约 19.2 MB/日 | 约 576 MB/月 |
| ASR 上行（Opus） | 假设 24 kbps、每天 10 分钟 | 约 1.8 MB/日 | 约 54 MB/月 |
| TTS 下行 | 假设压缩音频 32 kbps、每天 10 分钟 | 约 2.4 MB/日 | 约 72 MB/月 |
| 文本 LLM | 假设每日 100 轮、每轮上下行合计 10 KB | 约 1 MB/日 | 约 30 MB/月 |
| 结构化运动事件 | 数十至数百 KB/日 | 很小 | 通常 <10 MB/月 |
| 视频上行（反例） | 即使仅 1 Mbps、每天运动 30 分钟 | 约 225 MB/日 | 约 6.75 GB/月 |

因此推荐：本地 VAD/唤醒词先切掉静音，只上传儿童主动发起对话的 Opus 短片段；云端返回文本或压缩 TTS。**不上传持续环境音，更不上传运动视频。** 实际套餐应在样机遥测 4 周后按 P95 用户用量并留 OTA 余量定档，不能用上述假设直接采购。

### 6.2 OTA 是容易被漏掉的流量

若系统镜像 500 MB，即使每月一次就会压过大多数语音使用量。策略应是：

- 4G 只下发安全热修和必要资源；大型系统包默认等待 Wi-Fi，或经家长明确同意；
- A/B 分区、差分包、断点续传、签名校验与失败回滚；
- 家长 App 清楚展示“本月设备服务流量/系统更新”，但不把儿童对话内容暴露成监控记录。

## 7. 推荐的端云架构

```text
儿童与环境
   │ 摄像头/麦克风（明确工作指示）
   ▼
设备端可信边界
   ├─ 摄像头帧 → 人体/动作关键点 → 计数/姿态质量 → 即时反馈
   │               └─ 帧与关键点默认不出设备、不持久化
   ├─ 本地唤醒词/VAD/固定指令/内容安全前置
   ├─ 离线活动包、语音提示缓存、结果队列、网络状态机
   └─ 仅在主动对话窗口发送短音频，或尽量端侧 ASR 后发送文本
                 │ TLS + 设备身份 + 最小字段
                 ▼
云服务
   ├─ ASR（如端侧能力不足）→ 文本
   ├─ 对话编排/LLM（白名单工具与儿童安全策略）
   ├─ TTS/内容 CDN
   ├─ 运动事件与家长端同步
   └─ 设备管理、套餐、FOTA、审计与删除
                 │
                 ▼
家长 App：计划、共同选择、结果摘要、鼓励、设备/隐私设置
          不提供实时视频、音频监听、轨迹回放
```

### 必须在端侧运行

- 摄像头采集、人体检测、动作计数/基本纠错、区域越界和暂停；
- 唤醒词、VAD、音频缓冲，最好增加少量固定口令离线识别；
- 启动、身份选择、热身、基础活动、结束和结果页；
- 相机/麦克风状态灯控制（应由硬件链路驱动，不能只靠 UI）；
- 内容白名单、紧急停止、超时和断网降级。

### 适合放云端

- 非实时的自然语言理解与个性化活动编排；
- 高质量 ASR/TTS（在主动对话窗口内）；
- 家长与儿童两端的结构化结果同步；
- 内容包、模型/固件升级和设备运营。

### 明确禁止或默认关闭

- 持续上传摄像头画面、原始关键点序列或环境音；
- 家长远程打开摄像头/麦克风；
- 家长查看儿童逐字对话历史；
- 将儿童素材默认用于模型训练；训练授权必须独立、可撤回且不影响基本服务。

上述边界不仅是产品理念，也与儿童信息处理的正当必要、目的明确、监护人同意、最短保存、加密和最小授权要求一致。[国家网信办《儿童个人信息网络保护规定》](https://www.cac.gov.cn/2019-08/23/c_1124913903.htm) 进一步地，《未成年人网络保护条例》明确，不得因用户拒绝非必要信息处理而拒绝基本功能。[国家网信办《未成年人网络保护条例》](https://www.cac.gov.cn/2023-10/24/c_1699806932316206.htm)

## 8. 真实功能对应的 UI / 交互规则

| 系统真实状态 | 儿童硬件端 | 家长 App | 允许的动作 |
|---|---|---|---|
| 首次未实名/未激活 | “请家长用手机帮我开通”+ 配对码 | 实名、协议、设备绑定、套餐说明 | 本地演示可用；云服务锁定 |
| 4G 驻网中 | 角色先出现；非阻塞文案“正在连接” | 一般无需打扰 | 可进入离线活动 |
| 在线 | 不持续强调网络；云能力自然可用 | 显示设备在线与最近同步时间 | 对话、同步、内容下载 |
| 弱网 | 对话前提示“可能慢一点”；禁止无限转圈 | 弱网诊断与摆放建议 | 本地运动继续，云请求可取消 |
| 离线 | 明确“还能运动，聊天稍后再试” | 最近在线时间，不展示实时画面 | 离线活动；结果排队同步 |
| 套餐到期/卡停机 | 不把资费问题甩给孩子 | 家长端解释原因与续费/客服 | 基础离线功能不得被锁死 |
| 云服务超时 | 2–3 秒内给本地反馈，提供重试/换个玩法 | 仅持续故障才通知 | 不中断计数和运动结果 |
| 摄像头工作 | 物理遮挡打开 + 硬件灯常亮 + 屏幕简洁提示 | 只显示“运动识别中”，无画面 | 孩子可暂停/关闭 |
| 麦克风上传窗口 | 明确聆听动画和可见灯，超时自动关闭 | 不实时监听 | 儿童主动唤醒/按键后短时开启 |

关键规则：网络图标不是信息架构的主角；真正影响任务时才解释状态。所有 Loading 都必须有超时、取消和离线去路。运动完成后，即使仍离线，也要先在本地给出成功结果，云同步不能成为成功页的前置条件。

## 9. 建议 RFQ 与验证清单

### 给模组厂/方案商

- 中国移动/联通/电信具体入库型号与证书编号；Cat.1 与 Cat.1 bis 的确切基带和接收链路差异；
- 三网冷启动/热启动驻网实测分布，而非单一“典型值”；弱信号、跨省漫游、基站切换和断网恢复；
- Linux 内核/Android 版本支持、ECM/RNDIS/PPP 稳定性；
- 峰值电流波形、推荐电源与天线布局；
- eSIM/eUICC、MFF2、双卡/切换能力及配套平台；
- DFOTA、签名、回滚、固件维护周期、漏洞响应与量产追溯。

### 给运营商/物联网卡服务方

- 消费硬件最终用户实名流程、API/SDK、换机解绑和注销；
- 套餐是否支持语音模型流量特征、单卡限速/断流规则、流量池与超额保护；
- APN（公网/专网）、IPv4/IPv6、长连接、TLS、DNS、跨省策略；
- 停复机、异常卡、风险管控的状态 API 和 SLA；
- eUICC profile 远程下发是否已商用，支持的 eUICC/模组/平台与收费。

### 样机必须测

1. 三运营商、不同住宅和楼层的 P50/P95 驻网及云首包时间；
2. 连续 500 次冷启动、瞬态电流、掉电重启与热稳定；
3. 摄像头 + 屏幕 + 扬声器满载时的蜂窝吞吐和 EMI；
4. 弱网/断网/欠费/卡未实名/云超时每个 UI 状态；
5. 真实家庭一周的语音、事件、OTA 分项流量；
6. 抓包与服务端审计证明：运动视频、连续环境音和原始关键点没有离开设备。

## 10. 当前建议决策

1. **确认“双网但 4G 优先开箱”的产品方向**：4G 负责零配网启动与兜底，Wi-Fi 负责大型更新和可选降本。
2. **EVT 同时打样 EC800G-CN 与 Air780E 两套小板**，A7670C 做供应替代；以真实驻网、驱动、EMI 和功耗定点，不按宣传页定点。
3. **采用端侧视觉闭环 + 云端语言增强**，并把离线完成一次完整运动写入 MVP 验收标准。
4. **套餐先按 0.5–1 GB/月的语音交互假设做询价，同时设置流量遥测**；最终档位必须由 4 周实测决定。若持续使用 PCM 或频繁蜂窝 OTA，这一档位会立即不够。
5. **把隐私灯、物理遮挡、无远程监看和数据删除能力视为硬件/系统需求，不是后补的隐私文案。**

这套架构支持产品理念：4G 让孩子更快开始，云模型让陪伴更自然；但相机观察到的运动过程仍留在孩子身边，家长收到的是适合共同回顾的结果，而不是一台远程监视器。
