# Teamo 最新 UI 整体逻辑框架 V1.2｜整合稿

> 日期：2026-09-23  
> 范围：家庭 C 端；家长手机 App + 儿童硬件本体 + 本地/4G/云 + 成长玩法 + 模块化扩展  
> 状态：UI/UE 与产品架构联合评审稿  
> 来源：V1.1 主干逻辑 + 当前用户讨论形成的双用户、亲子、隐私、端云、成长宠物、排行榜与轮式底盘原则。

---

## 0. 产品命题

> **家长购买的是省心、可信和更好的亲子支持；孩子使用的是一个尊重自主、能看见真实努力的运动伙伴。**

Teamo 不是：

- 家长监视器；
- 儿童聊天玩具；
- 运动小游戏平台；
- 云端 AI 包装的计数器；
- 家长远程控制孩子的任务终端。

核心关系：**孩子拥有运动过程，家长参与关系，而不是观看过程。**

## 1. 双用户与权利边界

| 事项 | 家长 | 儿童 | Teamo |
|---|---|---|---|
| 购买、付费、实名、隐私授权 | 最终决定 | 被告知 | 透明、可撤回 |
| 可运动时段与安全范围 | 设置边界 | 知道边界 | 控制提醒频率 |
| 当次是否运动 | 可以邀请 | 开始/稍后/跳过 | 不惩罚拒绝 |
| 当次动作与目标 | 设置安全范围 | 在范围内选择 | 提供少量适龄选项 |
| 运动过程 | 不远程观看/控制 | 主要控制 | 本地识别、可暂停恢复 |
| 结果 | 看支持所需摘要 | 先看到并理解 | 事实一致、不篡改 |
| 主观感受 | 可邀请共享 | 决定是否共享 | 默认最小共享 |
| 训练数据 | 家长独立同意 | 可理解地知情 | 不与基础服务捆绑 |

四种触发入口

```text

────────────────────────

────────────────────────

```

## 3. 家长 App IA

一级导航保持四项：

```text
今天｜运动｜孩子｜设备
```

### 今天

- 今日是否需要支持；
- 邀请运动；
- 最近结果；
- 儿童主动求助；
- 一个亲子共同回顾入口；
- 必要设备异常。

不显示实时 Camera、实时次数、逐次错误和持续行为轨迹。

### 运动

- 安排一次运动；
- 个人历史与趋势；
- 家庭共同目标；
- 计划提醒；
- 经保护的小范围挑战（非 MVP 默认）。

### 孩子

- 昵称与年龄表达；
- 运动偏好；
- 儿童选择共享的感受；
- 开始、恢复、熟悉度等成长维度；
- 宠物关系、偏好和可删除记忆；
- 隐私授权状态。

### 设备

- 4G/Wi‑Fi/云服务分层状态；
- 电量、Camera、物理遮挡、固件、OTA；
- 物联网卡实名/套餐/停复机；
- 语言、主题、换装识别；
- 底座模块能力与固件；
- 售后诊断和数据删除。

## 4. 首次开通 Flow

```text
01 欢迎
→ 02 登录/注册
→ 03 扫描 Teamo 二维码
→ 04 设备与账号绑定
→ 05 4G 实名/激活（本地演示不等待）
→ 06 Camera、麦克风和数据边界
→ 07 创建最小儿童档案
→ 08 选择表达模式
→ 09 设备摆位/FOV 检测
→ 10 儿童端三次试做
→ 11 第一次亲子共同确认
→ 12 完成
```

规则：

- 不要求先配 Wi‑Fi；4G 是开箱默认，Wi‑Fi 是大更新/可选通道；
- 屏幕与本地运动引擎先启动，蜂窝驻网和云鉴权后台并行；
- 家长端不显示 Camera 实时画面；硬件端负责实时站位反馈；
- 首测必须证明全身入镜、计数反馈和物理隐私，而不只是“绑定成功”。

## 5. 四种日常入口

### F01 儿童自主运动——默认长期入口

```text
唤醒 → 快速选择 → 目标 → Session
```

### F02 家长邀请

```text
今天 → 邀请运动 → 目标 → 设备 ACK
→ 儿童开始/稍后/跳过 → Session
```

### F03 计划提醒

```text
允许时段到达 → 一次轻提醒
→ 开始/稍后/跳过 → Session
```

### F04 设备建议

```text
本地规则满足 → 克制邀请
→ 开始/稍后/不用了 → Session
```

设备建议 MVP 使用透明规则，不依赖不可解释的云模型决定何时催促。

## 6. 统一运动 Session

```text
SELECTING
→ SAFETY_CHECK
→ CAMERA_CONFIRM
→ FRAMING
→ DEMO / TRY
→ READY
→ COUNTDOWN
→ ACTIVE
→ PAUSED / RECOVERING / HELP
→ SAVING_LOCAL
→ COMPLETED 或 ENDED
→ LOCAL_ONLY / QUEUED / SYNCING / SYNCED
→ CHILD_REFLECTION
→ FAMILY_REVIEW
```

### 核心规则

- 最后一个有效动作后先本地落盘，再显示完成；
- 离画、暂停、重启和断网不清零已确认次数；
- 提前结束是真实结果，不标为失败；
- 求助不自动开启远程 Camera；
- 运动中不等待云模型；
- 云语言晚到不能打断当前动作；
- 家长 App 不显示秒级实时次数。

## 7. 儿童硬件三种 UI 模式

### Face Mode

待机、关系表达、简短问候、完成庆祝和隐私状态。

### Sport Mode

超大数字、目标、暂停/完成和一个方向性提示。运动中优先级：

```text
语音/短音 > 超大数字 > 大图形 > 极短文字
```

### Near Interaction Mode

儿童靠近设备后使用；一次只出现 2–3 个选择。运动中不要求远距离触控。

## 8. 本地、4G 与云模型状态

不能只有“在线/离线”两个状态。

| 状态 | 基础运动 | 云陪伴 | UI |
|---|---:|---:|---|
| LOCAL_BOOTING | 未就绪 | 不可用 | 立即灯光/声音响应 |
| LOCAL_READY | 可用 | 不可用 | 可直接开始运动 |
| CELLULAR_REGISTERING | 可用 | 不可用 | 非阻塞连接提示 |
| CLOUD_CONNECTING | 可用 | 准备中 | 使用本地固定表达 |
| ONLINE | 可用 | 可用 | 不持续强调网络 |
| WEAK_NETWORK | 可用 | 可能降级 | 可取消、无无限 Loading |
| OFFLINE | 可用 | 本地替代 | 结果排队同步 |
| SIM_ACTION_REQUIRED | 可用 | 不可用 | 问题只在家长 App 处理 |
| CLOUD_MAINTENANCE | 可用 | 本地替代 | 不影响计数和完成 |

端云分工：

- 本地：人体、关键点、动作阶段、计数、入镜、暂停、保存、安全提示；
- 云端：自然语言、内容编排、高质量语音、结构化结果总结；
- 默认禁止：上传持续视频、环境音和供家长回放的身体轨迹。

## 9. 亲子互动主线

首版验证三条：

### 一起选择

家长提供范围，孩子选择当次动作和目标。

### 一起运动

3/5/10 分钟协作活动，输出家庭共同完成，不输出亲子比分。

### 共同回顾

儿童先选择“轻松/刚好/有点难”；家长看到事实、证据边界和一个支持建议。孩子可以不共享私密感受。

家长发送鼓励只在开始前或完成后出现，不在动作中打断。

## 10. 成长型宠物最小闭环

复杂养成后置，但 MVP 必须验证：

- 真实运动触发表情和行为；
- 记住一次个人最好或暂停后恢复；
- 儿童感受影响下次表达；
- 关系从“初识”进入“熟悉”；
- 久未使用不生病、不退化、不清零；
- 偏好和记忆可查看、修改和删除。

长期成长维度：开始能力、完成与恢复、动作熟悉、活动多样性、伙伴关系。不同维度不合并成儿童总等级。

---

## 11. 排行榜与挑战护栏

MVP 不默认上线排行榜，但提前固定未来规则：

1. 默认与自己过去比较；
2. 优先家庭共同目标，不做亲子输赢；
3. 同伴挑战只允许匿名、小范围、同水平、短周期和无损退出；
4. 不做公开个人总榜、公开倒数、连续签到惩罚和付费倍率；
5. 识别可信度不足的记录不进入比较；
6. 6–9 岁默认只开放个人与家庭层；
7. 不做陌生人实时视频 PK 和私信。

## 12. 硬件形态 Gate

当前存在两条互斥路线，不能同时作为“最新结论”：

| 项目 | 掌心小主体 | 落地伙伴基线 |
|---|---:|---:|
| 外廓 | 约 60×90 mm | 约 180×235×150 mm |
| 屏幕 | 约 1.6–1.8 inch | 约 4 inch / 720×720 |
| 远距 UI | 强依赖语音 | 大数字和站位可见 |
| 4G/声学/配重 | 极紧张 | 可合理集成 |
| 产品感知 | 小配件/桌宠 | 运动现场伙伴 |

### 当前推荐

以落地 `180×235×150 mm + 4 inch` 作为 EVT 共同基线，掌心路线作为成本对照。通过以下测试后再冻结：

- 0.5/1.5/3 m 可读性；
- 三年龄/身高组全身 FOV；
- 开合跳、深蹲、跳绳动作余量；
- 4G 峰值功耗、扬声器声压和温升；
- 防倾倒、踢碰、玻璃和电源线风险；
- 可换装饰不遮 Camera/天线/声学。

## 13. 模块化与未来轮式底盘

```text
核心伙伴模块
├─ 固定防滑底座（MVP）
├─ 非电子换装件
└─ 未来轮式底盘
```

MVP 预留：

- 机械定位与防呆锁止；
- 底盘供电与通信候选接口；
- 底盘能力枚举和 Feature Flag；
- Camera 坐标系与底盘朝向；
- 急停、驻车、校准、移动和回充状态。

轮式阶段规则：

- 运动开始前可前往预设运动点、引导站位；
- 运动识别过程中默认机械驻车；
- 不追踪运动中的孩子；
- 不巡房、不远程驾驶 Camera、不追着催运动；
- 移动必须有低速、避障、防跌落、急停和儿童夹手保护。

## 14. 功能真实性准入表

每个 UI 元素必须说明：

| 字段 | 问题 |
|---|---|
| 用户任务 | 帮助谁完成什么？ |
| 数据来源 | 本地传感器、状态机、App、4G 还是云模型？ |
| 触发条件 | 什么真实事件让它出现？ |
| 成功确认 | 怎样证明真的成功？ |
| 等待 | 300 ms / 1 s / 5 s 后如何反馈？ |
| 失败 | 网络、算法、权限和硬件失败分别怎样处理？ |
| 降级 | 无网、云超时、无底盘时还能做什么？ |
| 隐私 | 使用哪些儿童数据，谁能看到？ |
| 跨端 | 家长和儿童分别显示什么？ |

无法填写完整的按钮、卡片、状态或动画，不进入 UI。

## 15. 页面与 Flow 优先级

### P0

1. 本地先启动 + 4G 后台接入；
2. 首次绑定/实名/隐私/摆位/试做；
3. 儿童自主运动；
4. 家长邀请；
5. 入镜、示范、计数；
6. 暂停/离画/恢复；
7. 求助和 Camera 关闭；
8. 本地保存/异步同步；
9. 儿童感受；
10. 家长结果与共同回顾；
11. 一起选择；
12. 成长宠物“初识”最小闭环。

### P1

1. 历史和成长趋势；
2. 计划提醒；
3. 亲子一起运动；
4. 家庭共同目标；
5. 宠物“熟悉”；
6. 多儿童；
7. 换装识别；
8. 底盘接口技术验证；
9. 语言、主题和无障碍完善。

### P2

1. 同水平小组挑战；
2. 轮式底盘受控互动；
3. 更丰富宠物行为；
4. 经专业评审的个性化建议；
5. 内容和装饰扩展。

### 禁止/暂不进入

- 实时 Camera/音频监听；
- 公开儿童个人总榜、陌生人视频 PK；
- 商城、抽卡、付费成长倍率；
- 开放聊天和无限记忆；
- 未验证的身体/能力评分；
- 运动中追踪儿童的轮式移动。

## 16. 推荐 Golden Flow

```text
家长 App：今天 → 一起选择/邀请
→ 设备 ACK
→ 儿童：开始/稍后/跳过
→ Camera 确认
→ 入镜 → 示范 → READY → COUNTDOWN
→ ACTIVE
→ 暂停/离画 → 恢复
→ 达成目标
→ 本地保存
→ 儿童结果与感受
→ 异步同步
→ 家长结果
→ 共同回顾/鼓励
→ 宠物形成一条真实共同记忆
```

UE 必须同时画出：

- 正常完成；
- 4G/云未就绪但本地完成；
- 离画恢复；
- Camera 关闭；
- 儿童拒绝/稍后；
- 提前结束；
- 求助；
- 同步失败后恢复。
