# 竞品分析方法论与竞品池：研究底稿 V1.0

> 日期：2026-09-18  
> 用途：为“儿童 AI 运动陪伴机器人”建立可复用的竞品分析输出范式与首批竞品池。  
> 研究边界：本稿只采用方法拥有者、国际标准组织、监管机构、产品官网/官方应用商店页、上市公司公告等一手或准一手资料。尚未经过实机体验、访谈或采购验证的内容，均不得写成确定事实。

## 1. 先给结论：专业竞品分析不应只是“功能表 + 主观优缺点”

成熟做法是把竞品研究拆成六层，并让每一层回答不同问题：

1. **战略层**：它服务谁、在什么情境下解决什么任务、凭什么被选择、谁付钱。
2. **方案层**：用软件、硬件、内容、真人服务、AI 或组织服务中的哪些组合交付价值。
3. **体验层**：用户从触发需求到完成任务的全流程，哪里顺畅、哪里中断、哪里建立信任。
4. **能力层**：功能、算法、内容、设备、传感器、生态连接、服务网络的真实能力边界。
5. **商业层**：价格只是入口，还需比较总拥有成本、订阅、耗材、配件、内容与服务续费。
6. **证据与决策层**：区分事实、体验、用户声音与推断；最后形成“借鉴/避坑/差异化/待验证”的产品决策，而不是停在描述。

这一结构与 Strategyzer 官方 Value Proposition Canvas 的“客户任务—痛点—收益—价值匹配”一致；与 ISO 9241-210 的人本设计要求一致，即硬件与软件都应在完整生命周期内围绕真实使用情境设计；也符合 Nielsen Norman Group（NN/g）关于旅程图、可用性测试和启发式评估的分工：专家评审可以找显著问题，但不能替代真实用户研究。[Strategyzer 官方 Value Proposition Canvas](https://www.strategyzer.com/library/the-value-proposition-canvas)；[ISO 9241-210:2019](https://www.iso.org/standard/77520.html)；[NN/g 启发式评估方法](https://www.nngroup.com/articles/how-to-conduct-a-heuristic-evaluation/)

## 2. 推荐的单品竞品报告格式

### 2.1 一页结论卡（先给决策者看）

必须包含：

- 官方名称、版本、调研日期、地区、终端与账号状态；
- 竞品关系：直接竞品 / 间接竞品 / 替代方案 / 能力标杆 / 跨界启发；
- 一句话定位：**面向谁（使用者 + 购买者），在什么场景，为完成什么任务，提供何种核心机制，相比替代方案有何不同**；
- 三条最值得借鉴、三条最大风险、一条我方机会；
- 当前证据完整度与最重要的待验证问题。

### 2.2 定位：必须拆开写，不能只写一句宣传语

| 字段 | 强制回答的问题 |
|---|---|
| 使用者 | 谁直接操作？儿童需按年龄、运动基础、认知与自理能力分层 |
| 购买者 | 谁付款、谁决策、谁批准？家长、学校、场馆或企业可能与使用者不同 |
| 影响者 | 体育老师、教练、医生、同伴、平台或渠道是否影响购买与持续使用 |
| 核心 JTBD | 在何种触发情境下，用户想取得什么进展，而不只是“用了什么功能” |
| 痛点 | 功能性、情绪性、社会性、经济性、安全性、时间成本分别是什么 |
| 场景 | 家庭客厅、卧室、户外、学校、场馆；单人/亲子/同伴；高频/低频 |
| 价格定位 | 免费、订阅、硬件一次性、服务按次、B2B 项目制；价格带及对标对象 |
| 替代方案 | 不用产品时用户如何解决：短视频、家长陪练、学校体育、私教、游戏机等 |
| 价值主张 | 产品如何创造收益、缓解痛点；哪些是可验证能力，哪些只是宣传承诺 |

JTBD 在本项目中建议采用“当……时，我想要……，从而……”的情境句式；随后再按 Value Proposition Canvas 拆成 jobs / pains / gains，避免把人口属性误当需求。竞品边界也不应只按产品品类划分，而应追问哪些方案在帮助用户完成同一项“工作”；Strategyn 的原始材料将 JTBD 作为理论，并用 Outcome-Driven Innovation 将任务及期望结果转为可量化创新机会。[Strategyzer 官方模板](https://www.strategyzer.com/library/the-value-proposition-canvas)；[Strategyn《Jobs to be Done Book》](https://strategyn.com/wp-content/uploads/2023/10/Jobs_to_be_Done_Book.pdf)

### 2.3 功能与个人体验：按任务流记录，不按菜单抄录

每个核心任务都应记录：

1. 触发：用户为什么此刻打开产品；
2. 进入：找入口、选账号/儿童、设备唤醒或配网；
3. 设定：目标、计划、课程、难度、设备与空间准备；
4. 执行：动作示范、实时反馈、纠错、鼓励、暂停与意外恢复；
5. 结束：结果、解释、奖励、下一步；
6. 复访：提醒、进度、适配、家长端/老师端闭环。

每一步同时填五栏：**客观行为、用户感受、有效之处、摩擦/风险、证据**。个人体验必须写清设备、网络、空间、光照、年龄角色、操作时长与是否付费，不能将单次体验泛化为全体用户结论。

评价口径采用 ISO 9241-11 的定义：必须在指定用户、目标和使用情境中评估有效性、效率与满意度。任务脚本先拆目标、步骤、子任务、决策和信息需求；不同竞品使用同一脚本，记录完成与否、耗时、错误、阻塞和恢复，才具备基本可比性。[ISO 9241-11:2018](https://www.iso.org/standard/63500.html)；[NN/g Task Analysis](https://www.nngroup.com/articles/task-analysis/)；[GOV.UK Usability Benchmarking](https://www.gov.uk/service-manual/measuring-success/usability-benchmarking-a-website-or-whole-service)

可让体验者用这些提问描述：

- 你原本想完成什么？成功标准是什么？
- 第一次卡住在哪里？当时预期系统怎么反应？
- 哪一刻觉得“它懂我/孩子”，哪一刻觉得机械或冒犯？
- 运动中你看屏幕、听声音、看设备还是看家长？是否分散注意力？
- 反馈是否来得及、是否说清“哪里错、如何改、改后是否正确”？
- 孩子愿不愿意第二天主动回来？家长为什么愿意继续付费？

### 2.4 优点与缺点：统一维度，避免“优点多、缺点只写贵”

至少覆盖以下维度，并要求“现象—影响—适用边界—证据”：

- 价值与需求匹配；
- 内容/训练专业性；
- AI 个性化、记忆与可解释性；
- 动作识别准确性、反馈实时性与容错；
- 激励、陪伴、游戏化与长期留存；
- 儿童适龄性、亲子关系与家长控制；
- 易用性与无障碍；
- 硬件形态、可靠性、续航、空间与安装；
- 数据、隐私、安全、健康声明；
- 多端协同、第三方设备和生态；
- 商业模式、价格透明度与 TCO；
- 客服、质保、退换、维修与内容持续性。

数字界面可用 NN/g 十项启发式作专家评审：状态可见、贴近现实、用户控制、一致性、错误预防、识别优先于记忆、灵活高效、简洁、错误恢复、帮助文档。报告必须注明：启发式评估是专家判断，不能冒充用户研究；NN/g 建议由 3–5 名评审者独立检查后合并问题。[NN/g 十项启发式](https://www.nngroup.com/articles/ten-usability-heuristics/)；[NN/g 评估理论](https://www.nngroup.com/articles/how-to-conduct-a-heuristic-evaluation/theory-heuristic-evaluations/)

### 2.5 硬件产品：建立“声明参数、实测参数、体验后果”三联表

| 参数组 | 应记录项目 |
|---|---|
| 基础 | 型号、版本、上市/更新日期、尺寸、重量、材质、适龄、颜色 |
| 计算与交互 | 芯片、内存、存储、屏幕/灯效、麦克风、扬声器、按键、触摸、震动 |
| 感知 | 摄像头、视场角、深度/红外、IMU、心率等传感器、骨骼点、识别距离与人数 |
| 连接 | Wi‑Fi 频段、蓝牙、蜂窝网络、配网、离线能力、手机/电视/穿戴兼容性 |
| 电源 | 电池容量、官方续航、实测续航、充电口、功率、充满时间、边充边用 |
| 运动适配 | 支持动作/课程、实时纠错、计数、延迟、空间/光照要求、遮挡与多人表现 |
| 安全与耐用 | 跌落、防水防尘、温升、边角、误吞、认证、儿童锁、隐私遮挡 |
| 服务 | App 依赖、云端依赖、账号数、内容更新、订阅、质保、维修、退换 |

严禁把官网“AI 精准”“专业级”等营销词直接转换成参数结论。每个数值标明：官方声明 / 第三方实验 / 本项目实测 / 未知。硬件与软件应作为一个系统评估，这与 ISO 9241-210 对交互系统硬件、软件整体人本设计的范围一致。[ISO 9241-210:2019](https://www.iso.org/standard/77520.html)

### 2.6 价格与 TCO：统一到可比较周期

除标价外，至少计算 1 年与 3 年总拥有成本：

`TCO = 硬件 + 必需订阅 + 内容/课程 + 配件/支架/显示设备 + 真人服务 + 耗材 + 维修/换新 + 退出成本 - 可验证优惠`

同时记录：家庭可共享人数、免费层限制、试用期、自动续费、退款、二手残值、网络/屏幕等前置资产。B2B 产品另计部署、教师培训、管理后台、场地改造、运维与采购最低量。价格必须注明地区、渠道、日期和税费，不同渠道不得直接混算。

联网硬件还应记录厂商承诺的预期寿命、支持期限、更新机制、漏洞响应、维护、维修、零件和退役；NIST 将安全能力与持续支持放在完整 IoT 生命周期内讨论。防尘防水只记录经过具体标准声明的 IP 等级，不把“生活防水”等营销词换算为等级。[NIST IoT 厂商文档基线](https://pages.nist.gov/IoT-Device-Cybersecurity-Requirement-Catalogs/nontechnical/manufacturer/documentation/)；[NIST IoT 生命周期 FAQ](https://www.nist.gov/itl/applied-cybersecurity/nist-cybersecurity-iot-program/faqs)；[IEC 60529](https://webstore.iec.ch/en/publication/2452)

### 2.7 用户评论研究：不是摘几条好评/差评

建议流程：

1. 明确平台、地区、版本、时间窗与样本量；
2. 分层抽样：星级、近期/历史、已购/未验证、设备型号与用户角色；
3. 去重并标记广告、模板化、利益相关与异常文本；
4. 用统一编码本：任务、触点、问题、严重度、频次、情绪、期望解决方案；
5. 保留反例，报告“出现次数/样本量”，不把评论频次当总体发生率；
6. 用实机、客服记录、版本日志或访谈三角验证高影响主题。

FTC 的消费者评论规则明确禁止购买虚假正/负面评论、未披露利益关系的内部评论、伪装独立的企业控制评论站及压制负评等做法，因此评论来源与激励机制本身就是证据质量的一部分。[FTC Consumer Reviews and Testimonials Final Rule](https://www.ftc.gov/system/files/ftc_gov/pdf/r311003consumerreviewstestimonialsfinalrulefrn.pdf)

评论样本还需公开抓取/筛选方法和局限：平台人群不代表全部用户，某次版本事故或舆情事件会造成时间聚集。研究问题应先于方法，质性探索与量化发生率验证不可混用；GOV.UK 的研究指南建议先把假设改写为研究问题，再选择能产生足够可靠证据的方法。[GOV.UK 用户研究规划](https://www.gov.uk/service-manual/user-research/plan-user-research-for-your-service)；[GOV.UK 从用户需求出发](https://www.gov.uk/service-manual/user-research/start-by-learning-user-needs)

### 2.8 证据等级与措辞规则

建议采用以下内部等级（这是为本项目建立的工作规则，不冒充外部行业标准）：

- **E1 已验证**：本项目可复现实测、正式合同/说明书/监管文件；
- **E2 官方声明**：官网、官方商店页、上市公司公告；可证明“厂商这样声称”，未必证明效果；
- **E3 多源用户证据**：多个独立平台、跨版本出现的一致主题；
- **E4 单源体验**：研究员个人体验或少量用户评论；
- **E5 推断/假设**：基于现象的解释，必须写验证计划。

措辞示例：E2 写“官网宣称支持 34+ 骨骼点”，不能写“识别准确”；E4 写“在本次 iPhone、家庭客厅、30 分钟体验中出现”，不能写“用户普遍会遇到”；E5 前必须加“推测/待验证”。

### 2.9 “如果我做”必须从洞察走到产品决策

每条建议使用同一决策卡：

- 观察：发生了什么；
- 证据与等级：何处看到、可信度多高；
- 洞察：它暴露了哪个未满足任务/设计矛盾；
- 原则：我方坚持什么；
- 方案：具体到角色、场景、任务流和反馈机制；
- 不做什么：边界和取舍；
- 风险：安全、隐私、误识别、商业与儿童影响；
- 验证：最小实验、目标人群、成功/失败指标；
- 决策：借鉴、规避、差异化、延后或否决。

分析时强制保持链条：**原始观察 → 聚类主题 → finding/insight → 用户意义 → 行动**；洞察标题应说明关键事实及其后果，并附截图、引语或数据。不能从一条评论直接跳到功能方案。[GOV.UK 分析研究场次](https://www.gov.uk/service-manual/user-research/analyse-a-research-session)；[GOV.UK 分享研究发现](https://www.gov.uk/service-manual/user-research/sharing-user-research-findings)

引导创始人回答：如果只能解决一个高频问题是什么？使用者和付款者的收益如何同时成立？AI 必须在哪一刻介入才比固定规则更好？离线或识别失败时产品仍能否完成任务？怎样让奖励指向运动能力和自我效能，而不是只追逐时长/付费？哪些健康建议必须转交专业人士？

## 4. 基于底层逻辑扩展的竞品池与筛选法

### 4.1 本项目的待验证底层定义

当前可先用作研究假设，不应当作已验证产品定位：

> 为缺少持续运动动机、专业反馈与稳定陪伴的儿童家庭，在家庭碎片化场景中，通过有形 AI 伙伴 + 动作感知 + 适龄游戏化 + 家长闭环，把“知道该运动”转化为“愿意开始、正确完成、持续回来”，并让家长看见安全、成长和效果。

由此，真正要比较的不是“是否也有课程”，而是五个底层机制：

1. **启动**：怎样降低儿童开始运动的心理和空间门槛；
2. **指导**：怎样感知动作并给出及时、可理解、可执行的反馈；
3. **坚持**：怎样形成关系、习惯和内在动机，而非短期刺激；
4. **共管**：怎样连接儿童、家长、老师/教练，又不让监督破坏自主性；
5. **信任**：怎样证明安全、隐私、适龄、效果与服务持续性。

### 4.2 扩展竞品分层

- **A 直接竞品**：儿童/家庭场景 + 动作识别/体感 + 训练反馈 + 陪伴或游戏化。首批：天天跳绳、BodyPark ATOM；满分运动需按家庭版/校园版边界判断。
- **B 核心能力标杆**：华为运动健康（设备管理、多端/多设备数据）、Keep AI 教练（计划与数据闭环）、betterWE 星球（饮食 AI + 真人服务）、星角萌萌（儿童人格与亲子连接）。
- **C 运动游戏/主机替代**：Nintendo Switch 运动/健身环、Just Dance 等；用于研究家庭共同运动、低学习门槛与游戏反馈，需在下一阶段核验中国区可得性和家长成本。
- **D 儿童 AI 陪伴硬件**：其他有长期记忆、主动互动、家长端的儿童机器人；用于研究关系、内容安全、续航、离线与隐私，不因“AI 陪伴”就视为运动竞品。
- **E 校园智慧体育**：摄像头体测、AI 体育课、智慧操场与作业平台；用于研究老师端、班级管理、体测合规和 B2B 交付。
- **F 人工替代**：家长陪练、体育老师、私教、体能馆、短视频课程；这是价格与效果的真实基准，不能从竞品池删除。

### 4.3 筛选评分（用于决定深度分析对象，不用于宣判产品好坏）

每项 0–5 分，建议权重：目标人群 20%、核心任务 20%、场景 15%、交互/硬件形态 15%、动作反馈能力 15%、陪伴留存机制 10%、商业与渠道 5%。总分 ≥70 进入深度拆解，50–69 进入专项借鉴，<50 只保留为替代方案。另设“一票进入”：某单项能力是我方关键未知且行业领先，即使总体相似度低也可做能力标杆。

## 5. 推荐交付物组合

每个竞品不宜只交一份长报告，建议形成：

1. 单品事实卡（定位、能力、价格、硬件、证据）；
2. 核心任务流 teardown（带截图编号和时间戳）；
3. 个人体验日志（条件明确）；
4. 用户评论主题表（样本与编码透明）；
5. 优缺点矩阵（统一维度）；
6. “如果我做”决策卡；
7. 跨竞品对比矩阵与机会地图；
8. 待验证清单与下一轮访谈/实测计划。

## 6. 当前必须向用户确认的问题

1. “健萌的 backway”是否确指 **betterWE 星球**？若不是，请提供截图、链接或正确拼写。
2. BodyPark 要研究的是中国官网的在线真人私教服务、ATOM 硬件，还是两者都研究？本稿建议拆开。
3. “满分运动”重点是学校采购/课堂方案，还是家庭端产品？两者的购买者、场景、价格和任务流完全不同。
4. 本项目目标年龄段尚需锁定；3–6、7–9、10–12 岁的交互、运动处方、家长控制与硬件安全标准不能混为一组。
5. 计划硬件是否自带屏幕/摄像头，还是依赖手机、平板或电视？这会决定直接竞品池、硬件参数表和 TCO 算法。

## 7. 研究纪律

- 页面宣传只证明“厂商声称”，不证明效果；
- App Store 当前价格会变化，引用时必须带日期、地区和渠道；
- 不同版本、地区、系统、付费层不合并；
- 同名产品先核开发者；
- 未实际体验不得写“操作流畅/识别准确”；
- 儿童、健康、运动建议必须单列安全、隐私与专业边界；
- 所有结论都要能回到截图、页面、实测记录、访谈逐字稿或样本编码表。
