# AI运动伙伴 · 竞品分析输出规范 V3.0（决策版）

> 日期：2026-09-18  
> 适用项目：6–15 岁儿童 AI 运动陪伴机器人  
> 文档状态：可作为后续单品调研与横向总结的统一模板；项目定位、价格、硬件方案仍按“假设”管理  
> 核心目的：用可复核证据回答产品定位、MVP、硬件、体验、商业模式应该如何取舍，而不是制作功能百科。

---

## 1. 为什么采用这套格式

用户提出的五段式结构——定位、功能与体验、优点、缺点、如果我做——方向正确，但需要增加“研究问题、证据、同场景任务流、硬件实测、从洞察到决策”五个约束，才能成为专业、可复用的竞品研究。

### 1.1 方法论依据

1. **定位不能只抄官网文案。** Strategyzer 的 Value Proposition Canvas 要求围绕一个具体用户群，区分其 jobs、pains、gains，并强调所谓匹配在用户证据验证前只是假设。因此，人群、痛点、价格、场景必须分别写“官方目标”“实际使用信号”“研究者判断”。  
   依据：[Strategyzer — Value Proposition Canvas](https://www.strategyzer.com/library/the-value-proposition-canvas)
2. **体验必须绑定具体用户、目标和使用环境。** ISO 9241-11 将可用性放在“特定用户、特定目标、特定使用情境”中，并以有效性、效率、满意度理解结果。因此，不比较脱离场景的“好不好用”，而比较完成同一任务时是否成功、付出多少和感受如何。  
   依据：[ISO 9241-11:2018](https://www.iso.org/standard/63500.html)
3. **功能要按任务流分析。** 单纯列功能无法说明用户是否能完成任务。本项目统一沿“触发—准备—开始—识别—反馈—恢复—完成—理解结果—再次使用”分析。
4. **可用性问题使用统一检查尺。** 采用 Nielsen Norman Group 的状态可见、贴近现实、用户控制、一致性、防错、识别优于回忆、效率、简洁、错误恢复、帮助等启发式原则，减少“我觉得”的任意性。  
   依据：[NN/g — Ten Usability Heuristics](https://media.nngroup.com/media/articles/attachments/NNg_Jakob%27s_Usability_Heuristic_Summary.pdf)
5. **儿童联网硬件必须把隐私当作产品维度。** 摄像头、语音、联网玩具和儿童账户不是普通功能项；分析应记录采集、处理、保存、共享、家长授权、撤回和删除。FTC 的 COPPA 指南明确将联网玩具、智能音箱、语音助手等纳入儿童在线服务讨论，并将儿童图像、视频和声音视为敏感信息。中国项目最终以适用的中国法律及法务意见为准，本条仅用于说明为什么竞品报告不能遗漏儿童数据链路。  
   依据：[FTC — COPPA FAQ](https://www.ftc.gov/business-guidance/resources/complying-coppa-frequently-asked-questions)

### 1.2 六条强制原则

1. **先问决策题，再收资料。** 每份报告最多回答 1–3 个决策问题。
2. **事实、体验、用户信号和判断分开。** 统一使用 `[事实]`、`[实测]`、`[用户信号]`、`[推断]`、`[待确认]`。
3. **同类才评分，同任务才横比。** 成人健身 App、儿童陪伴玩具、学校方案和专用硬件不能用一个总分强行排名。
4. **未知不等于没有。** 写“官方未公开/本轮未核实”，不能写成产品“不具备”。
5. **参数有三种口径。** `官方标称`、`第三方测量`、`本轮实测`不得混写；识别准确率、续航、销量、留存和用户规模尤其如此。
6. **结论必须改变一个决策。** 每条洞察最终进入“采纳、差异化、避开、试验、暂不行动”之一，否则不进入执行摘要。

## 2. 本项目底层逻辑：当前基准，不当作既定真理

竞品研究不是为了证明当前方案正确，而是用来挑战下列假设。

| 底层问题 | 当前工作假设 | 需要竞品回答什么 | 状态 |
|---|---|---|---|
| 服务谁 | 使用者为 6–15 岁儿童；付费/管理者为家长；体育老师和学校可能影响使用 | 不同年龄是否应拆成不同产品体验？家长和学校谁是更强触发者？ | 待分龄、付费与学校访谈验证 |
| 解决什么问题 | 孩子难开始、运动中易中断；家长反复催促且不易确认真实完成；家庭体育任务难执行和回传 | 用户真正愿意付费的是“开始”“坚持”“专业纠错”“可信完成”还是“陪伴”？ | 核心价值假设 |
| 用什么方式 | 家庭常驻专用硬件，结合视觉识别、自动计数、低频陪伴激励、家长任务和结果回看 | 专用硬件相对手机、电视、穿戴和智能配件是否显著降低摩擦或提高可信度？ | 最关键商业假设 |
| 在什么场景 | 家庭固定运动空间，短时、重复、高频；由任务提醒或孩子自主发起 | 家庭空间、机位、光照、噪声和家长介入会不会破坏“常驻即用”？ | 待家庭实测 |
| 为什么愿意付费 | 少摆放、少切换、少娱乐干扰，可主动邀请，运动状态专用，结果更稳定可信 | 这些差异是否被家长感知，且足以覆盖硬件购置和可能的订阅成本？ | 待价格测试 |
| 如何衡量成功 | 提高提醒到开始、开始到完成、7/30 日再次运动；降低家长催促；提升结果理解与信任 | 竞品在哪个环节真正改变行为，而非只增加内容或功能？ | 指标定义已形成，阈值待测 |

一句话版本暂定为：

> 为希望孩子在家真正开始、完成并坚持运动的家庭，提供一台常驻的儿童运动设备，通过可见的任务、视觉识别和适度陪伴，把家长反复催促与人工监督转化为孩子可独立完成、家长可理解和信任的运动记录。

这句话是研究锚点，不是最终宣传语。若证据不支持“常驻硬件”“儿童独立完成”或“家校”，必须允许修改方向。

## 3. 竞品分类：比较关系，而不是把所有产品排成一列

| 类型 | 定义 | 研究目的 | 是否进入统一总分 |
|---|---|---|---|
| 直接竞品 | 人群、任务、场景、方案形态中至少三项高度重叠 | 判断正面竞争与差异化空间 | 仅同类型、同任务时可评分 |
| 近邻竞品 | 解决同一任务，但人群或形态不同 | 判断方案迁移和潜在跨界威胁 | 不与直接竞品算综合排名 |
| 模块标杆 | 整体不竞争，但某一模块成熟 | 学设备管理、AI 计划、陪伴、家长端等 | 只评指定模块 |
| 替代方案 | 用户不购买本产品时实际采用的做法 | 识别真正的“现状竞争者” | 用成本、效果、摩擦比较，不套功能分 |
| 生态/渠道参照 | 学校、课程、教练或设备生态 | 判断进入路径、数据和交付成本 | 独立评估商业与组织能力 |

## 4. 每份竞品报告的标准结构

### 0）研究任务卡

| 字段 | 填写要求 |
|---|---|
| 本轮决策题 | 最多 3 个，必须能影响定位、MVP、硬件、商业模式或验证计划 |
| 竞品关系 | 直接 / 近邻 / 模块标杆 / 替代 / 生态参照 |
| 研究对象 | 准确产品名、型号、版本、系统、地区、体验日期 |
| 研究场景 | 具体角色、地点、任务、设备与空间条件 |
| 证据范围 | 官方资料、说明书、实测、评论样本、客服/门店、媒体或监管资料 |
| 研究限制 | 未购买、未登录、地区限制、样本少、旧版本、无法实测等 |

### 1）一页执行摘要

- 一句话定位：为谁，在什么场景，用什么方式，解决什么问题。
- 它与本项目是什么关系，威胁/借鉴价值为何。
- 三条结论：最值得学、最不该学、最需要验证。
- 是否增强或削弱“独立硬件付费理由”，证据是什么。
- 本报告置信度：高 / 中 / 低，以及最大证据缺口。

### 2）定位四件套

#### 2.1 人群定位

必须拆开：

- 使用者：年龄、能力、动机、运动基础、数字素养。
- 购买者：谁付款，使用什么心理账户。
- 决策者：谁决定买/用/续费/停止。
- 影响者：家长、老师、同伴、教练、医生、平台或渠道。
- 宣传人群与实际使用人群是否一致。
- 明确“不服务谁”以及为什么。

#### 2.2 痛点定位

按 `触发情境 → 想取得的进展 → 现有替代 → 阻碍 → 成功标准` 填写，并区分：

- 官方声称解决的问题。
- 用户反复表达的问题。
- 产品实际最擅长解决的问题。
- 用户愿意付费的问题。
- 产品制造的新成本或新风险。

#### 2.3 价格定位

必须记录：

- 硬件官方价、常见成交价、促销条件、渠道与日期。
- 免费层、试用期、会员、课程、内容包、按次、耗材、配件、维修和延保。
- 付费墙出现在哪个任务节点。
- 首年与三年完整拥有成本 `TCO`；不能只比较裸机价格。
- 退款、自动续费、家庭成员共享、设备更换后的权益迁移。
- 若价格未核实，写“待核实”，不得引用搜索摘要作为最终价格。

#### 2.4 场景定位

至少写清：

- 时间、地点、触发者、频次、单次时长。
- 前置条件：空间、距离、机位、穿戴、联网、光照、噪声、电视/手机/配件。
- 是否需要成人协助；首次使用和日常使用分别需要多少协助。
- 主要场景、边缘场景、失败场景。
- 使用前、使用中、使用后的设备和数据流转。

### 3）核心任务流与功能描述

统一基准任务流：

`产生动机/收到任务 → 找到入口 → 选择或理解目标 → 设备准备/入镜 → 准备就绪 → 开始 → 识别与反馈 → 暂停/错误恢复 → 完成 → 理解结果 → 奖励/复盘 → 再次回来`

每个节点记录：

| 节点 | 用户目标 | 产品输入/输出 | 用户操作 | 系统反馈 | 摩擦/失败 | 恢复方式 | 可观察指标 | 证据 |
|---|---|---|---|---|---|---|---|---|

任务流之后再附功能地图，按以下模块分组：获客、首次价值、训练核心、计划、陪伴激励、家长管理、设备管理、家校、社交、商业化、隐私安全、售后。状态只写：`有 / 部分 / 有条件 / 无 / 未核实 / 不适用`。

### 4）个人体验：由用户口述，我负责追问和结构化

个人体验是 `n=1` 证据，不代表普遍用户。每次口述固定记录：

1. **情境**：谁、什么时候、为什么用，空间和设备条件。
2. **目标**：当时想完成什么，而不是打开了哪个页面。
3. **行为**：实际步骤、耗时、犹豫、退出、求助与绕路。
4. **系统表现**：识别、反馈、延迟、错误和恢复。
5. **感受**：惊喜、困惑、压力、羞耻、不信任、成就感发生在哪一刻。
6. **结果**：是否完成、是否相信结果、是否愿意再次用或付费。
7. **证据**：截图、录屏、订单、参数页、计时、计数对照。

统一追问十题：

1. 你为什么在那一刻使用它？
2. 从产生意图到真正开始运动用了多久？
3. 哪一步需要别人帮助或让你想放弃？
4. 它是否准确知道“人已在、准备好、正在做、做得对”？
5. 漏计、误计、延迟或错误建议发生时怎样恢复？
6. 哪种反馈让你继续，哪种反馈让你烦或有压力？
7. 完成后，你看懂并相信结果吗？
8. 第二天再来的理由是什么？吃灰的理由是什么？
9. 你愿意为什么价值付费，绝不愿为什么付费？
10. 如果只允许改一处，你会改哪里，为什么？

### 5）软件/服务专项评估维度

每一维同时写收益与代价；没有证据不打分。

| 维度 | 核心问题 |
|---|---|
| 开始阻力 | 从提醒/意图到真正运动的时间、步骤、摆放、登录、校准和成人介入 |
| 识别与结果可信 | 人体检测、动作判断、计数、延迟、误漏识别、结果保存和解释 |
| 专业与个性化 | 内容依据、动作安全、计划如何产生、建议是否可解释和可调整 |
| 儿童适配 | 分龄理解、独立操作、反馈语气、自尊保护、消费和社交保护 |
| 陪伴与持续激励 | 是否推动运动本身，是否形成健康复用，而非抢占注意力 |
| 家长价值 | 是否减少催促，结果是否一眼看懂，权限和异常是否可控 |
| 家校/教练闭环 | 任务、执行、记录、反馈和角色权限是否连贯 |
| 商业与完整成本 | 价值与价格是否匹配，收费是否伤害核心体验，交付能否规模化 |
| 隐私与信任 | 摄像头/麦克风可见性，数据采集、端云处理、保存、分享、删除和授权 |
| 服务与恢复 | 网络、账号、同步、售后、退款、设备更换和内容停止后的可用性 |

### 6）硬件专项参数表

所有包含硬件的产品必须附此表。参数表不是“规格越高越好”，每项都要解释对任务的意义。

| 类别 | 必查字段 | 体验/决策意义 |
|---|---|---|
| 型号与生命周期 | 型号、版本、上市日期、在售状态、地区、固件/系统更新 | 防止混用代际参数，判断售后和内容寿命 |
| 整机 | 尺寸、重量、材质、底座、防滑、移动/固定方式、建议安装高度 | 是否适合家庭常驻，儿童能否碰倒或误操作 |
| 显示 | 尺寸、分辨率、亮度、可视角、触控、运动距离可读性 | 运动中是否看得清核心反馈 |
| 摄像头/传感器 | 数量、分辨率、帧率、FOV、安装角度、遮挡状态、深度/红外/ToF（若有） | 入镜距离、多人/遮挡、低光和识别边界 |
| 麦克风/扬声器 | 麦克风数量、拾音距离、降噪、扬声器、音量控制、静音与物理指示 | 嘈杂家庭中的指令成功率和隐私可见性 |
| 运算与存储 | 芯片、内存、存储、端侧/云侧任务、启动时间、响应延迟 | 能否离线、隐私、发热、成本和可升级性 |
| 网络与配对 | Wi-Fi/蓝牙/蜂窝、频段、首次配网、断线恢复、手机/电视依赖 | 首次使用与日常稳定性 |
| 供电 | 适配器、线长、电池、标称/实测续航、充电时间、待机功耗、断电行为 | 常驻性、安全、移动能力和长期电费 |
| 机械能力 | 固定/云台、角度范围、噪声、速度、防夹、儿童触碰时表现 | 是否真的降低机位成本，是否引入安全风险 |
| 使用边界 | 建议距离、所需空间、光照、地面、人数、身高/年龄、服装限制 | 官网演示能否在真实家庭复现 |
| 耐用与安全 | 跌落/倾倒、圆角、温升、防水防尘、线缆、适配器、认证信息 | 儿童家庭长期使用风险；只记录已核实认证 |
| 隐私 | Camera/Mic物理开关或指示、端侧处理、原始媒体保存、账户权限、删除/解绑 | 家长信任与合规底座 |
| 联网生命周期 | 厂商承诺支持期限、OTA策略、漏洞响应、版本记录、停服/退役与数据迁移 | 避免设备寿命被云服务、账户或停止更新提前终结 |
| 包装与配件 | 标配、选配、耗材、替换成本、安装工具、运输与退换要求 | 真正到手成本和部署难度 |
| 售后 | 保修、维修、换新、客服、停服后的离线能力、内容所有权 | 硬件寿命是否被云服务绑定 |
| 价格与 TCO | 裸机、订阅、内容、配件、维修、退出成本、1年/3年总成本、二手残值 | 与手机 App、电视和线下课公平比较 |

防水、防尘、跌落、认证和安全等级只按产品明确声明的具体标准与范围记录；“生活防水”“儿童安全材质”等营销词不能自行换算成 IP 等级或认证结论。联网生命周期的记录参考 [NIST IoT 厂商文档基线](https://pages.nist.gov/IoT-Device-Cybersecurity-Requirement-Catalogs/nontechnical/manufacturer/documentation/)，IP 等级定义以 [IEC 60529](https://webstore.iec.ch/en/publication/2452) 为准。

硬件实测至少包含：

- 开箱到首次有效运动的总时长。
- 典型家庭空间中的最小/舒适入镜距离和覆盖宽度。
- 成人与儿童、不同身高、光照、衣着和部分遮挡下的识别表现。
- 20 次标准动作与 20 次非标准动作的计数/纠错对照；样本不足时只报告观察，不报“准确率”。
- 断网、遮挡、离画、暂停、重启、账户解绑后的恢复。
- 从运动位置看屏幕、听提示和发语音指令的可达性。
- 连续使用后的温升、噪声、稳定性与电量变化（具备测量条件时）。

### 7）结构性优点与缺点

优点和缺点不分成互不相干的赞美/吐槽清单，而按同一维度成对记录：

| 维度 | 做得好的现象 | 带来的价值 | 对应代价/短板 | 形成机制 | 影响角色/指标 | 证据与置信度 |
|---|---|---|---|---|---|---|

每一项必须回答：

1. **现象**：具体发生了什么。
2. **机制**：由产品选择、硬件结构、商业模式、组织能力还是临时 bug 导致。
3. **影响**：影响哪个角色、哪个任务节点和哪个指标。
4. **持续性**：是结构性、阶段性、执行问题还是证据不足。
5. **可迁移性**：我们会不会遇到；复制需要付出什么代价。

评分只用于同类导航：`1 核心任务失败/有明显风险；2 高摩擦；3 稳定满足基础预期；4 形成明显价值；5 多源验证且难低成本复制；N/A 不适用`。每个分数都必须附证据。

### 8）“如果我做”设计工作坊

这一节先由用户表达判断，我负责追问、挑战和落成决策，不替用户虚构偏好。

#### 8.1 引导问题

- 如果只改一处来提高“提醒 → 开始”，改什么？
- 如果只保留一个付费理由，保留什么？
- 对方最强能力背后付出了什么成本，我们愿意承担吗？
- 哪个功能看起来高级，但不会改变购买、完成或复用？
- 哪个风险一旦发生会直接失去家长或孩子的信任？
- 如果不能使用手机/摄像头/订阅/真人服务中的某一项，方案怎样重构？
- 哪一能力应成为硬件基础能力，哪一能力只应留在家长 App？
- 这项设计对 6–9、10–12、13–15 岁是否应不同？

#### 8.2 决策五桶

| 决策 | 含义 | 必填内容 |
|---|---|---|
| 采纳 Adopt | 用户已将其视为基础预期 | 进入版本、最低实现标准、依赖 |
| 差异化 Differentiate | 对手结构性弱，而本项目有条件更好 | 目标人群、价值指标、难复制原因 |
| 避开 Avoid | 会伤害运动主线、儿童安全、信任或商业结构 | 明确禁止规则和替代方案 |
| 试验 Test | 有潜力但证据不足 | 最小实验、样本、成功阈值、停止条件 |
| 暂不行动 Hold | 有价值但非当前关键路径 | 重新评估的触发条件 |

### 9）对本项目的可执行结论

行动前强制保留推导链：

`原始观察 → 相似观察聚类 → finding/insight → 对用户与本项目的意义 → 行动/实验`

一条评论、一次识别失败或一个竞品功能不能直接跳成产品方案。每份报告最多输出 5 条行动：

| 证据 | 洞察 | 影响的假设 | 决策 | 进入版本 | 验证方法/指标 | 负责人/时间 |
|---|---|---|---|---|---|---|

决策对象限定为：定位、人群分层、MVP、设备端交互、硬件规格、家长 App、算法/数据、内容/计划、家校、定价、隐私安全、研究计划。

## 5. 证据与不确定性规范

### 5.1 证据等级

| 等级 | 证据 | 可支持的结论 |
|---|---|---|
| E1 | 当前版本、统一条件下的可复核实测或测量 | 可支持该条件下的产品表现；不能无边界外推 |
| E2 | 官方说明书、价格页、产品/应用页面、认证或监管披露 | 可证明官方规格、功能、价格或披露事实；不能单独证明效果 |
| E3 | 多平台、跨版本反复出现的一致用户主题；可核实客户案例 | 可支持趋势信号，必须注明样本与偏差 |
| E4 | 单次个人体验、少量评论、单一采访或渠道商页 | 只作线索，不单独下强结论 |
| E5 | 搜索摘要、转述、推测、无法核实的经营数字或营销效果声称 | 只能形成待验证假设 |

### 5.2 引用规则

- 每个价格、参数、用户规模、销量、准确率、留存率和认证信息必须紧邻来源。
- 来源必须注明标题、主体、日期、链接/截图编号、访问日期。
- 官方产品页和说明书可以证明“官方列出了什么功能/规格”，营销效果材料只能证明“它声称什么”；两者都不能单独证明实际效果。
- 评论研究记录平台、采样时间窗、产品版本、样本量、去重规则、筛选方式、激励/刷评风险、重大版本或舆情事件和主题编码；不只挑极端评论。
- 评论只报告“该主题在样本中出现多少次”，不把评论频次外推成全体用户的真实发生率。
- 不复制无法确认来源的旧报告数字。旧稿中的数字重新进入新版前必须复核。

### 5.3 置信度

- **高**：至少两类独立证据相互印证，且含 E1 或可直接证明该事实的 E2。
- **中**：一个 E1/E2，或多条一致的 E3 信号。
- **低**：只有 E4/E5、旧版本或关键环节无法实测。

### 5.4 遇到不确定时的处理顺序

1. 查官方页面、说明书、应用内页面或实物铭牌。
2. 用第二类独立来源交叉核验。
3. 能实测则按统一任务流实测。
4. 仍不确定，明确写 `[待确认]`，列出缺失证据。
5. 若不确定项会改变竞品归类、结论或本项目方案，立即向用户提问；不影响主结论的，先进入问题清单，不中断整份研究。

## 6. 竞品池：扩展、筛选与首轮优先级

### 6.1 用户已指定的核心对象

| 对象 | 建议类型 | 重点回答的问题 | 输出深度 |
|---|---|---|---|

> 名称已由用户确认：健萌产品正式按 `betterWE 星球` 研究。BodyPark 在线真人私教服务与 ATOM 硬件必须拆成两份报告，避免将服务能力、硬件参数和商业模式混为一谈。

### 6.2 从底层逻辑推导的扩展方向

首轮不是越多越好，而是保证每一种真实替代路径都有代表样本。

| 扩展方向 | 候选代表（最终以在售与可核实为准） | 研究价值 |
|---|---|---|
| 儿童家庭视觉运动硬件 | 运动宇宙/悟空运动宇宙、咚咚星等 | 最接近“儿童+家庭+专用硬件+体感运动”，验证正面付费理由 |
| 儿童视觉运动 App | 百分运动等 | 检验低成本 App 在动作识别、体测和游戏化上的替代强度 |
| 电视/主机体感运动 | Nintendo Ring Fit / Switch Sports、电视体感方案 | 比较大屏、娱乐动机、空间占用、配件和家庭共玩 |
| 成人家庭运动硬件 | FITURE、Keep 体感/硬件代表 | 研究专用大屏、课程订阅、硬件吃灰和停服风险，不与儿童产品同分 |
| 智能运动配件 | 智能跳绳、跳绳垫、运动手表儿童模式 | 比较更低价格下的计数可信、穿戴摩擦和动作覆盖 |
| 儿童 AI 陪伴硬件 | BubblePal、阿尔法蛋等选 1–2 个 | 比较陪伴人格、家长端、记忆、内容与儿童数据，不扩大成泛玩具研究 |
| 校园智慧体育 | 选择 1 家具有公开方案、客户案例和数据流程的厂商 | 研究学校采购、任务、体测、回传、权限和重交付成本 |
| 人工服务 | 线下儿童体适能课、线上真人教练 | 判断“有人盯、有人纠”的付费上限和服务成本 |
| 零产品替代 | 家长口头催促、纸质打卡、微信群交作业、不做 | 这是最大的现状竞争，必须通过访谈进入总报告 |

### 6.3 初筛评分：只用于分配研究资源

每项 0–3 分，总分 21 分：

| 标准 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| 人群重叠 | 无 | 家庭/成人 | 儿童但年龄偏移 | 6–15 岁高度重叠 |
| 任务重叠 | 无 | 泛健康/陪伴 | 运动相关 | 让儿童在家开始并完成运动 |
| 场景重叠 | 无 | 非家庭 | 家庭偶发 | 家庭高频常驻 |
| 形态重叠 | 无 | 线下服务 | App/配件/电视 | 专用视觉硬件 |
| 决策价值 | 低 | 单点参考 | 影响一个模块 | 影响定位/MVP/定价 |
| 威胁可能 | 极低 | 间接 | 可跨界 | 已正面竞争 |
| 证据可得 | 几乎无 | 仅宣传 | 有说明/评论 | 可实测且多源 |

- `16–21`：完整深度报告。
- `11–15`：专项报告。
- `0–10`：快速扫描或并入类别研究。
- 任一安全/隐私重大信号可越级进入专项，不受总分限制。

### 6.4 建议研究顺序

1. **直接替代**：天天跳绳、满分运动。
2. **专用硬件核心**：BodyPark ATOM、儿童家庭视觉运动硬件代表 1 家。
3. **儿童陪伴**：星角萌萌。
4. **模块标杆**：华为运动健康、Keep AI 教练、确认后的健萌产品。
5. **价格与替代组**：智能跳绳/电视体感/线下体适能/家长人工监督。
6. 最后再决定是否追加百分运动、咚咚星、FITURE 或校园智慧体育代表，避免一开始铺得过宽。

## 7. 横向总报告的标准结构

1. 一页执行摘要：最大用户问题、最强替代、最大机会、最大风险、最需验证的假设。
2. 竞争关系地图：直接、近邻、模块标杆、替代和生态参照。
3. 用户与购买者地图：孩子、家长、老师、教练各自的任务、痛点、收益与付费/影响权。
4. 同任务流矩阵：逐节点比较开始、识别、反馈、错误恢复、完成、结果和复用。
5. 软件模块矩阵：只记录存在状态和证据，不统计“功能数量冠军”。
6. 硬件参数与实测矩阵：官方参数、实测表现、对任务意义三列分开。
7. 价格与完整拥有成本阶梯：免费 App、配件、电视/主机、专用硬件、硬件+订阅、真人/线下服务。
8. 定位图：坐标轴必须来自家长/儿童验证的购买标准，不能预设本项目应位于某个“空白右上角”。
9. 机会地图：基础门槛、可差异化、高风险勿做、证据不足。
10. 底层逻辑修订：明确哪些项目假设被支持、被否定或仍未知。
11. 路线图影响：只放被证据改变的需求、优先级和实验。

## 8. 交付规格与工作方式

### 8.1 单品交付

- 核心报告：约 2000–3500 字，先结论后证据。
- 证据附录：不限制长度，含来源表、截图、参数、评论编码和实测记录。
- 含硬件时必须提交硬件参数表和实测条件。
- 文件名：`竞品XX_产品名_分析报告_Vx.y_YYYYMMDD.md`。
- 截图名：`产品-平台或型号-任务节点-序号-日期`。

### 8.2 用户参与方式

每次只讨论 1 家产品。我先完成官方事实、公开证据和待确认项，再用第 4 节十个问题引导用户口述个人体验；随后用第 8 节问题完成“如果我做”，最后共同确认采纳/差异化/避开/试验/暂不行动。

### 8.3 复核机制

- 重点竞品每季度快速复核；新硬件、改价、停服、融资、重大投诉或法规变化时立即更新。
- 事实更新为小版本；分类、评分维度、研究问题或核心结论改变为大版本。
- 旧报告升级时保留“原结论—新证据—结论变化”的变更记录。
